# 見せ方の標準化

## 目的

- **誰のために**: CFO、経営会議メンバー、事業部門長、レポート作成者
- **何を解決するか**: レポートごとにチャートの種類が異なる、配色に一貫性がない、レイアウトがバラバラ――これらが放置されると、読み手はレポートのたびに「どこに何が書いてあるか」を探し、視覚的なノイズの中から情報を読み取る認知負荷を強いられる。作成者ごとの属人的な体裁も、レポート品質のバラつきの原因となる
- **届ける価値**: チャート種類・配色・レイアウトの標準を定め、全レポートに一貫した視覚言語を適用することで、読み手が情報構造を瞬時に把握でき、数字の意味の理解に集中できる状態をつくる

## スコープ

- **対象**: 経営レポート（月次レビュー資料、事業部パフォーマンスパッケージ、取締役会報告等）のビジュアル表現に関する標準の策定と維持
- **前提**: 用語・定義の統一および数値の整合性チェックが済んでおり、レポートに掲載する数値とコンテンツが確定している
- **後続**: 標準化されたレポートがレポートの配信と経営レビュー運営に引き渡される
- **対象部門**: FP&A部門（標準の策定・レポート作成の実行主体）、経営企画部門（全社的な資料体裁との整合確認先）

## 責任者

| 役割 | 担当 |
|------|------|
| ビジュアル標準の策定・テンプレート作成 | FP&Aアナリスト（シニア） |
| 標準の承認・例外判断 | FP&Aマネージャー |
| テンプレートに基づくレポート作成 | FP&Aアナリスト |
| 全社資料体裁との整合確認 | 経営企画部門 |

## 手順

**用語の定義**:
- **ビジュアル標準**: 経営レポートで使用するチャート種類の選択基準、配色パレット、レイアウト構成を定めたルール一式
- **テンプレート**: ビジュアル標準を具体化した、レポート作成の雛形ファイル。作成者はこのテンプレートをベースにレポートを作成する

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 基盤整備 | 1. チャート種類の選択基準の策定 | 初回構築時またはレポート体系の大幅見直し時 |
| 基盤整備 | 2. 配色パレットの策定 | ステップ1と並行して実施 |
| 基盤整備 | 3. レイアウト構成の標準化 | ステップ1-2の完了後 |
| 維持運用 | 4. テンプレートの運用と見直し | 毎月のレポート作成時（運用）、半期ごと（見直し） |

### 1. チャート種類の選択基準の策定

**実行条件**: ビジュアル標準が未整備の場合、またはレポート体系を大幅に見直す場合に実施する。

チャートの選択は「見栄え」ではなく「何を伝えたいか」で決まる。データの性質と伝達目的の組み合わせによって、最適なチャート種類は一意に近い形で絞り込める。

1. **データの性質と伝達目的に基づく選択基準を定める**

   | 伝達目的 | データの性質 | 推奨チャート | 使用場面の例 |
   |---------|------------|------------|------------|
   | 時系列の推移 | 連続的な期間データ | 折れ線グラフ | 売上高の月次推移、KPIのトレンド |
   | 構成比の提示 | カテゴリ別の内訳 | 積み上げ棒グラフ（横棒） | セグメント別売上構成、費用内訳 |
   | 実績と目標の比較 | 予実・前年比 | 棒グラフ（縦棒、予算は薄色・実績は濃色） | 予実比較、前年同期比較 |
   | 差異の要因分解 | ブリッジ構造 | ウォーターフォールチャート | 予算→実績のブリッジ、PVM分解 |
   | 2変数の関係 | 相関・散布 | 散布図 | 売上高と利益率の関係、部門間比較 |
   | 達成状況の一覧 | 多項目の達成率 | 信号灯テーブル（色付きセル） | KPIダッシュボード、部門別達成状況 |

2. **使用を禁止または制限するチャート種類を定める**
   - 円グラフ: 5項目超の場合は使用禁止。構成比の時系列比較には使用不可（積み上げ棒グラフを使用する）
   - 3Dチャート: 全面禁止。視覚的な歪みにより数値の正確な読み取りを妨げる
   - 二重軸チャート: 原則禁止。2つの指標のスケールが異なるため、相関があるように見える錯覚を生む。使用する場合はFP&Aマネージャーの承認を得て、右軸の存在を明示する注記を付ける
   - 面グラフ: 重なりにより下層の値が読み取りにくい。積み上げ面グラフは、構成比の推移を示す場合のみ許容する

3. **チャートの基本構成要素を定める**
   - タイトル: 「何のデータか」ではなく「何を読み取ってほしいか」をタイトルにする（例:「売上高推移」ではなく「売上高は3か月連続で前年超」）
   - 軸ラベル: 単位を必ず記載する。Y軸のゼロ起点を原則とし、例外的にゼロ起点でない場合は軸の切断を明示する
   - 凡例: 5項目以内に収める。それ以上は「その他」に集約するか、直接ラベルを使用する
   - データラベル: 主要な値のみ表示する。全データポイントにラベルを付けるとノイズになる

4. **FP&Aレポートに頻出するチャートの実務的な設計指針**

   FP&Aのレポーティングでは、汎用的なデータ可視化の原則に加え、経営層の読解習慣と整合させるための固有の設計判断が求められる。

   - **ウォーターフォールチャートの色規約**: 有利差異（増収要因・コスト削減要因）は青または緑、不利差異（減収要因・コスト増加要因）は赤で統一する。この色の対応は経営者の直感（青/緑=良い、赤=悪い）と一致させるためのものであり、全レポートで厳格に守る。色の意味が逆転している（赤が有利）レポートが1つでも混在すると、読み手は全てのチャートで色の意味を都度確認するようになり、認知負荷が増大する。開始値と終了値（予算値・実績値）はグレーまたはネイビーとし、差異項目と視覚的に区別する

   - **トレンドラインの移動平均期間の選択**: 折れ線グラフにトレンドラインを付加する場合、移動平均の期間選択は分析の目的に依存する:
     - **3か月移動平均（3MA）**: 直近の変化点を素早く捉えたい場合。四半期内のトレンド変化の検出に有効だが、ノイズに反応しやすい
     - **6か月移動平均（6MA）**: 半期の大きな方向感を見たい場合。季節性が弱い事業に適する
     - **12か月移動平均（12MA）**: 季節性を除去した構造的トレンドの把握に使用。年単位の成長率評価や中期計画のレビューに最適
     - 原則として、月次レポートの業績推移チャートには12MAを標準とし、短期の変化を強調したい場合に3MAを併記する。期間の異なる移動平均を同一チャートに3本以上重ねるのは視認性を損なうため避ける

   - **Y軸のゼロ起点問題**: FP&Aレポートで頻出する利益率・粗利率等のパーセンテージ指標では、ゼロ起点と非ゼロ起点のトレードオフが生じる:
     - **ゼロ起点（0%〜100%）**: データの歪曲がなく、読み手を誤解させない。ただし、利益率が10%〜15%の範囲で推移している場合、チャートの大部分が空白になり、1ポイントの変動（経営的には重要）が視覚的に読み取れない
     - **非ゼロ起点（例: 8%〜18%）**: 変動が拡大表示されるため微細な変化が読み取りやすいが、「大幅に悪化した」という印象を実態以上に与えるリスクがある
     - **推奨ルール**: 利益率・マージン指標は非ゼロ起点を許容するが、軸の切断を波線で明示し、チャート下部に「Y軸は○%起点」と注記する。売上高・コスト等の絶対額のチャートは原則ゼロ起点とする。この使い分けを社内で統一し、読み手が指標の性質によって軸の扱いを予測できるようにする

> **よくある落とし穴**: ウォーターフォールチャートで増減項目が多すぎ、個々の棒が細くなり読み取れないケース。差異項目は7-8項目を上限とし、それ以上は「その他」に集約するか、二段階（大分類→小分類）に分けて複数のチャートで示す。

> **判断の分岐点**: 経営層から「いつもと違うチャートで見せてほしい」と要望があった場合の対応。定例レポートの標準は維持しつつ、要望に応えるチャートをアペンディクスや別資料として追加する。標準を都度変更すると、他の読み手の混乱を招く。

### 2. 配色パレットの策定

**実行条件**: ステップ1と並行して実施する。

色は情報を伝える手段であり、装飾ではない。一貫した配色ルールがなければ、同じ青色がレポートAでは「予算」を、レポートBでは「実績」を指すことになり、読み手は毎回凡例を確認する手間を強いられる。

1. **基本配色ルールを定める**
   - 実績と予算: 実績を濃色、予算を同色の淡色（または破線・パターン）で表現する。全レポートでこの対応を統一する
   - 有利差異と不利差異: 有利差異は青系（または黒）、不利差異は赤系で統一する。緑と赤の組み合わせは色覚多様性への配慮から避ける
   - セグメント: 事業部門・製品ライン等の主要セグメントに固定色を割り当てる。どのレポートでも同じセグメントは同じ色で表現する
   - 時系列: 当期を最も濃い色、前期をやや薄い色、2期前をさらに薄い色とし、時間の遠近を明度で表現する

2. **配色パレットを具体的に定義する**
   - 使用する色を具体的な色コード（例: 色名＋16進コード）で定義する
   - 最大7色以内に収める。人間が一度に識別できる色数には限界がある
   - 会社のコーポレートカラーとの整合を確認する。経営レポートが対外資料（IR等）に転用される可能性がある場合、ブランドガイドラインとの一致が望ましい
   - モノクロ印刷でも区別可能な設計にする（色だけでなく、パターンや明度差で情報を区別する）
   - **IR部門・経営企画部門との調整**: 対外資料のデザインガイドラインが存在する場合、FP&Aの配色パレットとの整合を確認する。社内レポートが外部資料に転用される場合のスムーズな変換を考慮する

3. **色の意味の固定ルールを定める**
   - 「赤＝不利/マイナス」「青＝有利/プラス」を全レポートで固定する。レポートによって赤の意味が変わるのは最も混乱を招く
   - 中立的な情報（参考値、ベンチマーク等）にはグレー系を使用する
   - 強調したい数値は太字・下線で示し、色の追加による強調は避ける（色数の増加はノイズになる）

> **よくある落とし穴**: セグメントが多い企業で、全セグメントに異なる色を割り当てようとして色数が膨張するケース。チャートに表示するセグメントは通常3-5に絞り（上位セグメント＋「その他」）、全セグメントを見せる必要がある場合はテーブルを使用する。

> **業種別の注意点**:
> - **製造業**: 製品ライン・工場拠点が多い場合、色の割り当てが煩雑になる。階層構造（事業部→製品ライン→品目）に対応した配色階層（基調色→同系色のバリエーション）を設計する
> - **SaaS/テクノロジー**: ファネル分析（リード→商談→受注）やコホート分析で使用する色を、P&Lレポートの配色と整合させる。異なる分析フレームワーク間で色の意味が矛盾しないようにする
> - **小売・流通**: 既存店/新店、直営/FC等の区分に固定色を割り当て、店舗パフォーマンスレポートと全社レポートの間で一貫させる

### 3. レイアウト構成の標準化

**実行条件**: ステップ1-2の完了後に実施する。

レイアウトは「どの情報がどこにあるか」の予測可能性を決める。毎月同じ位置に同じ情報があれば、読み手はレポートを「探す」のではなく「確認する」だけで済む。

1. **ページ構成の標準を定める**
   - 情報の流れ: 結論→根拠→詳細の順序を徹底する。ページの上部にサマリー（数値のハイライトと一言コメント）、中段にチャートとテーブルによる根拠、下段に補足情報を配置する
   - 1ページ1メッセージの原則: 1ページに詰め込む情報量を制限し、各ページが1つの明確なメッセージを伝えるようにする
   - ページ番号と目次: 10ページ以上のレポートには目次を付ける。ページ番号は全ページに記載する

2. **定例レポートのページ順序を固定する**
   - 月次レビュー資料の例: エグゼクティブサマリー → P&L概要（全社） → 売上分析 → コスト分析 → セグメント別詳細 → KPIダッシュボード → フォワードルッキング → アペンディクス
   - ページ順序は一度決めたら原則変更しない。経営層は「3ページ目に売上分析がある」ことを記憶し、そこを直接見に行く。順序の変更は事前に通知する
   - **読み手への配慮**: ページ順序を変更する場合は、変更後の初回レポートで「構成変更のご案内」を冒頭に添付し、新しいページ構成の概要を示す

3. **テーブルの体裁を統一する**
   - 数値の表示: 右寄せ、千桁区切りカンマ、マイナスは△または括弧表記で統一。小数点以下の桁数は指標ごとに固定する
   - 比較構造: 「実績 | 予算 | 差異 | 差異率」の列順を統一する。全レポートで同じ列順を採用する
   - ヘッダ行: 背景色を薄いグレーにし、本文行と視覚的に区別する。複数行ヘッダは避ける
   - 小計・合計行: 太字にし、上に罫線を引いて内訳行と区別する

4. **余白とフォントの基準を定める**
   - 余白: ページ端から十分な余白を取る。情報をページの隅まで詰め込まない
   - フォント: 全レポートで同一のフォントファミリーを使用する。タイトル、見出し、本文、数値のフォントサイズを段階的に定める
   - 最小フォントサイズ: 印刷を想定する場合は8ポイント以上、画面閲覧専用でも10ポイント以上を下限とする

> **よくある落とし穴**: スペースが足りないからとフォントを小さくし、情報を詰め込むケース。読めないレポートは存在しないのと同じである。情報量を減らす（詳細はアペンディクスに移す）か、ページ数を増やす判断をする。

> **判断の分岐点**: レポートの配信形式（投影用、印刷配布用、画面閲覧用）によって最適なレイアウトは異なる。投影用はフォントを大きく情報量を絞る、印刷用はA4/A3に収まるよう調整する、画面閲覧用はスクロールを前提にしてよい。主たる配信形式に合わせて標準を設計し、副次的な形式には調整ルールを設ける。

> **業種別の注意点**:
> - **製造業**: 製品別・工場別の詳細データが多く、レポートのページ数が膨らみやすい。エグゼクティブサマリーとアペンディクスの二層構造を明確にし、経営層はサマリーのみ、実務担当者はアペンディクスも参照する運用とする
> - **SaaS/テクノロジー**: ダッシュボード形式のレポートが好まれる傾向がある。スライド形式とダッシュボード形式のどちらを「正」のレポートとするかを決め、体裁の標準もそれに合わせる
> - **金融業**: 規制報告と経営報告の体裁が混在しやすい。規制報告は所定のフォーマットがあるため、経営報告の標準はそれとは独立に設計し、両者の接続はブリッジテーブルで管理する

### 4. テンプレートの運用と見直し

**実行条件**: 毎月のレポート作成時にテンプレートを運用する。半期ごとにテンプレート自体の見直しを行う。

標準は策定しただけでは機能しない。テンプレートとして具体化し、日常的に使われることで初めて効果を発揮する。

1. **テンプレートファイルを作成・配布する**
   - ステップ1-3で定めた標準を反映したレポートテンプレートを作成する
   - テンプレートには、チャートの雛形（ダミーデータ入り）、配色設定済みのカラーパレット、レイアウト枠を含める
   - テンプレートの保管場所を一元化し、全作成者がアクセスできるようにする。個人のローカルにコピーを持たせない（バージョン管理の崩壊を防ぐ）

2. **レポート作成時にテンプレートへの準拠を確認する**
   - レポート作成者はテンプレートをベースに作成し、標準から逸脱しないことを自己確認する
   - レビュー者は、数値の正確性に加え、ビジュアル標準への準拠を確認項目に含める
   - 標準から逸脱する必要がある場合（特殊な分析、経営層からの個別要望等）は、FP&Aマネージャーの承認を得る

3. **半期ごとにテンプレートを見直す**
   - 過去半期のレポート作成過程で蓄積されたフィードバック（読み手からの要望、作成者の気付き）を棚卸しする
   - チャート種類の選択基準、配色、レイアウトに改善の余地がないかを検討する
   - テンプレートの修正は半期に1回に集約し、頻繁な変更による混乱を避ける。ただし、明らかな誤りやレポート構成の大幅変更に伴う修正は随時行う
   - **読み手からのフィードバックの活用**: テンプレート見直し時には、経営層や事業部門長から「レポートの見やすさ」に関するフィードバックを収集する。「このチャートは分かりやすい」「この指標はテーブルの方が見やすい」等の具体的な意見を、次期テンプレートに反映する

4. **新任メンバーへの引き継ぎに備える**
   - ビジュアル標準の趣旨と具体的なルールを、テンプレートとともに1つのガイド文書にまとめておく
   - 新任のレポート作成者が初回作成時にガイドを参照し、標準に準拠したレポートを作成できる状態を維持する
   - **引き継ぎの実務**: 新任者には、ガイド文書の読了に加え、既存メンバーによる1サイクル分のOJT（実際のレポート作成を横で見る/一緒に作成する）を推奨する。文書だけでは伝わらない「なぜこの標準にしたか」の背景理解が、標準の定着に寄与する

> **よくある落とし穴**: テンプレートを「制約」と感じた作成者が、独自のアレンジを加え始めるケース。標準の目的は「均質性」であり「創造性の排除」ではないことを共有する。定例レポートは標準に従い、アドホック分析やディープダイブ資料は自由度を持たせるという使い分けが実務上のバランスである。
