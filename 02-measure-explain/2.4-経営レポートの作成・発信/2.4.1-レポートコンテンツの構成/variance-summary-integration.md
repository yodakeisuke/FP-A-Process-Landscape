# 差異サマリーの統合

## 目的

- **誰のために**: CEO、CFO、事業部門長、取締役会メンバー
- **何を解決するか**: 予実差異分析（2.2）の結果は要因分解の粒度で散在しており、そのままでは経営層が「結局何が起きたのか」を短時間で把握できない。分解軸ごとの数表を並べるだけでは、差異間の相殺関係や優先順位が見えず、レポートの受け手が自力で統合・解釈する負担を強いることになる
- **届ける価値**: 複数の分解結果を経営の意思決定に必要な粒度に統合し、ウォーターフォールチャートとコメンタリーという2つの表現形式に変換することで、業績の変動要因を一目で把握でき、議論の出発点を揃える

## スコープ

- **対象**: 予実差異分析（2.2）の全分解結果（PVM、コスト構造、為替、セグメント、複合要因）を経営レポート向けに統合・変換するプロセス
- **前提**: 各分解フレームワークによる差異分解が完了し、ドライバの分類、性質の判別、および通期着地への影響評価が実施済みであること
- **後続**: 統合されたサマリーは業績ナラティブの作成、フォワードルッキング情報の追加と合わせて経営レポートのコンテンツを構成する
- **対象部門**: FP&A部門（実行主体）、経営企画部門（レポート受領・活用）、事業部門（コメンタリー素材の提供元）

## 責任者

| 役割 | 担当 |
|------|------|
| サマリーの統合・チャート作成 | FP&Aアナリスト |
| コメンタリーの品質レビュー・承認 | FP&Aマネージャー |
| 事業背景の補足・確認 | 事業部門の予算責任者 |
| 最終レポートの承認 | CFO / FP&Aディレクター |

## 手順

**用語の定義**:
- **ウォーターフォールチャート**: 開始値から終了値への変動を、増減要因ごとの棒グラフで橋渡し的に表現するチャート。ブリッジチャートとも呼ぶ
- **コメンタリー**: 数値の変動に対する定性的な説明文。単なる数値の読み上げではなく、「なぜそうなったか」「だから何か」を含む

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 統合設計 | 1. ウォーターフォールの軸と粒度の決定 | 月次レポートサイクルの都度。レポート体系変更時は再設計 |
| 統合実行 | 2. 分解結果の統合とブリッジ項目の算出 | 差異分解完了後 |
| 可視化 | 3. ウォーターフォールチャートの構築 | ステップ2完了後 |
| 言語化 | 4. コメンタリーの作成 | ステップ3完了後 |
| 検証 | 5. 整合性の検証と最終化 | ステップ4完了後 |

### 1. ウォーターフォールの軸と粒度の決定

**実行条件**: 月次レポートサイクルの開始時に確認する。レポート体系の変更がなければ前月の設計を踏襲する。

ウォーターフォールチャートの設計は「何を開始値・終了値にするか」「どの軸で分解するか」「何項目に分けるか」の3つの判断で決まる。

1. **開始値と終了値の組み合わせを選定する**
   - 予算 → 実績（BvA）: 標準的な月次レポート。予算に対する達成状況を示す
   - 前年同期実績 → 当期実績（YoY）: 成長性やトレンドの把握に適する。投資家向け資料でも多用される
   - 前回予測 → 実績（FvA）: 予測精度の検証。ローリング予測を運用している場合に有効
   - 受け手（経営会議、取締役会、事業レビュー）に応じて、同一データから複数のウォーターフォールを作成する場合がある

2. **分解軸を決定する**
   - P&L項目軸: 売上 → 売上原価 → 粗利 → 販管費 → 営業利益の各段階で差異を表示。全社サマリーの標準形
   - ドライバ軸: 数量・価格・ミックス・為替・コスト等の要因別に差異を表示。差異の原因理解に適する
   - セグメント軸: 事業部門別・地域別・製品別に差異を表示。責任の所在を明確にする
   - 通常は「P&L項目軸」を全社サマリーとして使い、必要に応じてドライバ軸・セグメント軸を補足資料とする

3. **項目数の制約を設定する**
   - 1つのウォーターフォールに表示する項目は7-12項目を目安とする
   - 項目が多すぎるとチャートの可読性が低下し、少なすぎると情報量が不足する
   - 重要性の低い項目は「その他」として集約する。ただし「その他」が最大項目になる場合は粒度設計を見直す

> **判断の分岐点**: ドライバ軸のウォーターフォールは分析者にとっては情報量が多く有用だが、経営層には馴染みが薄い場合がある。受け手の財務リテラシーと関心事項に応じて、P&L項目軸を主、ドライバ軸を補足とするか、その逆にするかを判断する。取締役会向けはP&L項目軸、事業レビュー向けはドライバ軸が適していることが多い。

---

### 2. 分解結果の統合とブリッジ項目の算出

**実行条件**: 全ての差異分解（PVM、コスト構造、為替、セグメント）が完了した後に実施する。

各分解フレームワークの結果は、分析の視点と粒度が異なるため、レポート向けの統合ロジックを適用する必要がある。

1. **分解結果を収集し、二重計上を排除する**
   - PVM分解の結果（数量差異・価格差異・ミックス差異）とコスト構造分解の結果（レート差異・効率差異・操業度差異）は、売上原価の変動費部分で重複する可能性がある
   - 為替影響は、売上・コスト双方に含まれるため、為替を独立項目として表示する場合は他の項目から除外する
   - 統合時のルール: 「実質業績（恒常為替レートベース）の差異」と「為替影響」に分離し、実質業績側でPVM・コスト構造の分解を表示する

2. **ブリッジ項目を算出する**
   - ステップ1で決定した軸と粒度に従い、各項目の金額を算出する
   - 各項目は「有利差異（プラス）」「不利差異（マイナス）」の符号を統一する
   - 項目の合計が「開始値 + 各項目の合計 = 終了値」となることを検算する。1円でも合わない場合は統合ロジックに誤りがある

3. **「その他」項目の内訳を管理する**
   - 集約された「その他」項目については、内訳リストを別途保持する
   - 経営層から「その他の中身は何か」と問われた際に即座に回答できるようにする
   - 「その他」の構成が前月と大きく変わった場合は、集約ルールの見直しを検討する

> **よくある落とし穴**: 差異分解の合計と損益計算書上の差異が一致しないケース。原因は、(1) 分解対象外とした小額科目の累積、(2) 端数処理の不一致、(3) 配賦ロジックの変更が分解に反映されていない、のいずれかであることが多い。統合時に必ず「分解の完全性チェック」を行い、未分解残差を把握する。

---

### 3. ウォーターフォールチャートの構築

**実行条件**: ステップ2のブリッジ項目算出が完了した後に実施する。

チャートは「数値を視覚的に伝える」ための手段であり、正確性と可読性の両立が求められる。

1. **項目の配置順序を決める**
   - P&L項目軸: P&Lの構造順（売上 → 売上原価 → 粗利 → 販管費 → 営業利益）に配置する
   - ドライバ軸: 影響額の大きい順に配置する。有利差異と不利差異を混在させるか、有利→不利の順にグルーピングするかは社内標準に従う
   - 開始値（左端）と終了値（右端）は合計バーとして視覚的に区別する

2. **視覚表現のルールを統一する**
   - 有利差異（利益増加方向）: 統一された色（例: 緑系統・青系統）
   - 不利差異（利益減少方向）: 統一された色（例: 赤系統・オレンジ系統）
   - 合計バー（開始値・終了値・小計）: 中立色（例: グレー系統）
   - 数値ラベルは各バーに付与し、単位（百万円、億円等）をチャートタイトルまたは軸ラベルに明記する
   - 色やフォーマットはレポートの品質管理と標準化の定義に従う

3. **補助線と小計の挿入を判断する**
   - P&L項目軸では、粗利や営業利益の段階で小計バーを挿入すると構造が把握しやすい
   - 予算値と実績値の水平ラインを引くことで、達成率の視覚的把握を助ける場合がある
   - 情報過多にならないよう、補助要素は最小限にとどめる

> **よくある落とし穴**: ウォーターフォールの縦軸のスケールが不適切で、小さな差異が視認できない、または大きな差異でチャートが潰れるケース。主要項目が視認できるスケールを選び、突出して大きい項目がある場合は軸の途中を省略するか、注記で補足する。

> **業種別の注意点**:
> - **製造業**: 原材料費と加工費を分けて表示すると、調達要因と生産要因が区別しやすい。操業度差異は独立項目として表示すべきか、コスト差異に含めるかを経営層と合意しておく
> - **SaaS/テクノロジー**: ARR・MRRベースのウォーターフォール（新規獲得・既存拡大・チャーン・ダウングレード）が、P&Lベースのウォーターフォールと並行して求められることが多い
> - **小売・流通業**: 既存店と新店・閉店の影響を分離したウォーターフォールが標準的。既存店成長率（Comparable Store Sales）の差異を独立表示する

### 4. コメンタリーの作成

**実行条件**: ステップ3のウォーターフォールチャート完成後に実施する。

コメンタリーはチャートの「翻訳」ではなく「解釈の付加」である。数値の読み上げは不要であり、チャートだけでは読み取れない文脈と判断を提供する。

1. **ブリッジ項目ごとにコメンタリーを作成する**
   - 各項目について以下の3要素を含める:
     - **何が起きたか**（差異の事実）: 「売上原価が予算比+15M円」
     - **なぜ起きたか**（ドライバの要約）: 「原材料価格の上昇（レート差異+12M円）が主因。市況上昇に加え、緊急調達によるスポット購入が3M円」
     - **だから何か**（経営への含意）: 「通期では+40M円の着地見込み。Q3の契約更改で一部吸収の見込み」
   - 全ての項目に同じ密度のコメンタリーは不要。重要性に応じて濃淡をつける

2. **コメンタリーの分量と形式を制御する**
   - 全社サマリーのコメンタリー: 1項目あたり2-3行が目安。全体で1ページ以内に収める
   - 詳細レポートのコメンタリー: 1項目あたり1段落（4-6行）。ドライバの分析と対応策を含む
   - 箇条書きと文章を混在させない。レポート内で形式を統一する

3. **コメンタリーのアンチパターンを排除する**
   - 数値の読み上げ: 「売上は100M円で、予算の95M円を5M円上回りました」 → チャートを見れば分かる。不要
   - 原因の欠如: 「販管費が予算を超過しました」 → 「なぜ」がない。ドライバを記載する
   - 曖昧な表現: 「やや増加」「概ね計画通り」 → 定量的に記述する。「計画通り」は差異率±2%以内の場合のみ使用可
   - 責任回避の受動態: 「コストが増加した」 → 「何がコストを増加させたか」を主語にする

> **判断の分岐点**: コメンタリーに「対応策」まで含めるか、事実と原因の記述に留めるかはレポートの位置づけによる。経営会議向けは対応策（またはその方向性）まで含めることが期待される。取締役会向けは事実と原因を中心とし、対応策は口頭で補足する場合が多い。レポートの受け手と合意しておく。

> **業種別の注意点**:
> - **製造業**: 操業度差異や歩留差異など製造固有の用語は、経営層に馴染みがない場合がある。「生産量が計画を下回ったため、固定費の回収が不足した（操業度差異 −8M円）」のように平易な説明を先に置き、専門用語を括弧内に付記する
> - **SaaS/テクノロジー**: Net Revenue Retention、LTV/CAC等の指標が経営層の関心事であることが多い。P&L差異のコメンタリーにこれらの指標との関連を織り込むと議論が深まる

---

### 5. 整合性の検証と最終化

**実行条件**: ステップ4のコメンタリー作成後に実施する。

1. **数値の整合性を検証する**
   - ウォーターフォールの開始値 + 各ブリッジ項目の合計 = 終了値であることを再確認する
   - チャート上の数値とコメンタリー中の数値が一致していることを確認する
   - 他のレポート（部門別PL、KPIダッシュボード等）との数値整合を確認する

2. **ストーリーの一貫性を検証する**
   - ウォーターフォールの視覚的な印象とコメンタリーの論調が矛盾していないか確認する
   - 例: チャートでは売上の有利差異が目立つのに、コメンタリーがコスト超過の警告に終始している場合、受け手に混乱を与える
   - 全体としてのキーメッセージ（「業績は好調だが粗利率の悪化が課題」等）が一貫しているか確認する

3. **レビューと承認を実施する**
   - FP&Aマネージャーによる内容レビュー: 分析の正確性、コメンタリーの品質、表現の適切さ
   - 事業部門への事前共有: コメンタリーの事実認識に齟齬がないか確認する。経営会議で事業部門長が「聞いていない」と言う事態を防ぐ
   - CFOまたはFP&Aディレクターの最終承認

> **よくある落とし穴**: レビュー段階で「この差異の説明は違う」と事業部門から指摘が入り、データの再確認に時間を取られるケース。これはコメンタリー作成段階で事業部門との認識合わせが不足していることが原因である。差異分析の段階から事業部門と継続的にコミュニケーションを取ることで、レポート段階での手戻りを最小化する。
