# 業績ナラティブの作成

## 目的

- **誰のために**: CEO、CFO、取締役会メンバー、事業部門長
- **何を解決するか**: 数値とチャートだけでは「だから経営として何をすべきか」が伝わらない。差異サマリーが「何が起きたか」を示すのに対し、ナラティブは「それが何を意味し、どう対処すべきか」を示す必要がある。FP&Aが数値の報告者に留まると、経営の意思決定に直接貢献できない。さらに、優れたナラティブは数値の裏にある文脈――現場の状況、顧客の動き、市場環境の変化――を統合したものであり、定量データだけからは生まれない
- **届ける価値**: 数値データを「事実→解釈→提言」の3層構造で論理的に構成されたナラティブに変換し、経営層が限られた時間で状況を理解し、判断を下すための基盤を提供する

## スコープ

- **対象**: 経営レポートにおける業績の定性的説明（ナラティブ）の構築プロセス。差異サマリーの統合結果を入力とし、ストーリーラインの構築から文章の最終化までを含む
- **前提**: 差異サマリーの統合（ウォーターフォールとブリッジ項目）が完了していること。ドライバの分類、性質の判別、および通期着地への影響評価が実施済みであること
- **後続**: 完成したナラティブはフォワードルッキング情報の追加と組み合わせ、経営レポートのコンテンツとして統合される
- **対象部門**: FP&A部門（実行主体）、事業部門（コンテキスト提供・事実確認）、経営層（レポート受領者）

## 責任者

| 役割 | 担当 |
|------|------|
| ナラティブの起案 | FP&Aアナリスト |
| ストーリーラインの設計・品質レビュー | FP&Aマネージャー |
| 事業コンテキストの提供・事実確認 | 事業部門の予算責任者 |
| 最終承認・キーメッセージの確定 | CFO / FP&Aディレクター |

## 手順

**用語の定義**:
- **ナラティブ**: 数値データに対する論理的に構造化された定性的説明。単なる「コメント」や「数値の読み上げ」とは区別する
- **ストーリーライン**: ナラティブ全体を貫く中心的なメッセージとその論理展開の骨格。個別の差異説明を束ねる上位の文脈
- **3層構造**: 事実（Fact）→ 解釈（Interpretation）→ 提言（Recommendation）の順で情報を構成する枠組み
- **Pre-alignment**: ナラティブの内容について、公式レビューの前に事業部門やCFOと事前にすり合わせるプロセス

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 情報収集 | 1. 事業部門からの定性情報の収集 | 差異サマリーの統合完了後 |
| 構造設計 | 2. ストーリーラインの設計 | ステップ1完了後 |
| 構築 | 3. 事実層の構築 | ステップ2完了後 |
| 構築 | 4. 解釈層の構築 | ステップ3完了後 |
| 構築 | 5. 提言層の構築 | ステップ4完了後 |
| 検証 | 6. 事業部門との事前すり合わせと最終化 | ステップ5完了後 |

### 1. 事業部門からの定性情報の収集

**実行条件**: 差異サマリーの統合が完了した後、ナラティブの起案前に実施する。

ナラティブの質は、数値の裏にある文脈をどれだけ把握しているかに大きく依存する。差異サマリーの数字だけを見てナラティブを書くと、「表面的な数字の読み上げ」に陥りやすい。事業の実態を理解した上で数字を解釈するために、事業部門からの定性情報の収集を起案前に行う。

1. **事業部門の予算責任者に差異の背景を確認する**
   - 差異サマリーの統合結果を事業部門と共有し、主要な差異項目について事業の文脈を聞き取る
   - **確認すべきポイント**:
     - 「この売上差異の背景にある顧客動向・市場環境は何か」
     - 「このコスト差異は意図的な施策の結果か、想定外の事象か」
     - 「前月から変化した要因で、ナラティブに反映すべきものはあるか」
     - 「事業部門として経営層に伝えたいメッセージはあるか」
   - この確認は、ナラティブの正確性と説得力を高めるだけでなく、事業部門が「FP&Aは現場の状況を理解した上で書いている」と認識する基盤となる

2. **現場マネージャーからの補足情報を収集する**
   - 予算責任者だけでなく、可能であればオペレーションに近い現場マネージャーにも短時間のヒアリングを行う
   - 現場マネージャーは、数字に表れる前の先行的な変化（顧客の問い合わせ傾向、サプライチェーンの異変、現場の課題感）を知っていることが多い
   - このヒアリングは15分程度のカジュアルな対話で十分。形式的な会議体として設定する必要はない

3. **前回のナラティブへのフィードバックを確認する**
   - 前回の経営レビュー会議で、ナラティブに対して経営層から出た質問・指摘・宿題事項を確認する
   - 「前回、粗利率の悪化について詳しく説明してほしいと言われた」「前回のアクション提言の進捗を聞かれた」等の事項を、今回のナラティブに織り込む

> **よくある落とし穴**: 事業部門への確認を省略し、FP&Aがデスクで数字だけ見てナラティブを書くケース。数字の背景にある事業の文脈が欠けたナラティブは、経営レビューの場で「実態と違う」と指摘され、FP&Aの信頼性を損なう。確認の手間をかけることが、結果として手戻りを減らし、ナラティブの品質を高める。

### 2. ストーリーラインの設計

**実行条件**: ステップ1の定性情報収集が完了した後に実施する。

ナラティブは個別の差異コメントの寄せ集めではなく、全体を貫くストーリーラインに基づいて構成する。ストーリーラインがないナラティブは、読み手に「結局何が言いたいのか」を自力で推測させることになる。ストーリーラインの設計には、ステップ1で収集した定性情報を活用する。

1. **当月の業績を一文で要約する**
   - 「営業利益は予算比+30M円（達成率105%）。売上の数量増が牽引したが、原材料費の高騰が粗利率を圧迫している」
   - この一文がナラティブ全体のストーリーラインとなる。全ての詳細記述はこの要約を支持する方向で構成する
   - 一文に盛り込む要素: 結論（良いのか悪いのか）、主要因（何が効いたか）、懸念点（何に注意すべきか）

2. **キーメッセージを3つ以内に絞り込む**
   - 差異項目の全てを等しく扱わない。経営の関心事項と照合し、「今月伝えるべきこと」を優先順位付けする
   - キーメッセージの選定基準:
     - 金額インパクトが大きいもの
     - 前月からトレンドが変化したもの（反転、加速、新規発生）
     - 経営判断を要するもの（投資の追加、方針の転換、リスクの顕在化）
     - 前回の経営会議で質問や宿題が出た事項への回答
   - **キーメッセージの選定におけるCFOとの事前すり合わせ**: 可能であれば、ストーリーラインとキーメッセージのドラフトをCFOと事前に共有し、経営層の関心事項とのずれがないか確認する。CFOが「今月はこの論点を重点的に議論したい」という意向を持っている場合、それをナラティブに反映する

3. **ストーリーラインの型を選択する**
   - **好調型**: 「業績は好調。ただし〇〇に注意が必要」 → 好材料を先に述べ、懸念事項を後段で提示
   - **課題型**: 「〇〇が業績を圧迫。対応策として△△を実施中」 → 課題を先に述べ、打ち手の進捗を示す
   - **転換型**: 「従来の〇〇トレンドが変化。背景は△△であり、今後××の影響が見込まれる」 → 変化の兆候を示し、将来への示唆を展開
   - 型の選択は当月のデータが示す状況に依存する。「良く見せたい」「悪く見せたい」という意図でストーリーラインを歪めてはならない
   - **ステップ1で収集した定性情報の活用**: 事業部門から得た文脈情報が、ストーリーラインの型の選択を支える。数字は計画達成だが、現場が強い懸念を持っている場合は「好調型」ではなく「転換型」が適切かもしれない

> **判断の分岐点**: 好材料と悪材料が拮抗している月は、ストーリーラインの設計が最も困難である。この場合、「PLの着地は計画線上だが、構成要素に変化がある」という構造で整理し、構成変化の含意に焦点を当てるのが有効である。全体の数値が計画通りだからといって「特筆事項なし」とするのは、FP&Aの価値を放棄することに等しい。

### 3. 事実層の構築

**実行条件**: ステップ2のストーリーライン設計が完了した後に実施する。

事実層は「何が起きたか」を正確に記述する層である。主観や解釈を混ぜない。

1. **定量的事実を記述する**
   - 主要なP&L項目について、実績値・予算値・差異額・差異率を記述する
   - 前年同期比が求められる場合は、予算比と並記する
   - 数値は一貫した単位・端数処理で記載する（レポート内で百万円とM円が混在しない等）

2. **差異の構成要素を記述する**
   - 差異サマリーのブリッジ項目に基づき、差異の内訳を記述する
   - 例: 「売上差異+50M円の内訳: 数量差異+35M円、価格差異+20M円、ミックス差異−5M円」
   - 構成要素間の相殺関係がある場合は明示する。「粗利差異は+10M円だが、売上増による+30M円とコスト増による−20M円が相殺した結果である」

3. **事実層で避けるべき表現**
   - 「大幅に増加」「若干の減少」 → 定量的に記述する（「+15%増加」「−2M円減少」）
   - 「計画通り」 → 差異率の範囲を明示する（「予算比+1.2%、計画線上で推移」）
   - 「好調」「不調」 → これは事実ではなく解釈。事実層では使わない

4. **事業部門との事実認識の確認**
   - 事実層のドラフトを事業部門の予算責任者に共有し、数値と記載内容が事実として正確かを確認する
   - 数値の定義や範囲について認識の齟齬がある場合（例: 事業部門が使っている「売上」の定義が管理会計と異なる）は、この段階で解消する
   - 事実認識の齟齬を放置すると、経営レビューの場で「その数字は違う」という指摘が入り、議論が数字の確認に終始する

> **よくある落とし穴**: 事実層に解釈を混入させるケース。「売上は予算比+50M円と好調だった」の「好調」は解釈である。事実層では「売上は予算比+50M円（達成率105%）」と記述し、「好調」という評価は解釈層で述べる。事実と解釈の混在は、読み手の判断を歪め、後で事実認識の齟齬を生む原因になる。

### 4. 解釈層の構築

**実行条件**: ステップ3の事実層構築が完了した後に実施する。

解釈層は「なぜそうなったか」「それは何を意味するか」を述べる層である。ドライバの分類、性質の判別、および通期着地への影響評価の結果を活用する。このステップでは、ステップ1で収集した事業部門の定性情報が特に重要な役割を果たす。

1. **差異のドライバを要約する**
   - ドライバの分類・性質の判別・通期着地への影響評価で識別されたドライバの中から、キーメッセージに関連するものを選択して記述する
   - ドライバは「実行要因」「外部要因」「計画要因」に分類して記述すると、読み手が「コントロールできるのか」を即座に判断できる
   - 例: 「原材料費の上昇（+12M円）は、国際市況の上昇（外部要因: +8M円）と緊急調達によるスポット購入（実行要因: +4M円）に分解される」
   - **事業部門の文脈を反映する**: 事業部門のヒアリングで得た背景情報を解釈に織り込む。「緊急調達によるスポット購入は、主要仕入先B社の生産トラブルに起因する」という文脈は、FP&Aのデータだけからは得られない。現場から得た情報が解釈の説得力を高める

2. **一過性と構造的の区別を明示する**
   - 各差異について、一過性か構造的かの判断を明記する
   - 一過性: 「先月の出荷遅延の反動で当月に売上が集中した（翌月は反動減の見込み）」
   - 構造的: 「新規サービスの立ち上げに伴い、クラウドインフラ費用が恒常的に月額+5M円増加」
   - この区別が曖昧だと、経営層は「放置してよい差異」と「対応が必要な差異」を判別できない
   - **一過性/構造的の判断について事業部門と合意する**: FP&Aが構造的と判断していても、事業部門は一過性と捉えている場合がある（またはその逆）。この認識のずれを事前に解消しておくことが、経営レビューでの生産的な議論の前提となる

3. **相互関連性を示す**
   - 差異項目間の因果関係や相殺関係を解釈する
   - 例: 「売上の数量増（+35M円）に伴い、変動費も増加（−20M円）しているが、変動費率は前年比で改善しており、スケール効果が発現している」
   - 個別項目を点で説明するのではなく、項目間の関係を線で結ぶことで、経営層の構造的理解を助ける

4. **比較文脈を提供する**
   - 当月の数値だけでは状況の深刻さ・重要度が伝わらない場合、比較文脈を追加する
   - 時系列比較: 「この傾向は3か月連続であり、加速している」
   - 計画比較: 「年度予算の前提と比較し、下期に回復する蓋然性は低下している」
   - 外部比較: 「同業他社も同様の市況影響を受けており、当社固有の問題ではない」（入手可能な場合）
   - **外部比較情報の収集**: 同業他社の決算情報や業界データは、IR部門、経営企画部門、業界団体の公開情報等から収集できる。FP&A単独で全てをカバーする必要はなく、IR部門に「直近の同業他社決算で、当社に示唆のある情報はあるか」と確認するだけでも解釈の質が向上する

> **判断の分岐点**: 解釈の深さはレポートの受け手によって調整する。経営会議向けは「ドライバの要約」と「一過性/構造的の判断」を中心とし、詳細な分析は補足資料に回す。事業レビュー向けは「相互関連性」と「比較文脈」まで踏み込んで記述する。

> **業種別の注意点**:
> - **製造業**: 生産効率・歩留・稼働率といった生産指標と財務差異の対応関係を示すと、事業部門との共通言語になる。「歩留が2%低下し、それが材料効率差異−8M円として現れている」。生産管理部門との事前すり合わせにおいて、この対応関係を確認する
> - **SaaS/テクノロジー**: コホート分析やユニットエコノミクスの変化をP&L差異の解釈に織り込む。「新規顧客のACVが前年比15%低下しており、売上の価格差異として顕在化している」。プロダクト部門・CS部門との情報共有が解釈の深度を左右する
> - **小売・流通業**: 客数・客単価・購買頻度の変動を売上差異の解釈に接続する。天候や暦日差の影響を定量的に分離する

### 5. 提言層の構築

**実行条件**: ステップ4の解釈層構築が完了した後に実施する。

提言層は「だからどうすべきか」を述べる層であり、FP&Aが経営の意思決定に直接貢献する部分である。提言は「書いて終わり」ではなく、前回の提言の追跡と組み合わせてフィードバックループを形成する。

1. **提言の範囲を明確にする**
   - FP&Aの提言は「分析に基づく判断材料の提示」であり、「経営判断の代行」ではない
   - 「〇〇すべきである」ではなく、「〇〇を検討する必要がある。その場合のインパクトは△△と試算される」という形式が適切
   - ただし、データが明確に方向性を示している場合は、提言の方向性を明示して構わない

2. **提言を構造化する**
   - **即時対応が必要な事項**: 閾値を超える不利差異、計画の前提が崩れた場合の見直し要否
   - **モニタリング継続事項**: トレンドの変化が確認されたが、もう1-2か月の観察が必要な項目
   - **次回以降の検討事項**: 中長期的な構造変化の兆候、予算前提の見直し候補
   - この3分類により、経営層は「今日決めること」と「次回以降に決めること」を区別できる

3. **提言に根拠を付与する**
   - 提言は必ず事実層・解釈層の記述と論理的に接続する
   - 「原材料費の市況上昇は構造的（解釈層）であり、通期では+40M円のインパクトが見込まれる（事実層の延長）。ヘッジ手段の検討または価格転嫁のタイミングについて判断が必要」（提言）
   - 事実層・解釈層に記述のない情報に基づく提言は、論理の飛躍として読み手の信頼を損なう

4. **前回の提言の追跡結果を含める（フィードバックループ）**
   - 前回のナラティブで提示した提言の進捗を追跡し、今回のナラティブに含める
   - 「前回、原材料費のヘッジ検討を提言。今月、調達部門がQ3の50%分のヘッジ契約を締結。残り50%の方針は来月判断予定」
   - 提言の追跡により、ナラティブが「毎月の一回限りの報告」ではなく「継続的な対話の蓄積」であることを示す
   - **提言が実行されなかった場合の対応**: 前回の提言が実行に移されていない場合、その理由を確認する。「優先度が低いと判断された」「リソース不足で着手できていない」「検討中で結論が出ていない」等、理由によって次の対応が異なる。重要な提言が放置されている場合は、改めて優先順位を上げて提言し直す

5. **提言に含めてはいけない内容**
   - 分析に基づかない希望的観測: 「下期には回復すると思われます」 → 根拠を示す
   - 責任の押し付け: 「事業部門の管理不足により...」 → FP&Aの役割は原因特定と対策提案であり、責任追及ではない
   - 過度に断定的な表現: 「必ず〇〇になる」 → 不確実性がある場合はその旨を明記する

> **よくある落とし穴**: 提言が「前月と同じ」になるパターン。構造的な課題に対する提言は月を跨いで継続するが、その場合は「前回提言の〇〇について、今月の進捗は△△。引き続き対応が必要」と進捗を踏まえた更新を行う。同じ文章のコピーは、FP&Aが状況をモニタリングしていないという印象を与える。

---

### 6. 事業部門との事前すり合わせと最終化

**実行条件**: ステップ3-5の3層全ての構築が完了した後に実施する。

ナラティブの最終化は、論理的一貫性の検証と関係者との事前すり合わせの両方を含む。経営レビューの場でサプライズが発生しないことを確保する。

1. **3層間の論理的接続を検証する**
   - 事実層に記述された全ての重要な差異に対して、解釈層で原因が述べられているか
   - 解釈層で「構造的」と判断された項目に対して、提言層で対応方針が述べられているか
   - 提言層の根拠が事実層・解釈層に存在するか（逆に、事実・解釈に基づかない提言がないか）
   - 論理の断絶がある場合は、該当する層を補完する

2. **ストーリーラインとの整合を確認する**
   - ステップ2で設計したストーリーラインに沿って、3層の内容が一貫しているか確認する
   - キーメッセージと矛盾する記述がないか確認する
   - 詳細の記述に引きずられてストーリーラインがぼやけている場合は、キーメッセージを冒頭に再配置する

3. **事業部門との事前すり合わせ（Pre-alignment）を実施する**
   - ナラティブのドラフトを事業部門の予算責任者と共有し、以下を確認する:
     - 事実認識に齟齬がないか
     - 解釈（一過性/構造的の判断、ドライバの帰属）に合意できるか
     - 提言の内容が実行可能か、事業部門として追加・修正したい観点はあるか
   - **すり合わせのルール**: 事実の修正は受け入れる。解釈についてはFP&Aと事業部門で見解が異なる場合、双方の見解を記録し、必要に応じて「FP&Aの見解」として注記する。提言については事業部門の意見を取り入れつつ、FP&Aの独立性を維持する
   - **異論が解消しない場合のエスカレーション**: 事業部門とFP&Aの見解が重要な点で一致しない場合、その論点をCFOに報告し、判断を仰ぐ。エスカレーションは対立ではなく、経営判断に必要な多面的な視点の提供として位置づける

4. **読み手視点での最終チェック**
   - 経営層の立場で読み直し、以下を確認する:
     - 3分で全体像が把握できるか（エグゼクティブサマリーの機能）
     - 「だから何をすべきか」が明確か
     - 専門用語に過度に依存していないか。事業部門の言葉で語れているか
   - **財務用語の翻訳**: FP&Aのナラティブは、財務のバックグラウンドがない読み手にも理解できるよう、可能な限り事業の言葉で記述する。「操業度差異−8M円」ではなく「生産量が計画を下回ったため、固定費の単位あたり負担が増加し−8M円」と記述する。経営層が数字の意味を直感的に把握できることが重要
   - FP&Aマネージャーのレビューを経て、CFOまたはFP&Aディレクターが最終承認する

> **判断の分岐点**: ナラティブの分量は「短いほどよい」が原則だが、短くするために重要な情報を削ると意思決定に支障をきたす。目安として、全社サマリーのナラティブはA4で1-2ページ、事業部門別の詳細ナラティブは各1ページ以内とする。これを超える場合は、ストーリーラインの絞り込みが不足している可能性がある。
