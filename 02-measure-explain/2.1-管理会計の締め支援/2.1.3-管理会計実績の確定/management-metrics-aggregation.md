# 管理指標の集計

## 目的

- **誰のために**: CFO、事業部門長、経営企画部門、KPIオーナー
- **何を解決するか**: 部門別PLが確定しても、経営判断に必要な指標はPLの数値だけでは完結しない。利益率、効率性指標、非財務指標（人員、顧客数、案件数等）を個別に集計していると、指標間の整合性が取れず、「PLの数字と矛盾するKPI」が報告される。財務指標と非財務指標が紐付かないまま経営会議に上がると、議論が噛み合わない
- **届ける価値**: 確定した管理会計実績をベースに、財務指標と非財務指標を一貫した定義・タイミングで集計し、経営管理に使えるKPIセットとして一元的に提供する

## スコープ

- **対象**: 管理会計実績の確定プロセスのうち、部門別PL確定後のKPI・非財務指標の集計・統合作業。本SOPは [2.3 KPIの運用・モニタリング](../../2.3-KPIの運用・モニタリング/2.3.1-KPIの定義と目標設定/kpi-selection-definition.md) で定義されたKPIの月次集計を扱う。KPIの定義・選定・体系設計は2.3系SOPを参照
- **前提**: 部門別PLの確定が完了していること。非財務指標のデータソース（人事システム、営業管理システム、顧客管理システム等）からのデータ取得が可能であること
- **後続**: 集計されたKPIセットは、実績確定の承認と引き渡しを経て、KPIモニタリング・経営レポート作成に使用される
- **対象部門**: FP&A部門（実行主体）、事業部門（非財務データ提供元・KPIオーナー）、人事部門・営業企画部門等（非財務データ提供元）

## 責任者

| 役割 | 担当 |
|------|------|
| KPIの集計・検証 | FP&Aアナリスト |
| KPI定義の管理・例外判断 | FP&Aマネージャー |
| 非財務データの提供・精度保証 | 各データオーナー（人事、営業企画等） |
| 部門別KPIの確認・コメント付与 | 事業部門の管理職 |

## 手順

**用語の定義**:
- **財務KPI**: 管理会計実績から算出される指標（売上総利益率、EBITDA、一人当たり売上高等）。計算の基礎は確定済みの部門別PLにある
- **非財務指標**: 財務データ以外の事業活動の状態を示す数値（従業員数、顧客数、解約率、リードタイム、NPS等）。財務KPIの先行指標や補足指標として使用する
- **KPI定義書**: 各KPIの計算式、データソース、更新頻度、責任者、閾値を定めた文書。指標の一貫性を担保する基盤

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 前提整備 | 1. KPI定義書の整備と維持 | 定義書の新規作成時または見直し時。月次集計時は参照のみ |
| 集計 | 2. 財務KPIの算出 | 部門別PLの確定後 |
| 集計 | 3. 非財務指標の取得と検証 | ステップ2と並行実施可能 |
| 統合 | 4. 財務・非財務指標の統合と整合性確認 | ステップ2・3の完了後 |

### 1. KPI定義書の整備と維持

**実行条件**: KPI体系の新規構築時、戦略変更・組織再編時、または半期ごとの定期見直し時。月次の集計作業では既存の定義書を参照する。

KPIの集計において最も多いトラブルは「定義のブレ」である。同じ名前の指標が部門によって異なる計算式で算出されている状態は、経営会議での議論を空転させる。

1. **KPIごとに定義の構成要素を明文化する**
   - 指標名称と一意のID
   - 計算式（分子・分母の定義を含む）
   - データソース（どのシステムのどのフィールドから取得するか）
   - 集計の粒度と期間（月次/四半期、部門別/全社、ストック/フロー）
   - 更新タイミング（部門別PL確定後〇営業日以内等）
   - 責任者（KPIオーナー: 定義の妥当性に責任を持つ人）

2. **計算式の曖昧さを排除する**
   - 「売上高」が総売上か純売上か、「人員数」が期末時点か期中平均か、「顧客数」がアクティブ顧客のみか全顧客かを明記する
   - 除外条件を明示する（例: 一人当たり売上高の計算で、入社1か月未満の社員を含めるか）
   - 年率換算（annualize）の方法を統一する（単月×12か、直近12か月累計か）

3. **KPIの階層構造を整理する**
   - 全社KPI → 部門KPI → チームKPIのカスケードを定義する
   - 上位KPIと下位KPIの関係性を明確にする（分解関係、先行・遅行関係、相関関係）
   - KPI間の相互依存を把握する（例: 顧客獲得コストの改善が一人当たり売上高を押し上げるが、顧客品質の低下で解約率が上昇するリスク）

> **よくある落とし穴**: KPI定義書が形骸化し、実際の集計作業では担当者の暗黙知で計算しているケース。担当者の交代時に計算方法が変わり、トレンドの連続性が断絶する。定義書と実際の集計ロジックの一致を半期ごとに検証する。

> **判断の分岐点**: KPIの数は多すぎると焦点がぼやけ、少なすぎると盲点が生まれる。全社レベルで10-15指標、部門レベルで5-8指標が目安である。これを超える場合は「経営会議で議論するKPI」と「モニタリング専用のKPI」を明確に層別する。

### 2. 財務KPIの算出

**実行条件**: 部門別PLの確定が完了した後に実施する。

1. **確定済み部門別PLからKPIの基礎数値を取得する**
   - KPI定義書に基づき、各KPIの計算に必要なPL科目の数値を抽出する
   - 取得元が確定版（ロック済み）の部門別PLであることを確認する。未確定の暫定値を使わない
   - 複数部門にまたがるKPI（例: 全社EBITDA）は、全部門の確定が完了してから算出する

2. **KPIを算出する**
   - 定義書の計算式に従い、各KPIを算出する
   - 代表的な財務KPI:

   | カテゴリ | KPI例 | 計算の要点 |
   |---------|-------|-----------|
   | 収益性 | 売上総利益率、営業利益率、EBITDA率 | 分母の売上高の定義（総額/純額）を統一する |
   | 効率性 | 一人当たり売上高、一人当たり営業利益 | 人員数の定義（期末/平均、FTE/頭数）を統一する |
   | 成長性 | 売上高成長率、営業利益成長率 | 前年同期との比較可能性を確保する（組織変更の影響を除外） |
   | 投資効率 | ROIC、投下資本回転率 | BS項目が必要な場合は経理部門から取得する |

3. **算出結果の妥当性を検証する**
   - 前月実績・前年同月実績との比較で異常値がないか確認する
   - KPI間の整合性を確認する（例: 売上高成長率がプラスなのに一人当たり売上高が低下している場合、人員増の影響を確認する）
   - 計算過程で四捨五入や端数処理が累積していないか確認する（特に比率指標）

> **よくある落とし穴**: 組織再編があった期間のKPIを前年同期と単純比較するケース。組織再編前後で同一部門のスコープが異なる場合、プロフォーマ（仮定再表示）ベースでの比較が必要である。プロフォーマ調整を行うか行わないかは、FP&Aマネージャーが判断し、レポートに注記する。

---

### 3. 非財務指標の取得と検証

**実行条件**: 部門別PLの確定とは独立して開始できるが、ステップ4の統合にはステップ2の完了が必要。

1. **データソースから非財務指標を取得する**
   - KPI定義書に記載されたデータソースから、当月分の非財務指標を取得する
   - 代表的な非財務指標のデータソース:

   | 指標カテゴリ | 指標例 | データソース |
   |------------|--------|------------|
   | 人員 | 従業員数、FTE、離職率 | 人事システム |
   | 顧客 | 顧客数、新規獲得数、解約率 | 顧客管理システム |
   | 営業活動 | パイプライン、受注率、案件数 | 営業管理システム |
   | オペレーション | 稼働率、リードタイム、品質指標 | 生産管理・業務管理システム |

   - データの基準日・対象期間がKPI定義書と一致していることを確認する（例: 従業員数は月末時点、解約率は当月中の解約件数÷月初顧客数）

2. **非財務データの品質を検証する**
   - 前月比で異常な変動がないか確認する（急激な増減は入力ミスまたは集計対象の変更の可能性がある）
   - データの欠損がないか確認する（特定の部門・拠点のデータが未提出の場合、該当部門に確認する）
   - 定義変更がないか確認する（例: 「アクティブ顧客」の定義が「過去3か月以内に取引あり」から「過去6か月以内」に変更されていないか）

3. **データ未取得・品質不足時の対応を決める**
   - 締め日までにデータが取得できない非財務指標がある場合、前月値での暫定反映か、当該指標の非開示かを判断する
   - 暫定値で反映する場合は、暫定であることを明記し、翌月に確定値で置き換えるルールを適用する
   - データ品質に懸念がある指標は、そのまま集計せずデータオーナーに差し戻す。品質に疑義のあるデータが経営レポートに載ると、KPI全体の信頼性を毀損する

> **判断の分岐点**: 全ての非財務指標が揃うまで待つか、入手済みの指標から先行して統合に進むかは、経営レポートの締め切りとの兼ね合いで決める。主要指標（経営会議で議論されるKPIの基礎となる非財務指標）は必ず当月の実績値を取得する。補足的な指標は前月値の暫定反映を許容してよい。

> **業種別の注意点**:
> - **SaaS/テクノロジー**: MRR、ARR、チャーン率、NRR等のSaaS固有指標は、顧客管理システムと請求システムの両方からデータを取得する必要がある場合が多い。データソース間の定義差異（契約ベースか請求ベースか）に注意する
> - **製造業**: 生産量、歩留まり、設備稼働率等のオペレーション指標は生産管理システムから取得する。会計期間と生産期間のカットオフが一致しているかを確認する
> - **サービス業**: 稼働率（ビラブルレシオ）、プロジェクト利益率等はプロジェクト管理システムから取得する。工数入力の遅延が指標の精度に直結するため、入力締め日の遵守状況も確認する

---

### 4. 財務・非財務指標の統合と整合性確認

**実行条件**: ステップ2（財務KPIの算出）とステップ3（非財務指標の取得）がともに完了した後に実施する。

1. **KPIセットを一覧に統合する**
   - 財務KPIと非財務指標を、KPI定義書の階層構造に従って一覧化する
   - 全社レベル・部門レベルの各粒度でKPIセットを構成する
   - 各指標に当月実績、前月実績、予算値、前年同月実績を並記する（比較軸の網羅）

2. **財務指標と非財務指標の整合性を検証する**
   - 財務と非財務の間に論理的矛盾がないかを確認する:
     - 売上高が増加しているのに顧客数が減少している場合 → 客単価の上昇か、大口顧客の集中か
     - 人件費が増加しているのに従業員数が減少している場合 → 一人当たり人件費の上昇（昇給、残業増、構成比変化）か
     - 営業利益率が改善しているのに顧客満足度が低下している場合 → コスト削減がサービス品質を犠牲にしていないか
   - 矛盾がある場合は、データの誤りか、実態としての変化かを判別する。実態の変化であれば、後続の差異分析やレポートで解説すべき論点として記録する

3. **KPIダッシュボード・帳票への反映を行う**
   - 統合されたKPIセットを、経営ダッシュボードや月次帳票のフォーマットに反映する
   - 信号灯（目標達成状況の色分け）を更新する。閾値はKPI定義書に基づく
   - 暫定値で反映した指標がある場合は、その旨をダッシュボード上に明示する

4. **KPIコメンタリーの素材を準備する**
   - 主要KPIについて、当月の変動要因の概要を記録する（詳細な分析は予実差異分析で行うが、集計時点で把握した事実を記録しておく）
   - 前月から継続して悪化しているKPI、または閾値を超過したKPIにフラグを立てる
   - これらの素材は、実績確定の承認時の説明資料、および経営レポートのコメンタリー作成に使用する

> **よくある落とし穴**: 財務KPIと非財務指標の集計期間のずれを見落とすケース。例えば、財務KPIは暦月ベースだが、顧客データは4週サイクルで集計されている場合、月末の数日分のずれが生じる。ずれが構造的に存在する指標は、KPI定義書にその旨を明記し、解釈時の注意点として共有する。

> **判断の分岐点**: KPIの数値が目標から大きく乖離している場合、集計段階でデータの正確性を再検証すべきか、そのまま報告して分析段階に委ねるべきか。原則は後者（集計段階では事実の正確な記録に徹し、解釈は分析段階で行う）だが、明らかなデータ異常（例: 前月比で桁が違う）は集計段階で差し戻す。「異常値」と「悪い実績」を混同しないこと。
