# 部門別PLの確定

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー、経営企画部門
- **何を解決するか**: 調整仕訳や配賦計算が反映された後の管理会計数値は、制度会計の数値とも予算の体系とも異なる「第三の数値」になる。この数値が部門別に正しく集計・確定されないまま後続の分析に流れると、予実差異分析の起点がずれ、業績評価の信頼性が崩壊する
- **届ける価値**: 事業部門・コストセンター・プロフィットセンター別の管理会計ベースPLを正式な「単一の事実」として確定し、後続の差異分析・KPIモニタリング・経営レポートの共通基盤を提供する

## スコープ

- **対象**: 管理会計の締め支援プロセスのうち、調整仕訳・配賦計算反映後の部門別PL確定作業
- **前提**: 調整仕訳の作成、配賦計算の実行、制度会計との差異照合が完了していること
- **後続**: 確定した部門別PLは、管理指標の集計、実績確定の承認と引き渡しを経て、予実差異分析・経営レポート作成に使用される
- **対象部門**: FP&A部門（実行主体）、経理部門（制度会計データ提供元）、事業部門（確認・合意先）

## 責任者

| 役割 | 担当 |
|------|------|
| 部門別PLの作成・検証 | FP&Aアナリスト |
| 確定判断・例外処理の承認 | FP&Aマネージャー |
| 制度会計実績データの提供 | 経理部門 |
| 部門別数値の確認・質疑応答 | 事業部門の管理職 |

## 手順

**用語の定義**:
- **部門別PL**: 管理会計上の組織単位（事業部門・コストセンター・プロフィットセンター）ごとに集計した損益計算書。制度会計のPLとは体系・粒度が異なる
- **確定（ロック）**: 当月の管理会計数値を公式な実績として固定し、以降の修正を原則として認めない状態にすること。確定後の修正は翌月以降の調整仕訳で対応する

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 集計 | 1. 部門別PL組替えテーブルの維持と適用 | 組替えルールの新規作成時または変更時。月次はテーブル参照のみ |
| 集計 | 2. 調整仕訳・配賦結果の部門別集計 | 前工程（調整仕訳・配賦計算・差異照合）完了後 |
| 検証 | 3. 部門別PLの整合性検証 | ステップ2完了後。全部門について実施 |
| 確定 | 4. 部門別PLの確定とロック | ステップ3の検証完了後 |

### 1. 部門別PL組替えテーブルの維持と適用

**実行条件**: 組替えルールの新規構築時、組織再編時、または半期ごとの定期見直し時。月次の確定作業では既存テーブルを参照する。

管理会計の部門別PLは、制度会計の勘定科目体系を管理会計の損益構造に「組替え」て作成する。この組替えテーブルが管理会計PLの骨格であり、ここが不正確だと全ての部門別数値が歪む。

1. **制度会計科目と管理会計科目のマッピングを定義する**
   - 制度会計の勘定科目を管理会計のPL表示科目に対応付ける（例: 制度会計の「給与手当」→ 管理会計の「人件費-正社員固定給」「人件費-正社員変動給」に分割）
   - 1対1のマッピングだけでなく、1対多（制度会計1科目を管理会計の複数科目に分割）、多対1（制度会計の複数科目を管理会計の1科目に統合）のパターンを網羅する
   - マッピングに按分が伴う場合、按分キー（人員数、面積、売上比率等）とそのデータソースを明記する

2. **組織階層と集計単位を定義する**
   - 最小集計単位（コストセンター/プロフィットセンター）を決め、上位への積み上げルールを設定する
   - 典型的な階層: コストセンター → 部 → 事業部門 → 全社。プロフィットセンターは事業部門単位で設定されることが多い
   - 内部取引（部門間の役務提供・振替）の消去ルールを定義する。消去を行う階層レベルを明確にする

3. **PLの段階利益構造を定義する**
   - 管理会計PLに表示する段階利益を決める（例: 売上総利益 → 直接貢献利益 → 部門営業利益 → 全社営業利益）
   - 各段階利益に含める費目と含めない費目を明確にする。特に間接費配賦をどの段階で反映するかは経営判断に直結するため、FP&Aマネージャーと事業部門長の合意を取る

> **よくある落とし穴**: 組織再編があったにもかかわらず組替えテーブルを更新しないまま月次を迎えるケース。前年同期比や予算比の比較可能性が失われ、差異分析の全てが手戻りになる。組織変更が発生した場合は、変更の発効月より前に組替えテーブルを更新し、影響範囲を記録する。

> **業種別の注意点**:
> - **製造業**: 工場別・製品群別のプロフィットセンター管理が一般的。標準原価と実際原価の差異（原価差額）をどの部門に帰属させるかが論点になる
> - **SaaS/テクノロジー**: 機能別組織（開発・CS・セールス・G&A）での管理が主流。プロダクト別の収益性を見るには、開発コストの按分ロジックが鍵になる
> - **持株会社・多角化企業**: 事業会社別PLと機能別コストセンターの二軸管理が必要。本社費配賦の合理性が事業評価を左右する

---

### 2. 調整仕訳・配賦結果の部門別集計

**実行条件**: 前工程（調整仕訳の作成、配賦計算の実行、制度会計との差異照合）が全て完了した後に実施する。

1. **制度会計実績を取り込み、調整仕訳を反映する**
   - 経理部門から受領した制度会計の部門別試算表に、管理会計調整仕訳（再分類、非経常項目の除外・調整、期間帰属の修正等）を加算する
   - 調整仕訳の反映順序: (1) 再分類仕訳 → (2) 非経常項目の除外 → (3) 期間帰属の修正 → (4) その他の管理調整。順序を変えると中間検証ができなくなる

2. **配賦計算の結果を部門に展開する**
   - 間接費配賦、共通費按分の結果を各部門のPLに反映する
   - 配賦元（本社部門等）のコストが配賦後にゼロになることを確認する（配賦漏れ・過剰配賦の検出）
   - 多段階配賦（サービス部門間の相互配賦）を行っている場合は、配賦の順序と最終残高を検証する

3. **内部取引の消去を行う**
   - 部門間取引（内部売上と内部仕入、部門間サービス費用等）を識別し、集計レベルに応じて消去する
   - 消去前後の全社合計が制度会計の数値と整合することを確認する

4. **組替えテーブルに基づきPLフォーマットに変換する**
   - ステップ1で定義した組替えテーブルを適用し、管理会計PLのフォーマットに変換する
   - 按分が必要な科目は、当月の按分キーの最新値を適用する（固定キーを使っている場合はその旨を記録）

> **よくある落とし穴**: 調整仕訳の反映と配賦計算の結果反映を並行して行い、二重計上が発生するケース。特に配賦対象となる間接費に管理会計調整が含まれている場合、「調整後の金額」を配賦しているか「調整前の金額」を配賦しているかで結果が変わる。配賦計算のインプットが調整後の数値であることを必ず確認する。

> **判断の分岐点**: 月次の配賦按分キーを毎月更新するか、年初に固定するかは運用負荷と精度のトレードオフである。金額の大きい配賦（人件費、オフィス賃料等）は四半期ごとにキーを更新し、少額の配賦は年初固定で許容するのが実務的な落としどころである。ただし、大規模な人員異動や拠点変更があった月は、少額配賦も含めてキーの臨時更新を検討する。

### 3. 部門別PLの整合性検証

**実行条件**: ステップ2の集計が完了した後、全部門について実施する。

確定前の最終検証であり、ここでの見落としは後続プロセス全体に影響する。機械的なチェックと分析的なレビューの両方を行う。

1. **縦の整合性を検証する（各部門内のPL構造チェック）**
   - 各段階利益が正しく計算されているか（売上高 − 売上原価 = 売上総利益、等）
   - 符号の異常がないか（費用科目がマイナス、収益科目がマイナスになっている場合は原因を確認）
   - 前月比・前年同月比で異常な変動がある科目を抽出し、原因を確認する（閾値例: 前月比±30%超、または金額で±500万円超）

2. **横の整合性を検証する（部門間・全社レベルのチェック）**
   - 全部門の合計値が、管理会計ベースの全社PLと一致することを確認する
   - 管理会計の全社PLと制度会計のPLの差異が、調整仕訳の合計額と一致することを確認する（ブリッジの完全性）
   - 内部取引の消去が正しく行われ、全社レベルで残高がゼロになっていることを確認する

3. **分析的レビューを実施する**
   - 部門別の主要利益率（売上総利益率、部門営業利益率等）が合理的な範囲にあるか確認する
   - 前月・前年同月からの利益率の変動が説明可能かどうかを確認する
   - 特定部門にコストが偏っていないか（配賦の歪みの兆候）を確認する

4. **不整合が検出された場合の対応**
   - 不整合の原因を特定し、修正が必要な場合は調整仕訳の追加または配賦計算の再実行で対応する
   - 修正の影響範囲を評価し、修正後に再度ステップ3の検証を実施する
   - 期限内に原因を特定できない差異が残る場合は、FP&Aマネージャーに報告し、暫定値での確定か締め日の延長かの判断を仰ぐ

> **判断の分岐点**: 軽微な不整合（全社PLの合計との差異が数千円レベルの端数差異）は、丸め差異として記録の上そのまま確定してよい。ただし「軽微」の閾値は事前に定義しておく（例: 各部門の営業利益の0.01%未満）。閾値を超える不整合は、金額の大小にかかわらず原因を特定する。

> **業種別の注意点**:
> - **製造業**: 原価差額（標準原価と実際原価の差異）の配分先と配分方法が部門別PLの利益率に大きく影響する。原価差額の処理が正しいかを重点的に検証する
> - **小売・流通業**: 店舗別PLでは本部費配賦の影響が大きい。店舗の直接貢献利益と配賦後利益の両方を検証し、配賦による逆転（直接貢献利益は黒字だが配賦後は赤字）がないか確認する
> - **プロジェクト型事業**: プロジェクト別PLとコストセンター別PLのクロス検証が必要。同一コストが両方の軸で正しく集計されているかを確認する

---

### 4. 部門別PLの確定とロック

**実行条件**: ステップ3の整合性検証が完了し、重要な不整合が解消された後に実施する。

1. **確定対象の最終確認を行う**
   - 全部門のPLが検証済みであることを確認する（検証チェックリストの完了状態を確認）
   - 暫定値で確定する部門がある場合、その部門と暫定の理由を明記する
   - 前月に暫定値で確定した項目がある場合、当月の確定値で修正が反映されていることを確認する

2. **確定処理を実行する**
   - 管理会計システム上で当月の部門別PLデータをロックする（手動運用の場合は、確定版ファイルに「確定」のステータスを付与し、以降の編集を禁止する）
   - 確定日時と確定者を記録する
   - 確定版のスナップショットを保存する（後日の検証・監査対応のため）

3. **確定後の修正ルールを運用する**
   - 確定後に誤りが判明した場合は、当月のデータを遡及修正しない。翌月以降の調整仕訳で対応する
   - ただし、重大な誤り（部門営業利益の10%超に影響する誤り等）が確定後・後続プロセス開始前に発見された場合は、FP&Aマネージャーの承認を得て例外的にロック解除・再確定を行う
   - ロック解除の実績（日時、理由、影響範囲、承認者）は全件記録する

> **よくある落とし穴**: 「確定」の定義が曖昧で、後続プロセスが開始された後も部門別PLの数値が更新され続けるケース。差異分析の途中で基準値が変わると、分析結果の信頼性が失われ、手戻りが発生する。確定＝ロックを厳格に運用し、後続プロセスの開始条件として「部門別PLの確定完了」を明示する。

> **判断の分岐点**: 全部門の検証完了を待つか、検証完了した部門から順次確定するかは、後続プロセスのスケジュールとの兼ね合いで決める。月次締めの期限が厳しい場合、主要部門（売上の80%をカバーする部門群）を先行確定し、残りの部門は翌営業日に確定するという段階的確定も選択肢となる。ただし、段階的確定を行う場合は、先行確定分だけで全社PLを仮集計しないこと（部分的な数値が独り歩きするリスクがある）。
