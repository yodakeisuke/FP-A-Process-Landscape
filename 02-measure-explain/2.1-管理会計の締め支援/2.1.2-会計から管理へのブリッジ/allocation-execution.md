# 配賦計算の実行

## 目的

- **誰のために**: CFO、事業部門長、コストセンター責任者、製品ポートフォリオ責任者
- **何を解決するか**: 間接費・共通費は発生部門と受益部門が一致しないため、そのままでは事業部門・製品・プロジェクト単位の収益性が正しく把握できない。配賦なしの部門PLは直接費のみの不完全な姿であり、配賦ルールが不適切であれば収益性の序列が実態と逆転し、資源配分の意思決定を歪める
- **届ける価値**: 経済的因果関係に基づく配賦基準を設計・適用し、間接費を受益の実態に即して配分することで、部門・製品・プロジェクト単位の収益性を公正に把握し、資源配分と業績評価の精度を高める

## スコープ

- **対象**: 管理会計ベースの間接費・共通費を部門・製品・プロジェクト等の配賦先に配分するプロセス。配賦基準の選定、配賦計算の実行、結果の検証を含む
- **前提**: 調整仕訳の作成が完了し、配賦前の管理会計実績が確定していることが入力条件。配賦ルール・費目体系は年度予算編成時に設計されたものを使用する
- **後続**: 配賦後の部門別PLが確定し、制度会計との差異照合および管理会計実績の確定に引き渡される
- **対象部門**: FP&A部門（実行主体）、経理部門（制度会計側の配賦データとの照合）、間接部門（コスト発生元・配賦基準データ提供元）、事業部門（配賦先・受益者・配賦結果の確認者）

## 責任者

| 役割 | 担当 |
|------|------|
| 配賦計算の実行・検証 | FP&Aアナリスト |
| 配賦ルールの設計・承認 | FP&Aマネージャー |
| 配賦基準データの提供 | 間接部門・管理部門（人事、IT、総務等） |
| 配賦結果の受領・確認 | 事業部門の予算責任者 |

## 手順

**用語の定義**:
- **配賦基準（Allocation Base）**: 間接費を配賦先に配分する際の尺度。受益の程度を代理する指標を選定する（例: 人員数、床面積、売上高、直接費合計）
- **配賦元（Cost Pool）**: 配賦対象となる間接費の集合。同質のコストを一つのプールにまとめ、共通の配賦基準で配分する
- **配賦レート**: 配賦元の金額を配賦基準の総量で除した単価。配賦レート = 配賦元金額 / 配賦基準総量

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 前提整備 | 1. 配賦ルールの確認と配賦基準データの取得 | 毎月次。年度中の配賦ルール変更時は追加で設計レビューを実施 |
| 配賦実行 | 2. 直接配賦の実行 | 毎月次。直接配賦対象の間接費がある場合 |
| 配賦実行 | 3. 段階配賦の実行 | 毎月次。間接部門間の相互サービスがある場合 |
| 配賦実行 | 4. 共通費の按分 | 毎月次。全社共通費の配分が必要な場合 |
| 結果統合 | 5. 配賦結果の検証と引き渡し | ステップ2-4完了後 |

### 1. 配賦ルールの確認と配賦基準データの取得

**実行条件**: 毎月次。月初の管理会計締めプロセスの中で実施する。

配賦計算の精度は、配賦基準の選定とデータの鮮度に依存する。毎月の計算前に前提を確認する。配賦基準データの取得は複数の間接部門に依存するため、依頼のタイミングと収集の仕組みが重要である。

1. **当月適用する配賦ルールを確認する**
   - 年度予算編成時に設計された配賦ルール一覧を参照する
   - 配賦ルール一覧に含めるべき項目: 配賦元（コストプール名・対象科目）、配賦基準、配賦先（部門・製品等）、配賦方法（直接配賦 / 段階配賦 / 按分）
   - 前月からのルール変更がないか確認する。変更がある場合は、変更内容と影響範囲をFP&Aマネージャーが承認する

2. **配賦基準データを取得する（部門横断の連携）**
   - 配賦基準ごとに、当月の実績データまたは最新のデータを取得する:

   | 配賦基準 | データソース | 更新頻度 | FP&Aからの依頼タイミング |
   |---------|------------|---------|----------------------|
   | 人員数・FTE | 人事部門 | 毎月 | 締め開始の3営業日前 |
   | 床面積 | 総務部門 | 変更時 | 四半期初、変更発生時 |
   | IT利用量（端末数、ストレージ等） | IT部門 | 毎月または四半期 | 締め開始の3営業日前 |
   | 売上高・直接費 | FP&A実績データ | 毎月 | 自動（データ取得と同時） |
   | 工数・プロジェクト時間 | プロジェクト管理部門 | 毎月 | 締め開始の3営業日前 |

   - データが当月分として未確定の場合（例: 月末時点の人員数が月初にしか確定しない）、前月実績または予算値を暫定的に使用し、翌月に洗い替える
   - **データ提供部門との関係構築**: 配賦基準データの提供は、提供元部門にとっては「自部門の業務に直接関係しない追加作業」に見えることがある。FP&Aから「このデータがどのように使われ、どのような経営判断に影響するか」を説明することで、データ提供の優先度を高めてもらう。例えば「人員データは部門別の収益性分析に使われ、リソース配分の意思決定に直結します」と伝える

3. **配賦基準の妥当性を確認する**
   - 配賦基準の構成比が前月から大きく変動していないか確認する（10%超の変動は要確認）
   - 変動がある場合、実態の変化（組織再編、拠点移転、大型プロジェクトの開始・終了等）に起因するか、データの誤りかを判別する。判別が難しい場合はデータ提供元部門に確認する
   - 配賦基準が受益の実態を適切に反映しているか、四半期ごとにレビューする。レビューには配賦先である事業部門の視点も取り入れる

> **判断の分岐点**: 配賦基準を「実績ベース」にするか「予算ベース」にするかは、目的によって使い分ける。実績ベースは受益の実態をより正確に反映するが、配賦先の受領額が毎月変動し予測しにくい。予算ベースは安定的だが、年度中の構造変化を反映しない。業績評価目的には予算ベース、収益性分析目的には実績ベースを使う企業が多い。

> **業種別の注意点**:
> - **製造業**: 製造間接費の配賦基準として直接作業時間や機械稼働時間を使用するのが伝統的。ただし自動化が進んだ工程では直接作業時間が極端に少なくなり、配賦レートが異常に高くなる。活動基準（作業指示件数、段取り回数等）の併用を検討する
> - **SaaS/テクノロジー**: R&D費用の製品別配賦が論点になりやすい。開発工数の自己申告データを使う場合、申告精度が配賦精度のボトルネックになる
> - **金融業**: 本部機能（リスク管理、コンプライアンス、法務等）のコストが大きく、配賦ルールが収益性評価に大きく影響する。規制対応コストの配賦は特に慎重に設計する

### 2. 直接配賦の実行

**実行条件**: 毎月次。特定の配賦先に直接紐づけ可能な間接費がある場合に実施する。

直接配賦は、間接部門のコストを事業部門に直接配分する最もシンプルな方法である。

1. **直接配賦対象のコストプールを特定する**
   - 間接部門のコストのうち、受益先が明確に特定でき、単一の配賦基準で配分可能なもの
   - 例: IT部門のコスト→端末数で配分、総務部門のオフィスコスト→床面積で配分、人事部門の採用費→部門別採用人数で配分

2. **配賦レートを算出する**
   - 配賦レート = コストプール金額 / 配賦基準総量
   - 例: IT部門コスト 1,000万円 / 全社端末数 500台 = 2万円/台

3. **配賦額を計算する**
   - 各配賦先の配賦額 = 配賦レート × 当該配賦先の配賦基準量
   - 例: A事業部（100台）= 200万円、B事業部（150台）= 300万円、C事業部（250台）= 500万円
   - 全配賦先の配賦額合計がコストプール金額と一致することを確認する（端数処理により数円の差異が生じる場合は、最大配賦先に寄せる）

4. **配賦仕訳を起票する**
   - 借方: 各事業部門の間接費受入科目
   - 貸方: 間接部門のコストプール科目（配賦控除）
   - 配賦元の残高がゼロになることを確認する

> **よくある落とし穴**: 直接配賦は間接部門間のサービス提供を無視する。例えば、IT部門が人事部門にもサービスを提供している場合、IT部門のコストは全額が事業部門に配賦され、人事部門はIT部門のコストを負担しない。この結果、人事部門のコストが過小に、事業部門のIT関連コストが過大に計上される。間接部門間の相互サービスが重要な場合は、段階配賦（ステップ3）を採用する。

### 3. 段階配賦の実行

**実行条件**: 毎月次。間接部門間で相互にサービスを提供しており、直接配賦では配賦結果が歪む場合に実施する。

段階配賦（ステップダウン方式）は、間接部門間のサービス提供関係を順序立てて反映する方法である。

1. **配賦の順序を決定する**
   - 他の間接部門に対するサービス提供が大きい部門から順に配賦する
   - 順序の判定基準: 他部門へのサービス提供額（または提供量）が大きい部門を先にする
   - 一度配賦が完了した部門には、後続の配賦からコストを戻さない（一方向の配賦）
   - 例: IT部門（全部門にサービス提供）→ 総務部門（オフィス関連）→ 人事部門（人事サービス）→ 事業部門

2. **各段階で配賦レートを算出し配賦する**
   - 第1段階（例: IT部門）: IT部門のコストを、IT以外の全部門（総務、人事、事業部門）に配賦する
   - 第2段階（例: 総務部門）: 総務部門の自部門コスト＋IT部門から受け入れたコストの合計を、総務以外の残り部門（人事、事業部門）に配賦する
   - 第3段階（例: 人事部門）: 人事部門の自部門コスト＋前段階から受け入れたコストの合計を、事業部門のみに配賦する
   - 各段階で配賦元の残高がゼロになることを確認する

3. **配賦結果の確認**
   - 全段階の配賦完了後、全間接部門の残高がゼロであることを確認する
   - 事業部門が受け入れた配賦額の合計が、配賦前の間接部門コスト総額と一致することを確認する

> **判断の分岐点**: 間接部門間の相互サービスが双方向で大きい場合（例: IT部門が人事部門にシステムを提供し、人事部門がIT部門に採用・労務サービスを提供）、段階配賦では順序によって結果が変わる。この場合、相互配賦法（連立方程式法）の採用を検討する。ただし相互配賦法は計算が複雑になるため、双方向サービスの金額が全体の5%未満であれば段階配賦で十分な精度が得られる。

> **よくある落とし穴**: 段階配賦の順序を「慣例で」決めており、事業構造の変化を反映していないケース。組織再編やアウトソーシングにより間接部門のサービス提供関係が変わった場合、配賦順序の見直しが必要。年度予算編成時に順序の妥当性を再検証する。

### 4. 共通費の按分

**実行条件**: 毎月次。全社共通費（経営管理費、本社管理費等）の配分が必要な場合に実施する。

共通費は特定の受益者を明確に特定できないコストであり、配賦基準の選定に恣意性が入りやすい。事業部門の納得感を確保するためのコミュニケーションが特に重要なステップである。

1. **共通費の範囲を定義する**
   - 全社共通費として按分する対象を明確にする:
     - 経営層人件費（CEO、CFO等の役員報酬）
     - 本社管理部門のうち、段階配賦で処理しきれないもの
     - 全社横断プロジェクトのコスト
     - 本社ビルの共用部分コスト
   - 共通費に含める範囲は年度予算編成時に確定し、年度中は原則変更しない

2. **按分基準を選定する**
   - 共通費の按分基準は、「受益の実態」を直接測定することが困難なため、間接的な代理指標を使用する:

   | 按分基準 | 適する場面 | 注意点 |
   |---------|-----------|-------|
   | 売上高比率 | 売上規模に応じた経営資源の消費が想定される場合 | 利益率の低い事業部門に過大な負担がかかる |
   | 直接費比率 | コスト構造が類似した事業部門間の按分 | 資本集約的な部門と労働集約的な部門の比較が歪む |
   | 人員数比率 | 人的サービスが中心の共通費 | パートタイム・外注をどう換算するかの定義が必要 |
   | 均等按分 | 受益の差が小さい場合、または測定が困難な場合 | 規模の大きい部門に有利になる |
   | 複合基準 | 上記の単一基準では不公平感が強い場合 | 計算が複雑化し、説明が難しくなる |

   - 按分基準の選定は「完璧な正解」がない領域であり、事業部門の納得感と運用の簡潔さを重視する

3. **按分額を計算する**
   - 各配賦先の按分額 = 共通費総額 × 当該配賦先の按分基準比率
   - 按分比率の合計が100%になることを確認する
   - 全配賦先の按分額合計が共通費総額と一致することを確認する

4. **按分結果の妥当性確認と事業部門とのコミュニケーション**
   - 各事業部門の共通費按分額が、売上高対比で合理的な水準にあるか確認する
   - 前月からの按分額の変動が大きい部門がある場合、按分基準データの変動を原因として特定する
   - **事業部門への説明**: 配賦結果を事業部門に通知する際は、単に金額を伝えるだけでなく、以下を含める:
     - 按分基準と当該部門の比率
     - 前月からの変動とその理由
     - 配賦額が部門P&Lの段階利益に与える影響
   - **異議への対応ルール**: 事業部門から按分結果に対する異議が出た場合の対応プロセスを明確にしておく:
     - 異議申立期間: 配賦結果の通知から3営業日以内
     - 調整プロセス: FP&Aマネージャーが異議の内容を確認し、按分基準データの誤り等が認められる場合は修正する
     - 最終判断者: 按分基準自体に対する異議はCFOまたは経営会議が判断する
   - **公式レビュー前のpre-alignment**: 配賦結果が大きく変動した部門には、経営レビュー会議の前に個別説明を行い、サプライズを防ぐ

> **よくある落とし穴**: 共通費の按分が「コスト配分の公平性」を追求するあまり、按分基準を毎月変えたり、複雑な複合基準を導入したりして、配賦結果の予測可能性と比較可能性を損なうケース。按分基準は年度中固定とし、大きな構造変化があった場合のみ年度途中で見直す。

> **判断の分岐点**: 管理会計上、共通費を事業部門に按分しない選択もある。貢献利益階層の「直接貢献利益」までを事業部門の評価指標とし、共通費控除後の営業利益は全社レベルでのみ管理する方式。事業部門のコントロール不能なコストで業績評価が歪むことを避けるメリットがあるが、フルコストベースの収益性が見えなくなるデメリットもある。自社の経営管理思想に合わせて選択する。

> **業種別の注意点**:
> - **製造業**: 本社管理費の工場別按分は、生産量・出荷額・従業員数のいずれを使うかで工場間の収益性序列が変わりうる。工場長の業績評価に影響するため、基準の選定は経営層の合意を得る
> - **SaaS/テクノロジー**: プラットフォーム共通費（共通インフラ、共通機能の開発費）を製品別に按分する場合、利用量ベース（APIコール数、ストレージ量等）が最も合理的だが、計測の仕組みが必要
> - **持株会社・グループ経営**: グループ本社費の事業会社への按分は、経営管理契約や税務上のルール（移転価格税制）との整合性も考慮する

### 5. 配賦結果の検証と引き渡し

**実行条件**: ステップ2-4の配賦計算が完了した後に実施する。

1. **配賦の完全性を確認する**
   - 全ての間接費コストプールの残高がゼロになっていることを確認する（未配賦残高がないこと）
   - 全ての事業部門が配賦額を受け入れていることを確認する（配賦先の漏れがないこと）
   - 配賦前の間接費総額 = 配賦後の事業部門受入額合計 であることを確認する

2. **配賦後の部門別PLの妥当性を確認する**
   - 各事業部門の配賦額が、予算と大きく乖離していないか確認する
   - 乖離がある場合、原因を切り分ける:
     - 配賦元の間接費が予算と異なる（コストプール金額の差異）
     - 配賦基準の構成比が予算と異なる（配賦基準データの変動）
     - 配賦ルールが変更された（ルール変更による影響）
   - 配賦額の変動原因は、事業部門にとってコントロール不能な要因であるため、業績評価時に区別して報告する

3. **配賦差異の予実分析上の扱いを明確にする**
   - 配賦差異は以下の2つの構成要素に分解される:
     - **(1) コストプール自体の変動**: 配賦元部門のコストが予算と異なる（例: IT部門の支出増）。これは配賦元部門の支出差異として分析する
     - **(2) 配賦基準の変動**: 受益部門の活動量や構成比が予算と異なる（例: ある事業部門の人員増により配賦比率が変動）。これは配賦基準データの変化として説明する
   - 予実差異分析との接続: 事業部門の差異レポートでは、配賦差異を**「管理不能差異」として区分表示**し、当該部門のコントロール可能なコスト差異と分離する。これにより、部門の実行力評価が配賦ルールの影響で歪むことを防ぐ
   - 配賦差異が大きい場合の対応: 差異の原因は配賦元部門の支出差異として分析し、配賦を受ける側の事業部門には原因帰属しない。配賦元部門に対して支出差異の説明を求め、配賦先部門の業績評価からは除外する

4. **前月比較・予算比較の実施**
   - 配賦レートの前月比較: レートが大きく変動していないか確認する
   - 配賦額の予算比較: 各事業部門の受入額が予算の範囲内か確認する
   - 異常がある場合は、後続の差異分析で原因を特定する

5. **配賦結果の引き渡しと関係者への通知**
   - 配賦後の部門別PLを管理会計実績の確定プロセスに引き渡す
   - 配賦計算の根拠資料（配賦基準データ、配賦レート、配賦額明細）を制度会計との差異照合の入力として引き渡す
   - 配賦ルールの変更があった場合は、変更内容と前年同期比較への影響を記録し、経営レポートの注記事項として伝達する
   - **事業部門への通知**: 各事業部門の予算責任者に当月の配賦結果を通知する。通知には配賦額、前月比変動、予算比変動を含め、変動の大きい部門には個別にフォローする

> **よくある落とし穴**: 配賦結果の検証を形式的なチェック（合計一致の確認）だけで済ませ、配賦後の部門別PLの経営的な妥当性を確認しないケース。配賦後に特定事業部門の営業利益率が大幅にマイナスに転じた場合、配賦ルール自体の問題か事業の問題かを判別することが重要。

> **フィードバックループの設計**: 配賦ルールの妥当性を継続的に検証するため、以下のサイクルを回す:
> 1. 月次の配賦実行と結果の記録
> 2. 四半期ごとの配賦基準の妥当性レビュー（配賦基準が受益の実態を反映しているか、事業部門からのフィードバックを含めて確認）
> 3. 年度の振り返り（配賦ルール全体の見直し、翌年度予算への反映）
> 4. 事業部門からの異議・要望の蓄積と、配賦設計への反映
