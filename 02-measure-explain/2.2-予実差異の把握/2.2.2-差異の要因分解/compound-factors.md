# 複合要因の識別と分離

## 目的

- **誰のために**: CFO、FP&Aマネージャー、事業部門長
- **何を解決するか**: PVM分解、コスト構造分解、為替影響分離、セグメント軸分解の各プロセスは、それぞれ単独では正しい結果を出すが、複数の要因が同時に変動した場合の交互作用効果（残差）、好調と不調が打ち消し合う相殺差異、分解順序によって結果が変わる順序依存性といった問題が潜在する。これらを放置すると、差異分析の精度が損なわれ、経営判断に「見えない歪み」が混入する
- **届ける価値**: 各分解フレームワークの結果に対する品質管理プロセスとして機能し、交互作用効果の明示的な配分、隠れた相殺差異の検出、分解順序の統一ルール確立を通じて、差異分析全体の信頼性と一貫性を担保する

## スコープ

- **対象**: 予実差異の要因分解プロセスの結果に対する品質管理。PVM分解、コスト構造分解、為替影響分離、セグメント軸分解の各出力を入力とする
- **前提**: 各分解フレームワークによる一次分解が完了していることが前提となる。比較軸の選定と差異算出、および重要性の判定と深掘り対象の絞り込みで重要性ありと判定された差異が対象
- **後続**: 品質管理済みの分解結果は、ドライバの分類、性質の判別、および通期着地への影響評価に引き渡される
- **対象部門**: FP&A部門（実行主体）、データアナリティクスチーム（検証支援）、事業部門（構造的背景の確認先）

## 責任者

| 役割 | 担当 |
|------|------|
| 複合要因の識別・分離の実行 | FP&Aアナリスト |
| 配分ルール・分解順序の設計・承認 | FP&Aマネージャー |
| 分解結果の整合性検証 | FP&Aシニアアナリスト |
| 事業構造・取引背景の提供 | 事業部門の予算責任者 |

## 手順

**用語の定義**:
- **交互作用効果（Interaction Effect）**: 2つ以上の要因（例: 価格と数量）が同時に変動した場合に生じる残差項。個別要因の差異の合計と総差異の差額として現れる
- **相殺差異（Offsetting Variance）**: 異なるセグメント・科目・要因間で正の差異と負の差異が打ち消し合い、合算すると差異が小さく見える状態。構造的な問題が隠蔽されるリスクがある
- **分解順序依存性（Decomposition Order Dependency）**: 多要因の差異を逐次分解する際に、最初に固定する要因によって各要因への差異配分結果が変わる性質。PVM（Price→Volume→Mix）、PMV、MVPなどの順序で結果が異なる

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 事前準備 | 1. 分解順序の標準ルール策定と維持 | 初回策定時または年度方針変更時。月次分析時は参照のみ |
| 品質検証 | 2. 交互作用効果の識別と配分 | 各分解フレームワークの結果が揃った時点で実施 |
| 品質検証 | 3. 相殺差異の検出と可視化 | ステップ2と順序不問で実施可能 |
| 品質検証 | 4. 分解順序の影響度検証 | PVM分解の結果に対して実施。交互作用が大きい場合に重点実施 |
| 結果統合 | 5. 品質管理済み分解結果の統合と引き渡し | ステップ2-4完了後 |

### 1. 分解順序の標準ルール策定と維持

**実行条件**: 初回ルール策定時、または年度の分析方針見直し時。月次の差異分析では既存のルールを参照する。

差異の多要因分解は、要因を固定する順序によって各要因への配分結果が変わる。組織内でルールが統一されていないと、部門間・期間間で比較不能な分析結果が生成される。

1. **分解順序のパターンを理解する**
   - PVM分解を例にとると、売上差異 = 価格効果 + 数量効果 + ミックス効果 + 交互作用効果 となるが、交互作用効果の配分先は分解順序で変わる
   - **Price-first（PVM順）**: 価格を最初に固定し、残りを数量→ミックスの順に分解する。価格差異に交互作用が含まれにくく、数量・ミックス差異に残差が乗る
   - **Volume-first（VPM順）**: 数量を最初に固定する。数量差異が「純粋な数量効果」に近くなるが、価格差異に残差が乗る
   - **残差独立表示**: 各要因を「予算基準の純粋効果」で算出し、交互作用効果を独立した項目として表示する

2. **自社の標準順序を決定する**
   - 決定の基準: 経営の関心が最も高い要因を最後に固定する（最後に固定した要因の差異に交互作用が含まれる）。または残差独立表示を採用する
   - 一般的な推奨: 価格決定力の高い業種ではVPM順（数量を先に固定し、価格差異を正確に把握）、コモディティ型事業ではPVM順（価格は市場決定のため先に固定し、数量・ミックスの管理に注力）

3. **標準ルールを文書化し維持する**
   - 対象: PVM分解の順序、コスト分解における固変分離の順序、為替分離のタイミング（分解前か分解後か）
   - 全ての分析レポートで同一ルールを適用し、期間比較の一貫性を確保する
   - ルール変更時は、過去期間への遡及適用の要否を判断し、変更影響を注記する

> **よくある落とし穴**: 「PVM順で統一」と決めたはずが、Excelテンプレートの計算式が実際にはVPM順になっているケース。ルールの策定だけでなく、計算ツールの実装がルールと一致しているかを定期的に検証する必要がある。

> **判断の分岐点**: 残差独立表示は理論的に最も正確だが、経営報告の受け手にとって「交互作用効果」という項目は直感的でない場合がある。報告の受け手が分解に慣れていない場合は、特定の順序に統一して交互作用を要因に含める方式の方がコミュニケーションコストが低い。ただし、交互作用効果が総差異の15%を超える場合は、どの方式であっても独立表示するか、少なくとも注記として付記する。

> **業種別の注意点**:
> - **製造業**: 標準原価制度がある場合、材料費の「価格差異→数量差異」の順が伝統的。標準原価カードとの整合性を維持する
> - **小売・流通業**: SKU数が多くミックス効果が大きい。ミックスを独立要因として明示する順序（P→V→M の3要因分解）が有効
> - **SaaS/テクノロジー**: ARR分解ではNew/Expansion/Churn/Contractionの構造が主流で、PVM的な順序問題は発生しにくい。ただしARPU×顧客数の分解では同様の順序問題が生じる

### 2. 交互作用効果の識別と配分

**実行条件**: PVM分解、コスト構造分解（レート×効率分解）の結果が出揃った時点で実施する。

2つ以上の要因が同時に変動した場合、個別要因の差異の合計は総差異と一致しない。この差額が交互作用効果であり、明示的に識別し配分ルールに従って処理する必要がある。

1. **交互作用効果の算出**
   - 2要因の場合（例: 価格Pと数量Q）:
     - 総差異 = P₁Q₁ − P₀Q₀
     - 価格の純粋効果 = (P₁ − P₀) × Q₀
     - 数量の純粋効果 = P₀ × (Q₁ − Q₀)
     - 交互作用効果 = (P₁ − P₀) × (Q₁ − Q₀)
     - 検算: 価格の純粋効果 + 数量の純粋効果 + 交互作用効果 = 総差異
   - 3要因以上の場合（例: 価格×数量×ミックス）: 2次の交互作用（2要因間）と3次の交互作用（3要因間）が発生する。要因数が増えるほど交互作用項が指数的に増加するため、実務上は主要な2要因間の交互作用に絞って識別する

2. **交互作用効果の重要性を判定する**
   - 交互作用効果の絶対額が総差異の5%未満: 実務上無視して差し支えない。いずれかの要因に含めて処理する
   - 5%以上15%未満: ステップ1で定めた標準ルールに従い、特定の要因に配分する。配分先を注記する
   - 15%以上: 独立項目として表示する。この水準の交互作用は「価格と数量が連動して大きく動いた」ことを意味し、そのメカニズム自体が重要な分析対象である

3. **配分方法を選択し実行する**
   - **最終要因吸収法**: ステップ1で定めた分解順序の最後の要因に交互作用を含める（実務上最も一般的）
   - **按分法**: 各要因の純粋効果の絶対額に比例して交互作用を配分する。按分計算: 要因Aへの配分 = 交互作用効果 × |要因Aの純粋効果| / (|要因Aの純粋効果| + |要因Bの純粋効果|)
   - **シャプレー値法**: ゲーム理論に基づき、全ての分解順序の平均を取ることで公平な配分を実現する。理論的に最も公正だが、計算が複雑で要因数が多い場合は実務負荷が高い
   - **独立表示法**: 配分せず「交互作用効果」として独立表示する

4. **配分結果の記録**
   - 交互作用効果の金額、採用した配分方法、配分先を記録する
   - 前期と異なる配分方法を使用した場合は、比較可能性への影響を注記する

> **よくある落とし穴**: 交互作用効果を「計算誤差」や「端数」として無視するケース。金額が小さい場合は問題ないが、価格改定と数量変動が同時に起きた月（値上げと需要減が同時発生するケースなど）では交互作用効果が大きくなり、無視すると価格効果と数量効果の両方が歪む。

> **判断の分岐点**: 按分法とシャプレー値法は理論的に優れるが、毎月の定例分析で計算する実務負荷を考慮する必要がある。交互作用が常に小さい（5%未満）事業環境であれば最終要因吸収法で十分であり、大きな交互作用が頻発する環境（例: 為替と現地通貨価格が連動する輸出企業）ではシャプレー値法や按分法の導入を検討する。

### 3. 相殺差異の検出と可視化

**実行条件**: セグメント軸分解の結果が揃った時点で実施する。ステップ2と順序不問で実施可能。

合算レベルでは小さく見える差異の中に、構造的に問題のある大きな差異が隠れている場合がある。ベテランのFP&Aアナリストが経験的に見抜く「嫌な小ささ」を体系化し、再現可能なプロセスとして定義する。

1. **相殺差異のスクリーニング**
   - 各セグメント（事業部門、製品群、地域、顧客セグメント等）の差異を個別に確認し、合算前の差異の絶対額合計（グロス差異）と合算後のネット差異を比較する
   - グロス差異 = Σ|各セグメントの差異|
   - 相殺度 = 1 − |ネット差異| / グロス差異
   - 相殺度が0.5以上（グロス差異の半分以上が相殺されている）の場合、相殺差異ありと判定する

2. **相殺パターンを分類する**

   | パターン | 具体例 | リスク |
   |---------|--------|--------|
   | セグメント間相殺 | 事業部Aの+50Mと事業部Bの-45Mが相殺し、全社差異+5M | 事業部Bの構造的不振が全社報告で埋没する |
   | 要因間相殺 | 価格効果+30Mと数量効果-28Mが相殺し、売上差異+2M | 値上げによる需要減という重要なダイナミクスが見えなくなる |
   | 期間内相殺 | 上期+40Mと下期-38Mが相殺し、通期差異+2M | 下期の急激な悪化トレンドが通期平均で薄められる |
   | 科目間相殺 | 売上+60Mと原価+55Mが相殺し、利益差異+5M | 売上増がほぼ全てコスト増に食われている構造問題が不可視になる |

3. **相殺差異の可視化**
   - ウォーターフォールチャート: ネット差異だけでなく、各セグメント・要因の差異を積み上げで表示し、正負の打ち消し構造を視覚化する
   - グロス差異の併記: 合算値の横にグロス差異を必ず併記する。例:「全社売上差異: +5M（グロス差異: 95M）」
   - ヒートマップ: セグメント×要因のマトリクスで差異の大きさを色分け表示し、相殺の構造を一覧化する

4. **「見かけの安定」の危険信号を定義する**
   - ネット差異が閾値以内だが、グロス差異が予算総額の一定割合（例: 10%）を超える場合、フラグを立てる
   - 前月と比較して、ネット差異は同水準だがグロス差異が拡大傾向にある場合、構造変化の兆候として警告する
   - 特定のセグメントが3ヶ月連続で同方向の差異を出している場合、一時的な変動ではなく構造的な問題の可能性がある

> **よくある落とし穴**: 経営会議の報告で「売上差異は+0.5%で軽微」と報告したが、実態は国内事業が-8%・海外事業が+9%で、国内事業の深刻な不振が海外の好調に隠されていたというケース。合算値だけで「問題なし」と判断することは、最も危険な分析エラーの一つである。

> **判断の分岐点**: 全てのセグメント分解に対して相殺差異検出を行うと分析量が膨大になる。実務上は、（1）経営会議で報告する主要KPIに対して必ず実施、（2）差異率が小さいのに事業環境が大きく変化しているとき優先実施、（3）新規事業・撤退事業がある期は必ず実施、の3つの優先ルールで対象を絞る。

> **業種別の注意点**:
> - **製造業**: 製品ラインが多い場合、個別製品の差異が激しく相殺されやすい。製品カテゴリ単位での中間集計レイヤーを設けて相殺を検出する
> - **小売・流通業**: 店舗間の相殺が典型的。既存店と新規店を分離した上で、既存店同士の相殺を検出する
> - **グローバル企業**: 通貨圏ごとの相殺が頻発する。為替影響分離後の現地通貨ベースで相殺を検出しないと、為替変動と事業パフォーマンスの相殺が混在する

### 4. 分解順序の影響度検証

**実行条件**: PVM分解の結果に対して実施する。特にステップ2で交互作用効果が総差異の10%以上であった場合に重点的に実施する。

ステップ1で標準ルールを定めていても、実際に順序を変えた場合の影響度を把握しておくことで、分析結果の頑健性を評価できる。

1. **代替順序での分解を実行する**
   - 標準順序（例: PVM）での分解結果に加え、少なくとも1つの代替順序（例: VPM）での分解結果を計算する
   - 各要因の差異額を標準順序と代替順序で比較する

2. **順序感応度を算出する**
   - 各要因について: 順序感応度 = |標準順序での差異額 − 代替順序での差異額| / |標準順序での差異額|
   - 順序感応度が20%を超える要因がある場合、分解結果の解釈に注意が必要であることを報告に付記する
   - 全ての順序で同じ方向（有利 or 不利）を示す要因は、順序に依存しない頑健な結論とみなせる

3. **頑健性の評価結果を記録する**
   - 各要因の差異について「順序に依存しない（頑健）」「順序により金額が変動するが方向は一定」「順序により方向が反転する（要注意）」の3段階で評価する
   - 方向が反転する要因がある場合、交互作用効果が支配的であることを意味する。当該要因の差異を単独で語ることは避け、関連する要因とセットで報告する

4. **報告への反映方法**
   - 頑健な結論のみを主要メッセージとして報告し、順序依存の大きい要因は補足情報として添付する
   - 「価格効果は+20Mから+35Mの範囲（分解順序により変動）」のようにレンジで報告することも有効

> **よくある落とし穴**: 順序感応度の検証を「面倒だから」と省略し、標準順序の結果だけを確定値として報告するケース。交互作用が大きい月に限っては、順序を変えると主要メッセージが変わる可能性がある。少なくとも交互作用効果が大きい場合は検証を省略してはならない。

> **判断の分岐点**: シャプレー値法（全順序の平均）を標準採用している場合、このステップは不要となる。シャプレー値法は「順序の影響を自動的に平均化する」ため、順序依存性の問題そのものが解消される。ただし計算コストとのトレードオフを考慮する。

### 5. 品質管理済み分解結果の統合と引き渡し

**実行条件**: ステップ2-4の品質検証が完了した後に実施する。

1. **品質管理チェックリストの完了確認**
   - 以下の項目を確認し、結果を記録する:

   | チェック項目 | 確認内容 | 判定 |
   |-------------|---------|------|
   | 完全性 | 全要因の差異合計が総差異と一致するか | 一致 / 不一致（差額: ___） |
   | 交互作用の処理 | 交互作用効果が識別され、配分ルールに従い処理されたか | 処理済 / 該当なし |
   | 相殺差異 | 主要KPIについて相殺差異の検出を実施したか | 実施済 / 該当なし |
   | 順序頑健性 | 交互作用が大きい場合に順序感応度を検証したか | 検証済 / 該当なし / 交互作用小 |
   | 一貫性 | 前月・前年同月と同一の分解順序・配分ルールが適用されているか | 一致 / 変更あり（内容: ___） |

2. **分解結果サマリーを作成する**
   - 各分解フレームワーク（PVM、コスト構造、為替、セグメント）の結果を統合し、要因別の差異額を一覧化する
   - 交互作用効果の処理内容と配分先を明記する
   - 相殺差異が検出された場合、ネット差異とグロス差異の両方を記載する
   - 順序感応度が高い要因には注記を付す

3. **ドライバの分類・性質の判別・通期着地への影響評価への引き渡し情報**
   - 品質管理済みの要因別差異額（交互作用配分済み）
   - 相殺差異マップ（どのセグメント間・要因間で相殺が発生しているか）
   - 順序頑健性の評価結果（各要因の結論の信頼度）
   - 「表面上は小さいが構造的に注意が必要な差異」のリスト（相殺差異検出で発見されたもの）
   - 前月からの変化点: 交互作用の大きさ、相殺パターン、グロス差異のトレンド

> **判断の分岐点**: 品質管理の深度は分析サイクルによって調整する。月次の定例分析では、交互作用の識別（ステップ2）と主要KPIの相殺差異検出（ステップ3）を必須とし、順序感応度検証（ステップ4）は交互作用が大きい場合のみ実施する。四半期レビューや年度振り返りでは全ステップをフルで実施する。
