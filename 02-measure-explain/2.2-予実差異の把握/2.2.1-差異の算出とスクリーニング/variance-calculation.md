# 比較軸の選定と差異算出

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー
- **何を解決するか**: 管理会計実績が確定した後、差異分析の起点となる「何と何を比較するか」の選定と「差異の正確な算出」が曖昧だと、後続の分析全体が歪む。比較軸の選定を誤れば差異の意味を読み違え、算出の符号規約や比較ベースが不統一であれば有利・不利の判定を逆転させる。これらの基盤工程を標準化しなければ、分析の再現性と信頼性を担保できない
- **届ける価値**: 分析目的に応じた比較軸を体系的に選定し、P&L全科目の差異を正確かつ網羅的に算出することで、後続の重要性判定プロセスに「判定可能な状態の差異データ一式」を引き渡す

## スコープ

- **対象**: 予実差異の把握プロセスの前半工程。比較軸（BvA、FvA、前年同期比等）の選定、比較データの整合性確認、P&L全科目の差異算出までを行う
- **前提**: 管理会計の締め支援が完了し、実績データが確定していること。具体的には、[実績確定の承認と引き渡し](../../2.1-管理会計の締め支援/2.1.3-管理会計実績の確定/actuals-approval-handoff.md) のステップ3でデータを受領した時点で開始する。予算データおよび最新予測（フォーキャスト）データがアクセス可能であること
- **後続**: 算出された差異データは、重要性の判定と深掘り対象の絞り込みに引き渡される
- **対象部門**: FP&A部門（実行主体）、経理部門（実績データの提供元）

## 責任者

| 役割 | 担当 |
|------|------|
| 比較軸の選定・差異算出の実行 | FP&Aアナリスト |
| 比較軸・算出ルールの設計・承認 | FP&Aマネージャー |
| 実績データの提供・確定連絡 | 経理部門 |

## 手順

**用語の定義**:
- **BvA（Budget vs Actual）**: 予算対実績差異。年初に承認された予算と実績の比較。業績評価・コミットメントの達成度を測る基本軸
- **FvA（Forecast vs Actual）**: 予測対実績差異。直近のフォーキャスト（最新見通し）と実績の比較。予測精度と直近の変調の検出に使う
- **PY vs A（Prior Year vs Actual）**: 前年同期対実績差異。前年同期の実績と当期実績の比較。中長期のトレンドや構造変化の検出に使う
- **有利差異**: 利益を押し上げる方向の差異。売上は「実績 > 基準」、費用は「実績 < 基準」
- **不利差異**: 利益を押し下げる方向の差異。有利差異の逆
- **オーガニックベース**: 買収・売却などの事業範囲変動を除外した既存事業ベースの比較

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 軸の選定 | 1. 分析目的に応じた比較軸の選定 | 月次締め完了後の毎サイクル |
| データ整備 | 2. 比較データの整合性確認と調整 | ステップ1完了後 |
| 差異算出 | 3. P&L科目別の金額差異・比率差異の算出 | ステップ2完了後 |
| 検証 | 4. 差異データの検証とフォーマット統一 | ステップ3完了後 |

### 1. 分析目的に応じた比較軸の選定

**実行条件**: 月次の管理会計締め完了後、毎サイクルで実施する。

差異分析の第一歩は「何と何を比較するか」を明確にすることである。比較軸によって差異が示す意味が根本的に異なるため、分析目的に応じた軸の選定が不可欠である。

1. **比較軸の特性を理解した上で選定する**

   | 比較軸 | 測定するもの | 主な分析目的 | 主な使用場面 |
   |--------|------------|------------|------------|
   | BvA（予算vs実績） | 年度計画に対する達成度 | コミットメントの遵守状況、業績評価 | 月次・四半期の業績レビュー、取締役会報告 |
   | FvA（予測vs実績） | 直近の見通し精度 | 予測精度の検証、直近の変調検出 | FP&A内部レビュー、予測プロセスの改善 |
   | PY vs A（前年同期vs実績） | 前年からの変化 | 成長・後退トレンド、構造変化の識別 | 投資家向け開示、中期計画の進捗確認 |
   | BvF（予算vs予測） | 年初計画からの見通し変化 | フォーキャスト修正の妥当性検証 | 予算責任者との合意形成 |

2. **通常サイクルでの使い分けを判断する**
   - 月次の標準セット: **BvA を主軸、FvA を補助軸** とする。BvA で「計画に対する位置」を測り、FvA で「直近の見通しの精度」を検証する
   - PY vs A の追加条件: 季節性の高い事業、投資家コミュニケーションが控えている場面、中期計画の進捗確認時
   - BvF の追加条件: 四半期ごとの予測見直し時、予算からの乖離が大きくなった場合の原因切り分け

3. **主軸の切り替えが必要な局面を見極める**
   - BvA からFvA への切り替え: 年度途中で予算の前提が大きく崩れた場合（M&A、事業売却、大幅な為替変動、パンデミック等の外部ショック）。予算が実質的に陳腐化しているときは、FvA を主軸に切り替え、BvA は参考値とする
   - 切り替えの判断権限: FP&Aマネージャーが起案し、CFO が承認する。切り替え時点と理由を記録する
   - 切り替え後も BvA の算出は継続する（年度末の業績評価で必要となるため）

> **判断の分岐点**: BvA と FvA で差異の方向が異なる場合の読み方。「BvA は大幅未達だが FvA はほぼオンライン」は、年初予算の前提が外れたが直近の見通しは正確だったことを意味する。逆に「BvA はオンラインだが FvA が大きく外れている」場合、直近に急変動が発生している。両軸を並べることで差異の性質（構造的 vs 突発的）を初期段階で切り分けられる。この初期判断が、後続の重要性判定で「どの差異を優先するか」の質を左右する。

> **業種別の注意点**:
> - **SaaS**: MRR/ARR ベースの比較を財務会計上の売上比較と並行して行う。契約ベースと収益認識ベースのタイミング差により、BvA の意味合いが変わる
> - **建設・プロジェクト型**: 進行基準の適用により月次実績が工事進捗率に依存する。予算との比較は進捗率ベースで調整しないと差異の意味を見誤る

### 2. 比較データの整合性確認と調整

**実行条件**: ステップ1で比較軸が選定された後に実施する。

比較軸が決まっても、実績データと比較基準データの前提が異なっていれば、算出される差異は無意味になる。「比較可能な状態」を確保するための前処理がこのステップである。

1. **勘定科目体系の一致を確認する**
   - 予算データと実績データで勘定科目コード・科目名称が一致しているかを確認する
   - 不一致が発生する典型的な契機: 組織再編、科目統廃合、新規事業の開始、会計システムの移行
   - 不一致がある場合は、マッピングテーブルを作成して対応関係を定義する。マッピングは FP&Aマネージャーが承認し、当月の差異算出が完了するまで変更しない

2. **フォーキャストのバージョンを特定する**
   - 月次ローリング予測の場合、「どの時点のフォーキャストと比較するか」を明確にする
   - 推奨: 当月実績との比較には「前月末時点の最新フォーキャスト」を使用する。これにより「1か月前の見通しがどれだけ正確だったか」を測定できる
   - 四半期レビューでは、四半期初時点のフォーキャストとの比較を追加し、より長い視野での予測精度を検証する
   - バージョンの選択を記録し、過去のサイクルと比較可能にする

3. **前年同期データの遡及修正を反映する**
   - 前年同期データに遡及修正（会計基準変更、リステート、過年度修正）がある場合は、修正後データを使用する
   - 修正前データとの差異を注記し、前年同期比の変動が「事業の変化」か「計上基準の変化」かを区別できるようにする

4. **為替レートの前提を確認する**
   - 予算レート、予測レート、前年実績レートのいずれが使用されているかを確認する
   - BvA: 予算レートと実績レートの差異が為替影響として混在する。為替影響の分離が必要な場合は、恒常為替レートベースの差異を別途算出する
   - PY vs A: 前年実績レートとの差異には、事業の実質的変化と為替変動が混在する点に留意する

5. **比較ベースの調整が必要なケースを処理する**
   - **営業日数の差異**: 月の営業日数が比較基準と異なる場合、日数調整後の比較を並行して作成する。特に日次売上型ビジネス（小売、飲食、物流等）では必須
   - **事業範囲の変動**: 当期に買収・売却があった場合、オーガニックベース（既存事業のみ）とインオーガニック込みの両方で差異を算出する。投資家向け開示ではオーガニック成長率が重視される
   - **会計方針の変更**: 収益認識基準の変更、リース会計の変更など、比較可能性に影響する変更がある場合は、影響額を定量化して注記する

> **よくある落とし穴**: フォーキャストのバージョン管理が不十分で、「どのフォーキャストと比較したか」が再現できないケース。月末のフォーキャスト確定値をスナップショットとして保存し、バージョン番号（または日付）を付与して管理する。過去のフォーキャストを上書きしてしまうと、予測精度の振り返りが不可能になる。

> **業種別の注意点**:
> - **小売・飲食**: 営業日数・天候・曜日配列の影響が大きいため、日数調整は必須。PY vs A は曜日配列の影響（祝日の曜日ずれ等）も考慮する
> - **製造業**: 生産カレンダーと会計カレンダーのずれに注意。4-4-5 カレンダーを使用している場合、月の区切りが暦月と異なる

### 3. P&L科目別の金額差異・比率差異の算出

**実行条件**: ステップ2で比較データの整合性が確認された後に実施する。

選定した比較軸に基づき、P&L の全科目について差異を網羅的に算出する。この段階では重要性の判定を行わず、事実としての差異を正確に計算することに徹する。

1. **符号規約を確認・統一する**
   - 有利差異（利益にプラス）を正、不利差異（利益にマイナス）を負とする
   - 売上科目: 実績 > 比較基準 → 正（有利）
   - 費用科目: 実績 < 比較基準 → 正（有利）、実績 > 比較基準 → 負（不利）
   - 経理システムの費用の符号（通常は正の値で記録）と管理会計レポートの符号（売上正・費用負の場合あり）が異なるケースが多い。差異算出の冒頭で符号規約を明示的にテンプレートに記載する

2. **金額差異を算出する**
   - 計算: 金額差異 = 実績 − 比較基準（予算 / 予測 / 前年同期）
   - P&L の全科目について例外なく算出する: 売上高、売上原価、売上総利益、販管費の各内訳科目、営業利益、営業外損益、経常利益、特別損益、税引前利益
   - 単月差異と YTD（年度累計）差異の両方を算出する

3. **比率差異（差異率）を算出する**
   - 計算: 差異率 = 金額差異 / 比較基準 x 100（%）
   - 比較基準がゼロまたは極めて小さい場合（目安: 金額差異の1/100以下）は差異率を「N/A」とし、金額差異のみで後続の判定に進む
   - 比率差異は、金額規模の異なる科目を横並びで比較する際に有用。大企業の数十億円の売上差異と数百万円の雑費の差異を、比率で相対的に評価できる

4. **小計・利益段階の差異を算出し、整合性を検証する**
   - 売上総利益差異 = 売上高差異 − 売上原価差異（符号規約に注意）
   - 営業利益差異 = 売上総利益差異 − 販管費差異
   - 個別科目の差異を合算した結果が利益段階の差異と一致するかを検証する
   - 不一致が発生した場合、データの欠落、科目の分類ミス、または端数処理の差異が原因。不一致が有意な金額の場合はデータの再取得を経理部門に依頼する

5. **単月と YTD の両軸で差異を整理する**
   - 単月差異: 直近月に何が起きたかを捕捉する。変調の検出に適する
   - YTD差異: 年度計画に対する進捗を把握する。年度目標の達成見通し判断に適する
   - 単月で大きな差異が出ても YTD では閾値以下のケース（過去月で相殺されている）、逆に単月は小さいが YTD でジリジリと累積しているケース、のいずれも見逃さないために両軸を並列で算出する

> **よくある落とし穴**: 費用科目の符号規約が統一されていない状態で差異を算出すると、有利・不利の判定が逆転する。特に複数の担当者が分担して差異を算出する場合、テンプレートに符号規約を明記し、算出後にサンプルチェック（売上が予算超過なら正、費用が予算超過なら負になっているか）を行う。

> **判断の分岐点**: 差異の算出を単月ベースのみで行うか、YTD を含めるかは分析リソースとの兼ね合いではなく、必須事項として両方を算出すべきである。単月とYTDで異なるシグナルが出ることは珍しくなく、片方だけでは差異の全体像を把握できない。

---

### 4. 差異データの検証とフォーマット統一

**実行条件**: ステップ3で差異算出が完了した後に実施する。

算出した差異データを後続プロセスに引き渡す前に、データの正確性を検証し、表示フォーマットを統一する。

1. **算出結果のクロスチェックを行う**
   - 利益段階の差異と、その構成科目の差異合計が一致するかを全段階で検証する
   - 複数の比較軸（BvA、FvA）で算出した場合、実績値が共通であることを確認する（基本的な不整合の検出）
   - 前月の差異データと当月の差異データを並べ、単月差異の変動が YTD差異の変動と整合しているかを確認する

2. **差異の表示フォーマットを統一する**
   - 科目ごとに「実績」「比較基準」「金額差異」「差異率」の4列を並べた一覧表を作成する
   - 複数の比較軸を使用する場合は、BvA と FvA を同一シートに並列配置し、両軸の差異を一覧で把握できるようにする
   - 単月とYTDを明確に区分し、混在しないようにする（推奨: 上段に単月、下段にYTD、または左右に並列）
   - 有利差異・不利差異の色分け（有利: 黒、不利: 赤等）を統一する

3. **調整事項を注記する**
   - ステップ2で実施した比較ベースの調整（営業日数調整、オーガニックベース調整、会計方針変更の影響等）がある場合は、該当科目に注記を付す
   - フォーキャストのバージョン、為替レートの前提を差異一覧表のヘッダーに記載する

4. **差異データを重要性判定プロセスに引き渡す**
   - 算出済みの差異データ一式（全科目 x 全比較軸 x 単月・YTD）を、重要性の判定と深掘り対象の絞り込みプロセスに引き渡す
   - 引き渡し時点で、符号規約・フォーマット・注記が揃っていることを確認する

> **よくある落とし穴**: 差異一覧表を毎月ゼロから作り直すケース。前月のテンプレートを引き継ぎ、実績と比較基準の数値のみを更新する方式にすることで、フォーマットの統一性と作業効率を両立する。ただし、科目の追加・削除があった場合はテンプレート自体を更新する。
