# 重要性の判定と深掘り対象の絞り込み

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー
- **何を解決するか**: 全科目の差異を網羅的に算出しても、すべてを等しく深掘りすることは現実的ではない。一方で、金額が大きい差異だけに着目すると、トレンド性のある小さな差異や経営の関心事項に直結する差異を見落とす。深掘りすべき差異とそうでない差異を体系的に選別する基準がなければ、分析リソースの配分が属人的になり、重要な論点が後手に回る
- **届ける価値**: 定量的な閾値と定性的なフラグの組み合わせによる多面的スクリーニングで重要差異を選別し、優先度と推奨分解手法を付与した「深掘り対象リスト」を、後続の要因分解プロセスに漏れなく引き渡す

## スコープ

- **対象**: 予実差異の把握プロセスの後半工程。算出済みの差異データに対して、金額閾値・比率閾値・定性的フラグによる重要性判定を行い、深掘り対象リストを確定するまでを行う
- **前提**: 比較軸の選定と差異算出が完了し、P&L全科目の差異データ（金額差異・差異率、単月・YTD）が整備されていること
- **後続**: 確定した深掘り対象リストは、差異の要因分解（PVM分解、コスト構造分解、為替影響の分離、セグメント軸による分解）に引き渡される。さらにその結果がドライバの分類、性質の判別、および通期着地への影響評価に接続する
- **対象部門**: FP&A部門（実行主体）、経営企画部門（経営アジェンダの共有元）、事業部門長（注目テーマの提供元）

## 責任者

| 役割 | 担当 |
|------|------|
| 閾値判定・スクリーニングの実行 | FP&Aアナリスト |
| 閾値・フラグ基準の設計・承認 | FP&Aマネージャー |
| 経営注目テーマ・定性情報の提供 | 経営企画部門 / 事業部門長 |
| 深掘り対象リストの最終承認 | FP&Aマネージャー |

## 手順

**用語の定義**:
- **重要性の閾値**: 差異が深掘り対象に該当するかを判定するための定量基準。金額基準・比率基準・複合基準の3種がある
- **定性的フラグ**: 閾値に達しなくても深掘り対象とすべき差異を拾い上げるための定性判断基準。ベテランの暗黙知を形式知化したもの
- **トレンドフラグ**: 複数月にわたり同方向に継続する差異を検出するフラグ
- **未是正フラグ**: 過去に指摘され是正アクションが未完了の差異に対するフラグ
- **経営注目テーマフラグ**: 経営陣が注視しているテーマに関連する科目を常時監視対象とするフラグ
- **深掘り対象リスト**: スクリーニングを通過した重要差異の一覧。後続の要因分解の入力となる

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 定量判定 | 1. 閾値体系の設計と運用 | 初回設計時または定期見直し時。月次分析時は既存基準を適用 |
| 定量判定 | 2. 金額・比率・複合閾値による判定 | 差異データ受領後の毎サイクル |
| 定性判定 | 3. 定性的フラグによる補完スクリーニング | ステップ2完了後 |
| 統合・確定 | 4. 深掘り対象リストの確定と引き渡し | ステップ2-3完了後 |

### 1. 閾値体系の設計と運用

**実行条件**: 閾値体系の新規設計時、または四半期ごとの定期見直し時。月次の差異分析では既存の閾値基準を参照する。

閾値は一律ではなく、科目の性質や企業規模に応じて段階的に設定する。閾値設計の巧拙が、スクリーニングの実効性を左右する。

1. **3種類の閾値を組み合わせて設計する**

   いずれか1つに該当すれば深掘り対象とする（OR条件）。

   | 基準種別 | 定義 | 捕捉する差異の特性 | 設定例（企業規模で調整） |
   |---------|------|------------------|----------------------|
   | 金額基準 | 差異の絶対額が一定額を超える | 利益インパクトが大きい差異 | 売上高1,000億円規模: 5,000万円、100億円規模: 500万円 |
   | 比率基準 | 差異率の絶対値が一定率を超える | 予算精度が低い科目・異常な変動 | 主要科目: ±5%、少額科目: ±10% |
   | 複合基準 | 金額と比率の両方がそれぞれの下限を超える | 一定の金額的影響があり、かつ通常の変動幅を超えている差異 | 金額 ≥ 1,000万円 かつ 比率 ≥ ±3% |

   - 金額基準のみでは、少額科目の大幅な逸脱を見逃す（100万円の科目が3倍になっても金額閾値を通過してしまう）
   - 比率基準のみでは、少額科目の微小な差異が大量にヒットしてノイズになる（10万円の科目の±20%は金額的には重要でない）
   - 複合基準は「金額的にも比率的にもある程度の逸脱がある」場合を捕捉する補完的な基準

2. **科目グループ別に閾値を調整する**

   | 科目グループ | 推奨する閾値の考え方 | 理由 |
   |-------------|-------------------|------|
   | 売上高・売上原価 | 金額基準を厳しめに設定。比率基準は ±3-5% | 利益インパクトが最大の科目群。小さな比率差異でも金額が大きくなる |
   | 人件費 | 金額基準に加え、人員数差異（FTE差異）も閾値判定に含める | 人件費は単価 x 人数の構造を持ち、FTE差異は組織運営上の重要シグナル |
   | 研究開発費 | 比率基準をやや緩めに設定（±10-15%） | プロジェクトの進捗タイミングで月次変動が大きいため、厳しすぎるとノイズが増える |
   | 減価償却費 | 金額・比率ともに厳しめに設定（小さな閾値） | 予測精度が高い科目であり、差異が出ること自体が異常（計上ミスや資産の予定外処分等） |
   | 一時的・非経常項目 | 予算にない項目が実績に計上された場合は金額にかかわらず自動的にフラグ | 新規発生の非経常項目は、金額が小さくても経営判断に影響する可能性がある |

3. **単月閾値と YTD閾値を別々に設定する**
   - 単月閾値: 直近月の変調を検出する目的。月次予算額に対する比率で設定する
   - YTD閾値: 年度累計の進捗を把握する目的。単月より金額の絶対額を大きく、比率はやや厳しく設定する（月次の変動が年間で平準化されるべきため）
   - 注意すべきパターン: 単月では閾値以下だが YTD では閾値を超えるケース。個々の月は小さな不利差異でも、累積すると年間で大きなインパクトになる「ジリ貧」パターンを検出できる

4. **閾値の見直しサイクルを定める**
   - 閾値は年度を通じて固定するのが原則。頻繁に変更すると、過去との比較可能性が失われる
   - 四半期ごとに、閾値の有効性をレビューする（ヒット率が高すぎないか、重要差異が漏れていないか）
   - 経営環境が大きく変動した場合（為替の急変、大型M&A等）は、FP&Aマネージャーの判断で臨時に閾値を引き下げることを認める。この場合、変更理由と適用期間を記録する

> **よくある落とし穴**: 閾値を設定したまま何年も見直さないケース。事業規模の成長、インフレ、事業ポートフォリオの変化により、かつて適切だった閾値が陳腐化する。年度予算の策定タイミングで閾値もあわせて見直す。

> **判断の分岐点**: 閾値を固定値で運用するか、各科目の予算額に対する比率で動的に設定するか。固定値は運用が簡単で透明性が高いが、科目間の金額規模差を反映しにくい。比率ベースは科目特性を反映できるが、予算額がゼロの科目や新規科目に適用できない。推奨は「主要科目は固定値、少額科目は比率ベース」のハイブリッド方式。

### 2. 金額・比率・複合閾値による判定

**実行条件**: 差異データを受領した毎サイクルで実施する。

ステップ1で設計した閾値体系を適用し、全科目の差異を機械的にスクリーニングする。

1. **全科目に対して閾値判定を実行する**
   - 各科目の金額差異を金額基準と照合する（単月・YTD それぞれ）
   - 各科目の差異率を比率基準と照合する（単月・YTD それぞれ）
   - 複合基準の両条件を同時に満たすかを確認する
   - いずれか1つでも該当すれば「閾値超過（深掘り対象候補）」とする

2. **利益段階レベルと科目レベルの両方でスクリーニングする**
   - 科目レベルのスクリーニング: 個別科目ごとに閾値判定を行う
   - 利益段階レベルのスクリーニング: 売上総利益、営業利益、経常利益の各段階でも閾値判定を行う
   - 相殺差異の検出: 売上が +5,000万円、売上原価が −4,800万円の場合、売上総利益差異はわずか+200万円で利益段階の閾値を通過するが、個別科目には大きな差異が存在する。科目レベルのスクリーニングを必ず併用することで相殺を見逃さない

3. **閾値判定の結果を記録する**
   - 各科目に「閾値超過（深掘り対象候補）」「閾値以下（スクリーニング通過）」のラベルを付与する
   - 閾値を超過した科目は、どの基準（金額/比率/複合）で超過したかを記録する
   - 超過基準の記録は、後続の要因分解で「なぜこの差異が選別されたか」を追跡するために必要

4. **閾値ギリギリの科目を識別する**
   - 閾値の80-100%の範囲にある科目を「ボーダーライン」として識別する
   - ボーダーライン科目は、ステップ3の定性的フラグで再評価する対象となる
   - 前月にボーダーラインだった科目が当月に閾値を超えた場合、トレンドの悪化を示唆するため優先度を引き上げる

> **よくある落とし穴**: 相殺差異の見落とし。利益段階の差異だけでスクリーニングすると、売上と費用が同方向に大きく動いている場合に差し引きの小さな差異しか見えない。「全体としては問題なさそうだが、中身が大きく入れ替わっている」という構造変化を検出するために、科目レベルのスクリーニングは必須である。

> **判断の分岐点**: 閾値判定の結果、深掘り対象候補がP&L科目数の30%を大幅に超える場合は、2つの原因を切り分ける必要がある。(1) 閾値が低すぎる: 閾値の引き上げを検討する。(2) 事業環境に大きな変動があった: 閾値は変えず、経営への早期アラートを優先し、要因分解の優先順位付けを厳格にする。

### 3. 定性的フラグによる補完スクリーニング

**実行条件**: ステップ2の閾値判定が完了した後に実施する。

定量的な閾値だけでは捕捉できない「重要だが金額的には小さい差異」を拾い上げるプロセスである。ベテランFP&A担当者が暗黙的に行っている「要注意」の判断を、可能な限り形式知化する。

1. **トレンドフラグ: 連続して同方向に動いている差異**
   - 3か月以上連続して同方向（有利 or 不利）に差異が出ている科目を抽出する
   - 個々の月の差異は閾値以下でも、トレンドが存在する場合は構造的変化の兆候である
   - 確認すべきパターン:
     - 差異の絶対額が月を追うごとに拡大している（加速トレンド）: 早期の介入が必要な可能性
     - 差異率が一定幅で推移している（定常的な乖離）: 予算の前提が外れている可能性
     - 差異の方向が前月と一致し、かつ前月より拡大（悪化トレンド）: 放置すると年度後半に大きな累積差異になるリスク

2. **未是正フラグ: 過去に指摘され、是正アクションが未完了の差異**
   - 前月以前の差異分析で指摘された事項のうち、是正アクションが完了していないものをリストアップする
   - 当月の差異が閾値以下であっても、未是正の案件に関連する科目は深掘り対象に追加する
   - アクション管理台帳（または差異分析の指摘事項リスト）との突合を行う
   - 未是正が3か月以上継続している案件は、アクションの実行可能性自体を再評価する

3. **経営注目テーマフラグ: 経営陣が注視しているテーマに関連する差異**
   - 経営会議やボードミーティングで議題となっているテーマ（例: 人件費の適正化、新規事業の投資効率、特定地域の収益性）に関連する科目を特定する
   - これらの科目は、閾値の如何にかかわらず毎月の深掘り対象とする
   - 経営アジェンダは四半期ごとに経営企画部門から共有を受け、スクリーニング基準に反映する
   - 経営注目テーマは「永続的」ではなく、経営の関心の変化に応じて更新する

4. **異常パターンフラグ: 経験則で「要注意」と判断するパターン**
   - **新規発生**: 前月まで差異ゼロだった科目に突如差異が発生した
   - **符号反転**: 差異の方向が前月と逆転した（前月有利→当月不利、またはその逆）
   - **季節パターン逸脱**: 通常のパターンから逸脱している（例: Q4に集中する費用がQ2に発生）
   - **実績ゼロ**: 予算があるのに実績が未計上（計上遅れ、費用の先送り、事業活動の停止の可能性）
   - **予算外科目**: 予算にない科目に実績が計上されている（新規の取引・契約、科目の誤分類の可能性）
   - これらのパターンは金額の大小にかかわらず「何かが変わった」シグナルであり、原因確認が必要

5. **フラグの結果を閾値判定と統合する**
   - ステップ2の「閾値超過」リストに、ステップ3の「フラグ対象」リストを追加する
   - 各差異に対し、トリガーとなった基準をタグ付けする（金額閾値/比率閾値/複合閾値/トレンド/未是正/経営注目/異常パターン）
   - 1つの差異に複数のトリガーが該当する場合は、すべてを記録する（後続の優先度判定に使用する）

> **よくある落とし穴**: 定性的フラグを形骸化させないこと。フラグの基準が更新されず、経営の関心が移った後も古いテーマのフラグが残り続けると、ノイズが増えて本来の機能を失う。四半期ごとにフラグ基準をレビューし、不要になったフラグを除去する。逆に、新たに重要になったテーマを速やかにフラグに追加する機動性も必要である。

> **業種別の注意点**:
> - **製造業**: 原材料費のトレンドフラグは、コモディティ市況との連動を確認する。市況連動であれば「構造的変化」ではなく「外部環境要因」として分類し、ヘッジ戦略の見直しにつなげる
> - **SaaS/テクノロジー**: 顧客獲得コスト（CAC）やチャーン関連指標は、経営注目テーマフラグとして常時監視対象に含めることが多い。ユニットエコノミクスの悪化は、P&Lに遅れて顕在化するため早期検出が重要
> - **金融業**: 引当金・評価損は規制当局の関心事項でもあるため、閾値に関わらず常に深掘り対象とする

### 4. 深掘り対象リストの確定と引き渡し

**実行条件**: ステップ2-3が完了した後に実施する。

1. **深掘り対象リストを作成する**
   - ステップ2の閾値判定とステップ3の定性的フラグの結果を統合し、深掘り対象の一覧を作成する
   - リストの各項目に以下の情報を付与する:

   | 項目 | 内容 |
   |------|------|
   | 科目名 | 差異が発生しているP&L科目 |
   | 比較軸 | BvA / FvA / PY vs A のいずれで検出されたか |
   | 金額差異 | 差異の金額（単月・YTD） |
   | 差異率 | 差異の比率（単月・YTD） |
   | トリガー基準 | 閾値超過（金額/比率/複合）、定性フラグ（トレンド/未是正/経営注目/異常パターン）のいずれか |
   | 推奨する分解手法 | PVM分解、コスト構造分解、為替影響の分離、セグメント軸による分解のいずれを適用すべきかの初期判断 |
   | 優先度 | 高 / 中 / 低 |

2. **優先度を付与する**
   - 高: 金額基準と比率基準の両方を超過、または経営注目テーマに直結、または複数のトリガーが重複
   - 中: いずれか一方の定量基準を超過、またはトレンドフラグに該当
   - 低: 定性フラグのみで検出、または閾値ギリギリの科目
   - 優先度は後続の要因分解の着手順序を決める。限られた分析リソースの中で高優先度から順に着手する

3. **推奨する分解手法を初期判断する**

   | 差異の性質 | 推奨する分解手法 |
   |-----------|----------------|
   | 売上高の差異 | 数量・価格・ミックスの分解（PVM分解） |
   | 売上原価・製造原価の差異 | コスト構造の分解（固変分解、レート x 効率分解） |
   | 海外取引に関連する差異 | 為替影響の分離（FX分解）を先行適用 |
   | 事業部門・製品間で傾向が異なる差異 | セグメント軸による分解 |
   | 上記が複合している差異 | 為替分離 → PVM or コスト分解 → セグメント軸の順で段階適用 |

   - 推奨手法はあくまで初期判断であり、要因分解の過程で変更される場合がある
   - 複数の分解手法が必要な場合は、適用順序も併記する

4. **深掘り対象数の妥当性を確認する**
   - 目安: 深掘り対象は P&L科目数の20-30%以内に絞る
   - 大幅に超える場合: 閾値が低すぎるか、事業環境に大きな変動があったかを切り分ける
   - 大幅に下回る場合: 閾値が高すぎて重要差異を見逃している可能性がある。定性フラグの適用漏れも確認する

5. **FP&Aマネージャーの確認を受ける**
   - 深掘り対象リストと優先度をFP&Aマネージャーにレビューしてもらう
   - マネージャーの判断で、リストへの追加・削除・優先度の変更を行う
   - 「閾値以下だがマネージャーの経験則で深掘りすべき」と判断された差異は、理由を記録した上でリストに追加する。この記録が閾値設計の改善とベテランの暗黙知の形式知化に貢献する

6. **差異サマリーシートを更新し、後続プロセスに引き渡す**
   - 深掘り対象リストを差異サマリーシートに転記し、後続プロセスの担当者がアクセスできる状態にする
   - 前月のサマリーシートとの差分を明示する: 新規追加、前月からの継続、前月で解消の3区分
   - 継続案件は、前月からの差異の推移（改善傾向か悪化傾向か）を併記する
   - 解消案件は、解消の理由（是正アクションの効果、一過性要因の消失、閾値以下への縮小等）を記録する

> **よくある落とし穴**: 深掘り対象が多すぎてすべてを分析しきれないまま月次サイクルが回るケース。分析に使える時間は限られている。対象が多すぎる場合は優先度「高」のみを当月の必須分析とし、「中」は時間が許す範囲で、「低」は翌月に繰り越すルールを設ける。繰り越しが3か月以上続く差異は、閾値の見直しか恒常的な分析リソースの確保を検討する。

> **判断の分岐点**: 深掘り対象リストの粒度について。科目単位でリスト化するか、科目 x セグメント（事業部門・地域等）の組み合わせでリスト化するか。科目レベルで閾値を超えていなくても、特定セグメントでは大きな差異が出ている可能性がある。理想的にはセグメント軸を含めたスクリーニングが望ましいが、データの粒度と分析リソースの制約を踏まえて判断する。多くの企業では、まず科目レベルでスクリーニングし、差異の要因分解の段階でセグメント軸を導入する二段階方式を採用している。
