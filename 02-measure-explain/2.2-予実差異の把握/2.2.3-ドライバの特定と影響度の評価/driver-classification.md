# ドライバの分類（実行要因、外部要因、計画要因）

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー
- **何を解決するか**: 要因分解によって差異の構成要素は明らかになるが、「その差異を引き起こした根本原因は何か」が分からなければ、是正アクションの方向性も責任の所在も定まらない。ドライバを「自社の実行に起因するもの」「外部環境の変化に起因するもの」「計画の前提誤りに起因するもの」に分類しなければ、実行の問題でないものに実行改善を求めたり、計画の精度向上につなげるべき学びを見逃す
- **届ける価値**: 差異の根本原因を構造的に分類し、原因の所在と対応の方向性を明確にすることで、後続の性質判別・影響度評価・アクション提言に一貫した判断基盤を提供する

## スコープ

- **対象**: 差異の要因分解（PVM分解、コスト構造分解、為替影響分離、セグメント軸分解、複合要因の識別と分離）の結果として得られた全ての差異項目に対する、ドライバの識別と3カテゴリへの分類
- **前提**: 差異の要因分解が完了しており、各差異項目に対してドライバ仮説と一過性/構造的の初期判断が付されていること
- **後続**: 分類結果は性質の判別（一過性/構造的、コントロール可否）および通期着地への影響評価に引き渡される
- **対象部門**: FP&A部門（実行主体）、事業部門（ドライバの確認・背景情報の提供）、経営企画部門（戦略的文脈の提供）

## 責任者

| 役割 | 担当 |
|------|------|
| ドライバの識別・分類の実行 | FP&Aアナリスト |
| 分類結果の検証・最終判断 | FP&Aマネージャー |
| 事業上の背景・コンテキストの提供 | 事業部門の予算責任者 |
| 分類に基づく対応方針の意思決定 | CFO / 事業部門長 |

## 手順

**用語の定義**:
- **ドライバ**: 差異を引き起こした根本原因。要因分解で得られた差異項目（価格差異、数量差異、レート差異等）のさらに上流にある、事業活動上の具体的な事象や意思決定を指す
- **実行要因**: 自社の活動・意思決定に起因するドライバ。営業活動、生産オペレーション、採用・組織運営、価格改定、マーケティング施策など、社内の行動が直接の原因であるもの
- **外部要因**: 自社の活動では直接コントロールできない外部環境の変化。市場需要、為替、原材料価格、競合動向、規制変更など
- **計画要因**: 予算・計画策定時の前提条件そのものの誤り。市場成長率の見積もり、季節性パターン、新製品売上の想定、コスト削減効果の想定など、計画時の仮定と実態の乖離

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| ドライバ識別 | 1. 差異項目からのドライバ仮説の導出 | 要因分解の結果が引き渡された全ての差異項目に対して実施 |
| 分類 | 2. 3カテゴリへの分類 | ステップ1完了後 |
| 検証 | 3. 分類の妥当性検証と記録 | ステップ2完了後 |

### 1. 差異項目からのドライバ仮説の導出

**実行条件**: 要因分解の結果が引き渡された全ての差異項目に対して実施する。前工程から初期的なドライバ仮説が付されている場合はそれを出発点とし、付されていない場合は本ステップで仮説を立てる。

要因分解で得られた差異項目（価格差異、数量差異、レート差異、効率差異等）は、あくまで「何がどう動いたか」の記述であり、「なぜ動いたか」の答えではない。このステップでは、差異の背後にある具体的な事象・意思決定を特定し、経営判断に使える粒度まで掘り下げる。

1. **要因分解の結果を一覧し、各差異項目に対して「なぜこの差異が発生したか」の仮説を立てる**
   - 仮説の導出には以下の情報源を活用する:
     - 前工程の引き渡し情報（ドライバ仮説、初期判断）
     - 事業部門へのヒアリング（営業活動、生産状況、市場動向等）
     - 外部データ（市場統計、為替レート推移、原材料価格指数等）
     - 社内の意思決定記録（価格改定、組織変更、投資決定等）

2. **仮説の粒度を経営判断に使えるレベルまで具体化する**
   - 不十分な粒度の例: 「売上が減った」「コストが増えた」
   - 適切な粒度の例: 「主力製品Aの北米向け出荷が前年比15%減。主要顧客X社の在庫調整が主因」「外注費が予算比8%増。Q2に発生した品質問題の手直し工数が原因」
   - 一つの差異項目に複数のドライバが関与している場合は、全てを列挙した上で影響度の大きい順に並べる

3. **仮説の裏付けを取る**
   - 事業部門への確認は必須。数値分析だけでは見えない文脈（顧客の意思決定の変化、現場のオペレーション変更等）を把握する
   - 裏付けが取れない仮説は「未確認」と明示し、確認のアクションと期限を記録する

> **よくある落とし穴**: ドライバの粒度が粗すぎるケース。「市場環境の悪化」「コスト増」といった抽象的な記述では、後続の性質判別や影響度評価が機能しない。ドライバは「誰が・いつ・何をした（何が起きた）結果、どの差異が発生したか」を説明できる具体性が必要である。

> **判断の分岐点**: 差異が小さい項目に対してどこまでドライバを掘り下げるか。重要性の閾値を超えていない差異項目については、前工程の初期仮説をそのまま採用し、詳細なヒアリングは省略してよい。ただし、金額は小さくても過去にない異質な差異（新しいパターンの出現）は掘り下げる価値がある。

---

### 2. 3カテゴリへの分類

**実行条件**: ステップ1でドライバ仮説が導出された全ての差異項目に対して実施する。

各ドライバを「実行要因」「外部要因」「計画要因」の3カテゴリに分類する。この分類は、対応の方向性（実行改善か、リスク管理か、計画プロセスの改善か）を決定する基盤となる。

1. **3カテゴリの判定基準を適用する**

   | カテゴリ | 定義 | 判定の問い | 例 |
   |---------|------|-----------|-----|
   | 実行要因 | 自社の活動・意思決定に起因するドライバ | 「自社が異なる行動を取っていれば、この差異は発生しなかったか？」 | 営業活動の強化/停滞、生産効率の改善/悪化、採用の前倒し/遅延、新製品の投入、価格改定の実施、マーケティング施策の効果/不発 |
   | 外部要因 | 自社の活動では直接コントロールできない外部環境の変化 | 「自社の行動に関わらず、この差異は発生したか？」 | 市場需要の変動、為替変動、原材料価格の変動、競合の価格戦略、規制変更、天候・災害 |
   | 計画要因 | 予算・計画策定時の前提条件そのものの誤り | 「実行は計画通りだったが、計画の前提が実態と乖離していたか？」 | 市場成長率の過大/過小見積もり、季節性パターンの見積もり誤差、新製品売上の過大想定、コスト削減施策の効果の過大想定、為替レート前提の乖離、トップサイド調整による乖離 |

2. **計画要因としてのトップサイド調整を識別する**
   - トップサイド調整とは、ボトムアップの予算積み上げに対して経営層が一律に加算または減算した調整を指す。この調整分は計画要因として明示的に識別する
   - 特にストレッチ目標として上乗せされた売上増分や、一律のコスト削減率（例: 全部門一律5%削減）が予算に織り込まれている場合、差異の一部はトップサイド調整に帰属する
   - トップサイド調整の存在を明示的に認識しないと、事業部門の実行力の問題と計画の無理の問題が混同され、誤ったアクション指示や不公正な業績評価につながる
   - 識別方法: 予算編成時の承認記録を参照し、ボトムアップ積み上げ額と最終予算額の差分をトップサイド調整額として把握する

3. **複合的なドライバの配分**
   - 一つの差異項目が複数カテゴリにまたがる場合が頻繁に発生する
   - 例: 売上数量差異の原因が「営業リソース不足（実行）」と「市場縮小（外部）」の両方
   - 対応方法:
     - 可能な限り寄与度を定量的に推定して配分する（例: 市場全体が5%縮小し自社が10%減少した場合、5%は外部要因、残り5%は実行要因と推定）
     - 同業他社や市場全体の動向と比較することで、自社固有の要因（実行要因）と市場共通の要因（外部要因）を分離する
     - 定量的な配分が困難な場合は「混合」と記録し、主因を明示する

4. **計画要因と外部要因の境界を判定する**
   - 計画策定時に合理的に予見できたか否かが判定基準となる
   - 計画策定時に入手可能だった情報（市場予測、契約条件、規制動向等）から予見できた場合は「計画要因」
   - 計画策定後に発生した予見困難な変化の場合は「外部要因」
   - 例: 為替レートの差異は、計画時の前提レートがコンセンサスから大きく乖離していた場合は「計画要因」、計画後の急激な変動の場合は「外部要因」

> **よくある落とし穴**: 差異の原因を安易に「外部要因」に帰属させてしまう傾向がある。「市場が悪かった」という説明は事業部門にとって心理的に受け入れやすいが、実際には実行要因（営業活動の質・量）や計画要因（前提の甘さ）が主因であるケースは多い。外部要因と結論付ける前に、同業他社や社内の他部門と比較して、自社固有の乖離がないかを確認する。自社の売上成長率が市場平均を下回っている場合、市場縮小では説明できない自社固有の問題が存在する。

> **判断の分岐点**: 「計画要因」の識別は組織的にセンシティブである。予算を策定した当事者にとって「計画が間違っていた」と認めることは難しい。しかし、計画要因を正しく識別しなければ、実行の問題でないものに対して実行改善を求めたり、次回の計画精度が向上しない。計画要因を指摘する場合は、属人的な責任追及ではなく、「どの前提条件が実態と乖離したか」「次回の計画サイクルでどう改善できるか」という構造的な学びとして提示する。

> **業種別の注意点**:
> - **製造業**: 原材料価格の変動は外部要因に見えるが、調達戦略（長期契約比率、ヘッジ方針）が不十分だった場合は実行要因の側面もある。調達部門の方針と比較して判定する
> - **SaaS/テクノロジー**: チャーンの増加を「競合の台頭（外部）」と分類しがちだが、プロダクト改善の遅れやカスタマーサクセスの不足（実行）が真因であるケースは多い。コホート別・解約理由別の分析で裏付ける
> - **小売・消費財**: 天候不順による売上減は外部要因だが、天候リスクを織り込まなかった計画は計画要因。季節商材の場合、天候感度をどこまで計画に織り込んでいたかで判定が分かれる

---

### 3. 分類の妥当性検証と記録

**実行条件**: ステップ2での分類が完了した後に実施する。

分類結果を第三者が検証可能な形で記録し、後続プロセスへの引き渡し品質を確保する。

1. **分類結果の偏りを確認する**
   - 全差異項目の分類分布を確認し、特定カテゴリへの偏りがないかチェックする
   - 外部要因に80%以上が集中している場合、実行要因や計画要因の見落としがないか再検討する
   - 実行要因に偏りすぎている場合、外部環境の変化を過小評価していないか確認する
   - 計画要因がゼロの場合、「計画は完璧だった」と暗に仮定していないかを問い直す

2. **事業部門との合意形成**
   - 分類結果を事業部門と共有し、認識のずれがないか確認する
   - 特に実行要因と外部要因の境界、計画要因の識別について合意を取る
   - 合意が得られない場合は、双方の見解を記録し、FP&Aマネージャーが最終判断する

3. **分類結果を構造化して記録する**

   | 項目 | 内容 |
   |------|------|
   | 差異項目 | 要因分解から引き継いだ差異の名称と金額 |
   | ドライバ | 根本原因の具体的内容 |
   | カテゴリ | 実行要因 / 外部要因 / 計画要因 / 混合（主因を明示） |
   | 根拠 | 分類の判定に用いた情報源と論理 |
   | 確認状況 | 事業部門との合意済み / 未確認 / 見解相違あり |

4. **後続プロセスへの引き渡し**
   - 分類結果は、性質の判別（一過性/構造的、コントロール可否）の入力となる
   - カテゴリ情報は、コントロール可否の判定において重要な手がかりとなる（実行要因はコントロール可能、外部要因はコントロール不可能の傾向が強い）
   - 計画要因の識別結果は、次回の計画サイクルへのフィードバック情報として別途蓄積する

> **よくある落とし穴**: 分類結果の記録が「カテゴリ名」だけで終わり、根拠が残らないケース。翌月以降に分類の妥当性を振り返ったり、類似の差異が発生した際に参照できるよう、判定の根拠と情報源を必ず記録する。
