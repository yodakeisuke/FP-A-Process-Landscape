# 通期着地への影響評価（ランレート換算、相殺差異・連鎖影響の識別）

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー、ローリング予測の担当者
- **何を解決するか**: 月次の差異額だけでは「通期の着地にどれだけ影響するのか」が分からない。月次差異を単純に12倍しても、季節性や契約改定タイミングを無視した過大/過小推定になる。さらに、個別差異を独立に評価するだけでは、有利差異と不利差異の相殺に潜むリスクや、一つのドライバが複数のP&L行に波及する連鎖影響を見落とす
- **届ける価値**: 各ドライバの通期着地への影響を、季節性補正・既知イベント織り込み済みのランレートで定量化し、相殺差異のリスクと連鎖影響のネット効果を明示することで、予測修正の要否判断とアクション優先順位付けに直結する情報を提供する

## スコープ

- **対象**: ドライバの分類と性質判別が完了した全てのドライバに対する、通期着地インパクトの定量評価
- **前提**: ドライバの分類（実行要因、外部要因、計画要因）および性質の判別（一過性/構造的、コントロール可否）が完了していること
- **後続**: 評価結果は経営レポートの作成に統合されるとともに、予測修正が必要と判断された項目はローリング予測の更新に引き渡される。アクション提言が必要な項目は打ち手の評価と提言に接続する
- **対象部門**: FP&A部門（実行主体）、事業部門（季節性パターン・契約情報の提供）、経営企画部門（戦略的文脈の提供）

## 責任者

| 役割 | 担当 |
|------|------|
| 通期影響の試算・分析の実行 | FP&Aアナリスト |
| 試算結果の検証・最終判断 | FP&Aマネージャー |
| 季節性・契約情報の提供 | 事業部門の予算責任者 |
| 通期着地への影響に関する意思決定 | CFO / 事業部門長 |

## 手順

**用語の定義**:
- **ランレート換算**: 月次（または四半期）の差異額を残存期間に投影し、通期への影響額を推定する手法。単純な月数乗算ではなく、季節性や既知の変動要因を織り込んで推定する
- **相殺差異**: 異なる要因による有利差異と不利差異が、P&L上で相殺し合って見かけ上の差異を小さくしているケース。有利側の消滅時にリスクが顕在化する
- **連鎖影響**: 一つのドライバが複数のP&L行に波及するケース。例えば、販売数量の減少が売上高・変動費・在庫評価・配賦コストに同時に影響する場合

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 個別影響の定量化 | 1. ランレート換算による通期影響の推定 | 性質判別が完了した全てのドライバに対して実施 |
| リスクの可視化 | 2. 相殺差異の識別と評価 | ステップ1完了後 |
| 波及効果の捕捉 | 3. 連鎖影響の識別と定量化 | ステップ1完了後。ステップ2と順序不問 |
| 結果統合 | 4. 評価結果の統合と予測修正要否の判断 | ステップ2-3完了後 |

### 1. ランレート換算による通期影響の推定

**実行条件**: 性質判別が完了した全てのドライバに対して実施する。一過性と判別されたドライバは当月実績としてのみ計上し、ランレート換算の対象外とする。

経営にとって最も重要な問いは「この差異は通期の着地にどう影響するか」である。月次の差異額だけでは通期のインパクトは分からない。

1. **ランレート換算の基本構造**
   - 基本計算: 月次差異額 × 残存月数 = ランレートベースの通期影響額
   - ただし、この基本計算はあくまで出発点であり、以下の調整を必ず行う

2. **季節性の補正**
   - 季節変動のある事業では、直近月の差異をそのまま残存月数に掛けると過大/過小推定になる
   - 補正手順:
     - 前年同期の月別パターン（月次売上の年間構成比等）を基準として季節性インデックスを算出する
     - 当月の差異額を季節性インデックスで調整し、年間ベースに換算する
     - 例: 閑散期（年間構成比5%の月）に100の差異が出ても、繁忙期（構成比15%の月）に同率で影響するなら通期影響は100÷5%×残存期間の構成比合計
   - 季節性インデックスは前年実績をベースとするが、事業構造の変化（新製品の追加、販路の変更等）がある場合は調整する

3. **既知の変動要因の織り込み**
   - 残存期間中に確実に起きる変動を織り込む:
     - **契約改定のタイミング**: 10月からの調達単価値上げ、4月からの賃金改定等
     - **価格改定の発効日**: 7月からの販売価格改定の効果
     - **事業イベント**: 新規事業の立ち上がり時期、設備投資の稼働開始時期、拠点の開設/閉鎖時期
     - **規制変更**: 発効日が確定している規制変更の影響
   - 織り込み済みの変動要因とその影響額を明示的に記録する

4. **事業部門への季節性パターンと既知イベントの確認**
   - ランレート換算の精度は、季節性の補正と既知イベントの織り込みの質に依存する。これらの情報は事業部門が最も正確に把握している
   - 事業部門への確認の問いかけ例:
     - 「今月の差異が残存期間にわたり継続すると仮定していますが、季節性を考慮すると影響の大小が変わるタイミングはありますか？」
     - 「下期に予定されている契約改定や価格変更で、この差異の方向性が変わる可能性はありますか？」
     - 「新規案件のパイプラインや、既知の受注・失注予定で、ランレートの前提が変わりそうなものはありますか？」
   - 事業部門から得た情報は、ランレート換算の前提として明示的に記録し、前提が変わった際に試算を更新できるようにする

5. **一過性/構造的の判別結果の反映**
   - 一過性と判定されたドライバ: 当月の実績差異としてのみ計上する。ランレート換算には含めない
   - 構造的と判定されたドライバ: 残存月数に展開する（季節性補正・既知要因調整済み）
   - 要モニタリングのドライバ: 構造的と仮定した場合のランレート換算値を条件付きで試算し、注記を付す

6. **レンジ推定の実施**
   - ランレート換算の結果を「ベストケース」「ベースケース」「ワーストケース」の3点で示す
   - ベストケース: 有利な前提（一過性と判定したドライバの再発なし、構造的ドライバの影響が縮小する可能性）
   - ワーストケース: 不利な前提（要モニタリングのドライバが全て構造的、季節性が前年より不利に振れる可能性）
   - レンジの幅自体が意思決定者にとっての有用な情報である。レンジが広い場合は不確実性が高く、追加の情報収集やシナリオ分析が必要

> **よくある落とし穴**: ランレート換算を機械的に「月次差異 × 12」で計算してしまうケース。これは以下の場面で重大な誤りを生む:
> - 季節性の強い事業（売上の60%がQ4に集中する等）では、Q1の月次差異は通期への影響度が小さい
> - 年度途中に発効する契約改定（例: 10月からの値上げ）は、発効前後で影響額が変わる
> - 一過性と判別されたドライバの差異まで含めてランレート換算すると、通期影響を過大に見積もる
> 必ず季節性補正・既知イベントの織り込み・一過性/構造的の区別を行った上で換算する。

> **判断の分岐点**: ランレート換算の基準時点をどこに置くか。年度の早期（Q1）では不確実性が高くレンジが広い。年度の後半（Q3以降）では実績の蓄積によりレンジが狭まる。Q1では保守的な前提でレンジを広めに取り、Q3以降は実績トレンドの延長で精度を高める。時点に応じたアプローチの使い分けが必要である。

### 2. 相殺差異の識別と評価

**実行条件**: ステップ1（ランレート換算）が完了した後に実施する。

相殺差異は、P&L上の見かけの安定の裏に潜むリスクを隠蔽する。個別差異の通期影響を把握した後、有利差異と不利差異の間に危険な相殺関係がないかを検証する。

1. **相殺差異の構造を理解する**
   - 相殺差異とは: 異なる要因による有利差異と不利差異が、P&L上で相殺し合って見かけ上の差異を小さくしているケース
   - 相殺差異が危険な理由: 売上の好調がコストの超過を隠している場合、売上の好調が反転した瞬間にコスト超過が露出し、影響が一気に顕在化する
   - 注意: 同一ドライバに起因する有利・不利の組み合わせ（例: 売上数量増と変動費増）は連動しており、相殺ではなく正常な構造的関係である

2. **相殺差異の識別手順**
   - ドライバ単位で有利差異と不利差異をリストアップする
   - 有利・不利が異なるドライバ間の独立性を確認する:
     - **連動している場合**（相殺ではない）: 売上数量増→変動費増、円安→海外売上増＋輸入コスト増
     - **独立している場合**（真の相殺）: 売上好調（営業努力）とコスト管理の緩み（予算超過）、一時的な大型案件の前倒し計上と構造的なコスト増
   - 独立したドライバ間の相殺を一覧化する

3. **相殺差異のリスク評価**
   - 有利側ドライバの性質を確認する:
     - 有利側が構造的であれば、相殺は比較的安定的
     - 有利側が一過性であれば、有利差異の消滅時に不利差異が露出するリスクが高い
   - ダウンサイドシナリオを試算する:
     - 有利側のドライバが消滅・反転した場合の通期影響額を算出する
     - この金額が「隠れた不利差異」として経営に報告すべき金額となる
   - 相殺の安定性を「高/中/低」で評価する

4. **相殺差異の報告と関係者への共有**
   - P&L上は差異が小さく見えても、内訳として有利・不利の構成を明示する
   - 特に、有利側が一過性で不利側が構造的な組み合わせは、最優先の報告事項とする
   - 「差異は小さいが、内訳に注意が必要」という形で経営レポートに織り込む
   - CFOへの報告では、相殺差異のダウンサイドシナリオ（有利側が消滅した場合の影響額）を必ず併記する。「現時点では問題ないが、〇〇が反転した場合に△△Mのリスクが顕在化する」というリスクの透明性を確保する
   - 事業部門には、相殺差異の有利側と不利側の両方を分離して共有する。有利側の事業部門には「この好調が持続するかの見通し」を確認し、不利側の事業部門には「隠れていた不利差異が露出するリスクへの備え」を促す

> **判断の分岐点**: 相殺差異の評価において、「P&L上で相殺されているから問題ない」と判断するか、「相殺の裏側にリスクが潜んでいる」と判断するかは、有利側ドライバの持続性に依存する。有利側が構造的（例: 新製品の好調な売上）であれば相殺は安定的だが、有利側が一過性（例: 大型案件の前倒し計上）であれば、翌月以降に不利差異が露出する。有利・不利それぞれのドライバの性質を踏まえて判断する。

> **業種別の注意点**:
> - **製造業**: 生産量増加による売上増と固定費の過吸収が同時に発生し、見かけの利益が膨らむケースがある。需要が反転すると両方が逆転し、二重のマイナス効果が出る
> - **SaaS/テクノロジー**: 新規顧客の獲得による売上増が、既存顧客のチャーン増を隠すケースに注意。ネットARRの増減だけでなく、グロスの獲得とチャーンを分離して評価する
> - **小売・消費財**: 天候要因による一時的な売上増が、販管費の超過を隠すケースがある。天候効果を除外した実力ベースの損益を確認する

### 3. 連鎖影響の識別と定量化

**実行条件**: ステップ1（ランレート換算）が完了した後に実施する。ステップ2と順序不問で実施可能。

個別差異を独立に評価するだけでは、一つのドライバが複数のP&L行に波及する連鎖影響を捕捉できない。連鎖影響を考慮しない場合、個別差異の合算では全体像を捉え損なう。

1. **連鎖影響の典型パターンを確認する**

   | 起点ドライバ | 直接影響 | 連鎖影響 |
   |------------|---------|---------|
   | 販売数量の減少 | 売上高の減少 | 変動費の減少（部分相殺）、固定費の未吸収、在庫増加と評価損リスク |
   | 原材料価格の上昇 | 売上原価の増加 | 粗利率の悪化、価格転嫁による販売数量への二次影響、在庫評価の変動 |
   | 採用の遅延 | 人件費の有利差異 | プロジェクト遅延による売上機会損失、外注費の増加、残業代の増加 |
   | 為替（円安） | 海外売上の円建て増加 | 輸入原材料コストの増加、海外拠点費用の円建て増加 |
   | 大幅な値引き | 売上単価の低下 | 販売数量の増加（部分相殺）、変動費の増加、ブランド価値への長期影響 |

2. **連鎖影響の識別手順**
   - 通期影響が大きい主要ドライバ（上位5-10件）を対象に、以下の問いを適用する:
     - このドライバはP&L上の他の行にも影響を与えているか
     - 直接影響を相殺する方向の連鎖影響はあるか（例: 数量減→変動費減）
     - 直接影響を増幅する方向の連鎖影響はあるか（例: 採用遅延→外注費増）
     - 連鎖影響が更に別の連鎖を生むか（二次連鎖）
   - 連鎖の経路をドライバごとに記録する

3. **連鎖影響の定量化**
   - P&Lの各行への影響を個別に推定する
   - ネットでの通期影響を算出する（直接影響＋全ての連鎖影響の合算）
   - 個別差異の単純合算とネット影響額の差分を明示する。この差分が「連鎖影響を考慮しない場合の見落とし額」となる
   - 定量化が困難な連鎖影響（ブランド価値への影響、従業員のモラルへの影響等）は定性的に記録する

4. **連鎖影響の時間差を考慮する**
   - 連鎖影響は直接影響と同時に発生するとは限らない
   - 例: 原材料価格の上昇が在庫を介して売上原価に反映されるまでのタイムラグ（在庫回転期間分の遅延）
   - 例: 価格転嫁の実施から顧客の発注量変化までのタイムラグ
   - 時間差を考慮し、残存月数ごとの影響プロファイルを描く

5. **連鎖影響の経路を事業部門と確認する**
   - 連鎖影響の識別は、FP&Aの分析だけでは経路の見落としが生じやすい。事業の実態を知る事業部門に連鎖経路を確認することで、精度を高める
   - 確認の問いかけ例:
     - 「採用遅延で人件費が有利に出ていますが、その結果として外注費やプロジェクト遅延の影響は出ていますか？」
     - 「原材料価格の上昇について、在庫を通じたコストへの反映タイミングはどの程度遅れますか？在庫回転はおおよそ何ヶ月ですか？」
     - 「値引きの結果として数量が増えていますが、この数量増はいつまで持続する見込みですか？また、変動費への影響はどの程度ですか？」
   - 経理部門にも連鎖影響の会計処理上のタイミング（在庫評価の変動が反映されるタイミング等）を確認する
   - 連鎖影響の定量化は事業部門にとって直感的でない場合がある。「人件費が△△M有利ですが、外注費が○○M不利で、ネットでは□□Mの不利です」という形で、P&L全体での影響を分かりやすく伝える

> **よくある落とし穴**: 連鎖影響の中で、有利方向の連鎖（例: 数量減に伴う変動費減）のみを認識し、不利方向の連鎖（例: 数量減に伴う固定費未吸収）を見落とすケース。連鎖影響は有利・不利の両方向を網羅的に洗い出す必要がある。

> **業種別の注意点**:
> - **製造業**: 在庫を介した連鎖影響に注意。原材料の数量差異は当月のP&Lには全額出ず、在庫に滞留して翌月以降に影響する。在庫回転期間を考慮した通期影響推定が必要
> - **SaaS/テクノロジー**: サブスクリプションモデルでは、当月の新規ARR/チャーンの影響が残存期間にわたり累積する。ランレート換算はMRRベースで行い、拡大/縮小のトレンドを織り込む
> - **プロジェクト型ビジネス（SI、建設等）**: 個別プロジェクトの進捗差異が通期着地に与える影響は、残工事量と完成見込み時期に依存する。ランレート換算ではなくプロジェクト別の完工予測を積み上げる

### 4. 評価結果の統合と予測修正要否の判断

**実行条件**: ステップ2-3（相殺差異の評価と連鎖影響の識別）が完了した後に実施する。

ランレート換算、相殺差異、連鎖影響の分析結果を統合し、経営判断に資する一貫した評価結果を作成する。

1. **通期影響評価サマリーを作成する**

   | 項目 | 内容 |
   |------|------|
   | ドライバ | 根本原因の具体的内容 |
   | カテゴリ | 実行要因 / 外部要因 / 計画要因 |
   | 性質 | 一過性 / 構造的 / 要モニタリング |
   | コントロール | 可能 / 部分可能 / 不可能 |
   | 当月差異額 | 実績ベースの差異金額 |
   | 通期影響額（ベースケース） | ランレート換算＋季節性補正＋既知イベント調整後 |
   | 通期影響額（レンジ） | ベストケース〜ワーストケース |
   | 相殺差異のリスク | 有/無。有の場合、隠れた不利差異額 |
   | 連鎖影響のネット効果 | 直接影響＋連鎖影響の合算額 |
   | 対応方針 | 是正アクション / リスク緩和 / 予測修正 / モニタリング継続 |

2. **予測修正要否の判断**
   - 以下の基準に該当する場合、ローリング予測の更新への引き渡しが必要:
     - 構造的ドライバの通期影響額が、年間予算の重要性閾値を超える場合
     - 計画要因として識別された前提条件の乖離が、残存期間の予測に影響する場合
     - 連鎖影響を含めた通期着地見込みが、現行予測から一定幅以上乖離する場合
     - 相殺差異のリスク評価で「安定性：低」と判定された項目がある場合
   - 予測修正の引き渡し情報: ドライバの内容、性質（構造的）、通期影響額（レンジ）、影響するP&L行、推奨する予測修正の方向性

3. **予測修正の方向性についてCFO・事業部門との事前すり合わせ**
   - 予測修正が必要と判断された場合、経営会議やボードへの報告前に、CFOおよび該当する事業部門長と事前にすり合わせを行う
   - すり合わせのポイント:
     - 「通期着地見込みが現行予測から△△M乖離する見込みです。修正の方向性について、お考えをお聞かせください」
     - 予測修正のレンジ（ベスト/ベース/ワースト）を提示し、どのシナリオを公式予測とするか合意する
     - 修正幅が大きい場合、段階的な修正（今回は一部を織り込み、追加情報を待って追加修正）か、一括修正かの判断を仰ぐ
   - IR部門への影響がある場合（業績予想の修正が必要な水準に達する場合）は、CFOを通じてIR部門に早期に情報を共有する。開示タイミングとの整合性を確保する
   - ローリング予測の担当者には、修正の根拠となるドライバ情報と前提条件を具体的に引き渡し、予測モデルへの反映方法を協議する

4. **経営レポートへの引き渡し**
   - 「事実（差異額）→原因（ドライバ）→影響（通期インパクト）→示唆（対応方針）」の流れで構造化する
   - 相殺差異のリスクと連鎖影響のネット効果は、個別差異の説明とは別に、統合的な視点で報告する
   - 通期着地見込みのレンジ（ベスト/ベース/ワースト）を明示し、不確実性の程度を伝える

5. **アクション提言への接続**
   - 是正アクションまたはリスク緩和策が必要と判断されたドライバについて、アクション候補と期待効果の概算を付して打ち手の評価と提言に引き渡す
   - 優先順位は性質判別の優先順位マトリクスと通期影響額の掛け合わせで決定する
   - アクション候補は、事業部門の実行可能性を踏まえたものとする。FP&Aが一方的に「このアクションを取るべき」と提言するのではなく、事業部門との対話を通じて「実行可能で効果的なアクション」を共同で特定する姿勢が重要である

## サイクル終了後の振り返り

四半期に一度、通期影響評価プロセスの有効性を振り返る。

- **ランレート換算の精度検証**: 過去の月次で実施したランレート換算の結果と、実際の通期着地を比較する。系統的な過大推定・過小推定がないかを確認し、季節性補正やイベント織り込みの精度を改善する
- **相殺差異のリスク評価の事後検証**: 「安定性：高」と評価した相殺差異が実際に安定していたか、「安定性：低」と評価した相殺差異が実際にリスクとして顕在化したかを確認する
- **連鎖影響の捕捉漏れの確認**: 事後的に「連鎖影響を見落としていた」ケースがなかったかを確認する。見落としがあった場合は、連鎖パターンの典型例リストを更新する
- **事業部門からのフィードバック**: 季節性パターンや既知イベントの情報提供が十分だったか、ランレート換算の前提に対する事業部門の納得感があったかを確認する。「FP&Aの通期見通しと事業部門の肌感覚が大きく乖離していた」ケースがあれば、情報共有プロセスを改善する
- **予測修正の適時性の確認**: 予測修正が必要と判断してからローリング予測に反映されるまでのリードタイムを確認する。修正が遅れた場合、意思決定のタイミングに影響がなかったかを振り返る

> **よくある落とし穴**: 評価結果のサマリーが「差異の説明」で終わり、「だから何をすべきか」の示唆が欠落するケース。通期影響評価の最終的な価値は、経営の意思決定を支援することにある。全てのドライバに対して「対応方針」を明記し、少なくとも最優先・高優先のドライバについては具体的なアクション候補を提示する。
