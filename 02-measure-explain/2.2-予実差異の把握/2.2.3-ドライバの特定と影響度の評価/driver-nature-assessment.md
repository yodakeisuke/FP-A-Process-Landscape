# 性質の判別（一過性/構造的、コントロール可否）

## 目的

- **誰のために**: CFO、事業部門長、FP&Aマネージャー、ローリング予測の担当者
- **何を解決するか**: ドライバが分類されても、「今月だけの話か、今後も続く話か」「自社のアクションで改善できるか否か」が分からなければ、対応の優先順位が付けられない。一過性の差異に対して構造改革を仕掛けたり、コントロール不可能なドライバに対して是正アクションを求めたりする誤った判断を生む
- **届ける価値**: 各ドライバの時間的持続性（一過性/構造的）とコントロール可否の2軸で性質を判別し、対応方針の優先順位付けの基盤を提供する。これにより、限られた経営資源を最も効果的なアクションに集中させる判断が可能になる

## スコープ

- **対象**: ドライバの分類（実行要因、外部要因、計画要因）が完了した全てのドライバに対する、時間的持続性とコントロール可否の判別
- **前提**: ドライバの識別と3カテゴリへの分類が完了していること
- **後続**: 判別結果は通期着地への影響評価に引き渡される。性質判別の結果とコントロール可否の判定を組み合わせた優先順位マトリクスは、経営レポートの作成およびアクション提言の起点となる
- **対象部門**: FP&A部門（実行主体）、事業部門（ドライバの持続性に関する現場情報の提供）、経営企画部門（市場構造変化の見解提供）

## 責任者

| 役割 | 担当 |
|------|------|
| 性質判別の実行 | FP&Aアナリスト |
| 判別結果の検証・最終判断 | FP&Aマネージャー |
| 持続性に関する現場情報の提供 | 事業部門の予算責任者 |
| 対応方針の意思決定 | CFO / 事業部門長 |

## 手順

**用語の定義**:
- **一過性（One-time）**: 単発で発生し、再発の蓋然性が低いドライバ。特定のイベント・取引に紐づき、自然に解消されるか既に解消済みであるもの
- **構造的（Recurring/Structural）**: 継続的に発生する、またはトレンドとして定着しているドライバ。事業構造・市場環境・契約条件等の変化に紐づき、意図的な介入がなければ継続するもの
- **コントロール可能**: 自社の意思決定・実行によって差異を縮小または解消できるドライバ
- **部分コントロール可能**: 影響を緩和する手段はあるが、完全な解消はできないドライバ
- **コントロール不可能**: 自社の行動では影響を変えられないドライバ

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 時間軸の判別 | 1. 一過性/構造的の判別 | ドライバの分類が完了した全ての差異項目に対して実施 |
| コントロール軸の判別 | 2. コントロール可否の判定 | ステップ1と順序不問で実施可能 |
| 統合 | 3. 2軸の統合と優先順位付け | ステップ1-2完了後 |

### 1. 一過性/構造的の判別

**実行条件**: ドライバの分類が完了した全ての差異項目に対して実施する。

ドライバが特定されても、それが「今月だけの話」か「今後も続く話」かで経営的な意味合いは全く異なる。構造的なドライバは通期着地への影響が大きく、予測修正と根本的な対応が必要になる。一過性のドライバは当月実績として認識し、再発防止に注力する。

1. **判別の基準を適用する**

   | 判別軸 | 一過性（One-time） | 構造的（Recurring/Structural） |
   |-------|-------------------|-------------------------------|
   | 発生頻度 | 単発で発生し、再発の蓋然性が低い | 継続的に発生する、またはトレンドとして定着している |
   | 原因の性質 | 特定のイベント・取引に紐づく | 事業構造・市場環境・契約条件等の変化に紐づく |
   | 解消の見込み | 自然に解消される、または既に解消済み | 意図的な介入がなければ継続する |
   | 過去の実績 | 過去に類似の発生がないか、あっても散発的 | 過去2-3期にわたり同方向の傾向が継続 |

2. **典型的なパターンによる判別**

   | ドライバの例 | 判別 | 根拠 |
   |------------|------|------|
   | 大型案件の一括納品による売上集中 | 一過性 | 特定案件に紐づき、翌月以降の再発は別案件次第 |
   | 主要顧客の発注パターンの恒久的変更 | 構造的 | 顧客側の方針変更であり、契約更改まで継続 |
   | サプライヤーの契約単価改定 | 構造的 | 契約期間中は継続。次回交渉まで変わらない |
   | 原材料のスポット価格高騰 | 要判別 | 市場の需給バランスに依存。一過性か構造的かは市場分析が必要 |
   | 新製品ローンチに伴う初期マーケティング費用 | 一過性 | ローンチフェーズ固有の支出。ただし継続投資計画の有無を確認 |
   | 生産ラインの歩留まり低下 | 要判別 | 設備老朽化なら構造的、一時的な材料ロット不良なら一過性 |
   | 採用コストの予算超過 | 要判別 | 採用市場の逼迫（構造的）か、特定ポジションの難航（一過性）かを区別 |
   | 為替レートの変動 | 要判別 | マクロ経済のトレンドか一時的なボラティリティかを市場コンセンサスで確認 |
   | 訴訟和解金・罰金 | 一過性 | 特定事案に紐づく。ただし、同種リスクの再発可能性は別途評価 |
   | 組織再編に伴う一時費用 | 一過性 | 再編完了で終了。ただし再編後の構造変化（人件費水準の変動等）は構造的 |

3. **「要判別」ケースの掘り下げ方**
   - **トレンド分析**: 過去6-12か月の推移を確認し、同方向の動きが3か月以上継続しているか
   - **構造変化の有無**: 契約条件、事業モデル、市場構造に変化があったかを事業部門に確認
   - **外部ベンチマーク**: 市場指標やアナリストコンセンサスを参照し、一時的な変動か構造的なシフトかを判断
   - **確信度の記録**: 判別の確信度を「高/中/低」で記録する。確信度が低い場合は、翌月以降のモニタリング項目として「要モニタリング」の判別結果を付与する

4. **事業部門・経営企画部門への確認による判別精度の向上**
   - 「要判別」のドライバについては、FP&Aの数値分析だけで判断せず、事業部門の現場情報と経営企画部門の市場分析を組み合わせて判別精度を高める
   - 事業部門への確認の問いかけ例:
     - 「この歩留まり低下は、設備の問題ですか、それとも材料の問題ですか？設備の場合、改善の見込みはありますか？」
     - 「主要顧客の発注パターンが変わりましたが、顧客側の事情をお聞きになっていますか？一時的な在庫調整か、恒久的な方針変更か、感触はいかがですか？」
     - 「採用コストの超過は、採用市場全体の逼迫ですか、それとも特定ポジションの難航ですか？」
   - 経営企画部門への確認の問いかけ例:
     - 「原材料のスポット価格上昇について、市場の見通しはどうなっていますか？構造的な需給変化か一時的な供給障害かの判断材料はありますか？」
     - 「この業界のトレンドは、一時的な調整局面ですか、それとも構造的な変化の兆しですか？」
   - ヒアリングのスタンスとして、一過性であることの「積極的な根拠」を求める。根拠がなければ構造的として扱う方が保守的で安全である

5. **両建てアプローチの適用**
   - 一過性と構造的の中間に位置するドライバを無理にどちらかに分類しない
   - 「構造的と仮定して通期影響を試算しつつ、一過性のシナリオも併記する」という両建てのアプローチが有効である
   - 判別の精度よりも、判別の前提と根拠を明示することが重要である

> **よくある落とし穴**: 一過性と構造的の判別を「希望的観測」で行うケース。不利差異を一過性と判定したい心理が働くが、「一過性であることの積極的な根拠」がなければ構造的として扱うべきである。逆に、有利差異を構造的と楽観的に判定すると、その前提が崩れた際にリスクが顕在化する。

> **業種別の注意点**:
> - **製造業**: 原材料価格の変動は、商品市況（構造的トレンド）とスポット要因（天候、地政学リスク）を区別する必要がある。先物価格カーブやサプライヤーの値上げ通知を参照する
> - **SaaS/テクノロジー**: チャーンレートの悪化が一過性（特定大口顧客の解約）か構造的（プロダクトフィットの低下、競合流出）かの判別は、コホート分析やNPSの推移で裏付ける
> - **小売・消費財**: 天候要因による売上変動は典型的な一過性だが、消費者の購買行動の変化（ECシフト、価格感度の変化等）は構造的。POSデータのトレンドで判別する

### 2. コントロール可否の判定

**実行条件**: ドライバの分類が完了した全ての差異項目に対して実施する。ステップ1と順序不問で実施可能。

ドライバのコントロール可否を判定することで、「アクションで改善できるもの」と「受容してリスク管理するもの」を分離し、アクション提言の方向性を決定する。

1. **コントロール可否の3段階で判定する**

   | 区分 | 定義 | 対応の方向性 |
   |------|------|------------|
   | コントロール可能 | 自社の意思決定・実行によって差異を縮小または解消できる | 是正アクションの立案・実行 |
   | 部分コントロール可能 | 影響を緩和する手段はあるが、完全な解消はできない | リスク緩和策の検討（価格転嫁、ヘッジ、代替調達等） |
   | コントロール不可能 | 自社の行動では影響を変えられない | 予測への織り込みとリスクシナリオの更新 |

2. **ドライバカテゴリとの対応関係を参照する**

   | ドライバカテゴリ | 典型的なコントロール可否 | 留意点 |
   |----------------|----------------------|--------|
   | 実行要因 | コントロール可能が多い | ただし、過去の意思決定の結果（既に実行済みの施策の効果不足等）は、短期的にはコントロール困難な場合がある |
   | 外部要因 | コントロール不可能が多い | ただし、為替ヘッジ、長期調達契約、価格転嫁等でリスク緩和が可能な場合は「部分コントロール可能」 |
   | 計画要因 | 当期はコントロール不可能 | 計画の前提が間違っていた場合、当期中にできるのは予測の修正。根本的な改善は次回の計画サイクルに反映 |

3. **「部分コントロール可能」の範囲を明確にする**
   - コントロール可能な範囲とできない範囲を具体的に切り分ける
   - 例: 原材料価格の上昇（コントロール不可能）に対し、「調達先の分散」「長期契約の締結」「価格転嫁」は部分的にコントロール可能。ただし市場全体の需給構造は変えられない
   - 緩和策の有効性と実行可能性を簡潔に記述する

4. **組織の権限とケイパビリティを踏まえた判定**
   - コントロール可否は「現在の組織能力と権限」を前提とした判定であり、絶対的なものではない
   - 例: 原材料価格の上昇はコントロール不可能だが、「価格転嫁する権限がある」場合は部分コントロール可能になる
   - 権限の拡大やケイパビリティの構築によって将来的にコントロール可能になるものは、その旨を付記する

5. **コントロール可否の判定における事業部門との認識すり合わせ**
   - コントロール可否の判定は、事業部門の実行力と権限に直結するため、FP&Aの判断だけで確定しない
   - 事業部門への確認の問いかけ例:
     - 「この原材料価格の上昇に対して、調達先の分散や長期契約で緩和する余地はどの程度ありますか？」
     - 「価格転嫁はどの程度可能ですか？顧客との交渉のリードタイムはどれくらいですか？」
     - 「この効率低下について、追加投資なしで改善できる余地はありますか？」
   - コントロール可能と判定した場合は、事業部門が「実行可能」と同意しているかを確認する。FP&Aが「コントロール可能」と判定しても、事業部門が「現場の実態として難しい」と判断している場合は、その乖離を記録し、対応方針の議論に含める
   - この確認は、後続のアクション提言が実効性を持つために不可欠である。実行不可能なアクションの提言は組織の信頼を損なう

> **判断の分岐点**: コントロール可否の判定は、アクション提言の方向性を規定する。コントロール可能と判定すれば是正アクションを求めることになり、コントロール不可能と判定すれば予測修正で対応することになる。この判定が甘い（コントロール可能なものを不可能と判定する）と改善機会を逃し、厳しすぎる（コントロール不可能なものを可能と判定する）と事業部門に無理な是正を求めることになる。事業部門の権限と実行力を踏まえた現実的な判定が必要である。

> **業種別の注意点**:
> - **製造業**: 生産効率の改善はコントロール可能に見えるが、設備の老朽化や設計起因の問題の場合は短期的にはコントロール困難。設備投資のリードタイムを考慮する
> - **SaaS/テクノロジー**: 顧客獲得コスト（CAC）の上昇は、マーケティング施策の最適化（コントロール可能）と市場全体の競争激化（コントロール不可能）の複合であることが多い。チャネル別のCAC推移で切り分ける
> - **プロジェクト型ビジネス**: プロジェクトの工期遅延は、リソース配分（コントロール可能）と顧客側の仕様変更・意思決定遅延（部分コントロール可能）を区別する

### 3. 2軸の統合と優先順位付け

**実行条件**: ステップ1（一過性/構造的の判別）とステップ2（コントロール可否の判定）が完了した後に実施する。

2つの軸の判別結果を統合し、後続の通期着地への影響評価と経営レポートに向けた優先順位を設定する。

1. **各ドライバの判別結果を一覧に統合する**

   | 項目 | 内容 |
   |------|------|
   | 差異項目 | 要因分解から引き継いだ差異の名称と金額 |
   | ドライバ | 根本原因の具体的内容 |
   | カテゴリ | 実行要因 / 外部要因 / 計画要因 |
   | 性質 | 一過性 / 構造的 / 要モニタリング |
   | コントロール | 可能 / 部分可能 / 不可能 |
   | 確信度 | 高 / 中 / 低 |

2. **優先順位マトリクスを適用する**

   | | コントロール可能 | 部分コントロール可能 | コントロール不可能 |
   |---|---|---|---|
   | **構造的** | 最優先: 是正アクションの検討対象 | 高: リスク緩和策の検討対象 | 中: 予測修正・リスクシナリオの対象 |
   | **要モニタリング** | 高: 暫定アクション＋監視 | 中: 監視＋緩和策の準備 | 低: 監視＋予測への条件付き織り込み |
   | **一過性** | 中: 再発防止策の検討 | 低: 影響の封じ込め | 低: 記録のみ |

3. **優先順位マトリクスの結果を経営層・事業部門と共有する**
   - 優先順位マトリクスの結果は、経営報告における差異説明の「重みづけ」を決定する。最優先・高優先のドライバに報告の重点を置き、低優先のドライバは簡潔な記載に留める
   - 事業部門には、マトリクスの結果を事前に共有し、「構造的×コントロール可能」のセルに入ったドライバについては、是正アクションの検討を依頼する。この依頼は、経営会議の前に行い、会議の場でアクション案を議論できる状態にしておく
   - 「構造的×コントロール不可能」のドライバについては、予測修正の方向性をCFOに早期に報告する。予測修正の規模が大きい場合は、IR部門や経営企画部門にも情報を共有する

4. **通期着地への影響評価に引き渡す情報を整備する**
   - 構造的と判別されたドライバ: ランレート換算の対象として引き渡す
   - 一過性と判別されたドライバ: 当月実績としてのみ計上し、ランレート換算には含めない旨を明示する
   - 要モニタリングのドライバ: 構造的と仮定した場合の影響額を条件付きで試算する対象として引き渡す

5. **モニタリング項目の設定**
   - 確信度が低いドライバ、「要モニタリング」としたドライバについて、翌月以降の確認ポイントを設定する
   - 確認ポイントの例: 同方向の差異が翌月も発生するか、外部指標がトレンドを示すか、事業部門から追加情報が得られるか
   - モニタリング結果に基づき、翌月の分析で判別を更新する
   - モニタリング項目は、翌月の分析開始時に事業部門に対しても共有し、「来月、この点について追加情報をいただけると助かります」と具体的に依頼する。これにより、翌月のヒアリングがより効率的になる

> **よくある落とし穴**: 優先順位マトリクスを機械的に適用し、金額の大きさを考慮しないケース。構造的かつコントロール可能でも、通期影響額が軽微であれば対応の緊急度は低い。マトリクスによる定性的な優先度に加え、通期着地への影響評価（後続プロセス）で定量的なインパクトを掛け合わせて最終的な優先順位を決定する。

## サイクル終了後の振り返り

四半期に一度、性質判別プロセスの有効性を振り返る。

- **判別精度の事後検証**: 「一過性」と判別したドライバが翌月以降も発生していないか、「構造的」と判別したドライバが実際に継続しているかを確認する。判別の正答率を把握し、改善に繋げる
- **コントロール可否の判定の実効性確認**: 「コントロール可能」と判定したドライバに対して実際にアクションが取られたか、その結果差異が改善されたかを確認する。判定と実行のギャップがある場合、判定基準の見直しが必要
- **モニタリング項目のフォローアップ**: 「要モニタリング」としたドライバの判別が更新されているかを確認する。モニタリングが形骸化して「要モニタリング」のまま放置されているドライバがないかをチェックする
- **事業部門へのフィードバック**: 四半期を通じた判別結果のサマリーを事業部門と共有し、「構造的と判別されたドライバへの対応状況」「一過性と判別されたドライバの再発状況」をレビューする。これにより、差異分析が単なる事後報告ではなく、経営改善のサイクルに繋がっていることを組織として確認する
