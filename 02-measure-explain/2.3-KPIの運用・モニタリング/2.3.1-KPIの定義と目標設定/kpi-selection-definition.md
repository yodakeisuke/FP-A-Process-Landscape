# KPIの選定と定義

## 目的

- **誰のために**: CFO、FP&A責任者、事業部門長、KPIオーナー
- **何を解決するか**: KPIが場当たり的に設定されると、戦略と無関係な指標が乱立し、モニタリングの負荷だけが増える。計算式の定義が曖昧なまま運用されると、同じKPIでも算出者によって値が異なり、経営判断の基盤が揺らぐ。さらに、KPI選定がFP&A部門の閉じた作業になると、事業部門が「押しつけられた指標」と捉え、日常の行動変容につながらない
- **届ける価値**: 戦略目標から逆算したKPIを事業部門との対話を通じて厳選し、計算式・データソース・更新頻度・責任者を一意に定義することで、組織全体が同じ数字で議論でき、かつ現場が「自分ごと」として運用できる状態をつくる

## スコープ

- **対象**: 全社・事業部門レベルのKPIの選定と定義プロセス。財務KPI（売上成長率、営業利益率等）および業務KPI（受注件数、解約率等）の双方を含む
- **前提**: 中長期計画または年度予算で戦略目標が設定済みであること。管理会計の実績データが取得可能な状態であること
- **後続**: 定義されたKPIは目標値・閾値の設定に引き渡され、KPI体系の構造化を経てダッシュボードに実装される
- **対象部門**: FP&A部門（設計主体）、事業部門（KPIオーナー候補）、経理部門・情報システム部門（データソース確認）
- **部門横断の連携先**: 経営企画部門（戦略との整合性確認）、HR部門（人的指標が候補に含まれる場合）、IR部門（開示指標との一貫性確認）

## 責任者

| 役割 | 担当 |
|------|------|
| KPI定義プロセスの設計・推進 | FP&Aマネージャー |
| 個別KPIの定義書作成 | FP&Aアナリスト |
| KPIセットの最終承認 | CFO / 経営会議 |
| データソースの実現可能性確認 | データ提供元部門（経理、営業管理、情報システム等） |
| KPIの日常運用・報告 | KPIオーナー（各事業部門の管理者） |

## 手順

**用語の定義**:
- **KPI（重要業績評価指標）**: 戦略目標の達成度を測定するために選定された定量指標。測定可能であり、定期的に更新され、意思決定に直結するもの
- **KPIオーナー**: 当該KPIの数値に対して説明責任を持ち、改善アクションを起案・実行する権限を持つ者
- **KPI定義書**: 1つのKPIについて、計算式・データソース・更新頻度・責任者・履歴等を一意に記録したドキュメント

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| 候補抽出 | 1. 戦略目標からのKPI候補の導出 | 中長期計画・年度予算の策定後、またはKPIの定期見直し時 |
| 選定 | 2. KPI候補の評価と絞り込み | ステップ1完了後 |
| 定義 | 3. KPI定義書の作成 | ステップ2完了後 |
| 確定 | 4. KPI定義の承認と周知 | ステップ3完了後 |

### 1. 戦略目標からのKPI候補の導出

**実行条件**: 中長期計画の策定後、年度予算の確定後、または四半期ごとのKPI見直し時に実施する。

KPIの選定は「何を測れるか」ではなく「何を測るべきか」から始める。戦略目標を起点に、その達成度を最も直接的に反映する指標を候補として洗い出す。

1. **戦略目標を分解し、測定可能な要素を特定する**
   - 戦略目標（例: 「3年で売上2倍」）を構成要素に分解する（新規顧客獲得数 × 顧客単価 × 継続率、等）
   - 各構成要素について「この要素が改善したことを何で確認するか」を問い、候補指標を列挙する
   - 1つの戦略目標に対して候補は5〜10個出すことを目安とする。この段階では絞り込まない

2. **事業部門の現場視点を取り込む**
   - 戦略目標の分解をFP&A内部だけで完結させない。事業部門長またはその直下の管理者に「日常の業務で最も気にしている数字は何か」「業績が悪化する兆候を最初にどこで感じるか」をヒアリングする
   - ヒアリングのタイミング: 候補指標の一覧が初版として出来上がった直後。白紙の状態で聞くと発散するため、たたき台を持参して意見を求める
   - ヒアリングの形式: 1on1の30分ミーティングが最も率直な意見を引き出しやすい。会議室ではなくカフェスペースやオンラインの気軽な場を選ぶと、本音が出やすい
   - 質問例:
     - 「この候補リストの中で、ご自身のチームが日々追いかけている数字はどれですか？」
     - 「逆に、このリストには入っていないが、実は毎日見ている数字はありますか？」
     - 「数字が悪くなったとき、最初に何を確認しますか？」
   - 事業部門が日常的に見ている非公式な指標（Excelで独自管理しているもの等）は、公式KPIの候補として重要な手掛かりとなる

3. **既存の管理指標・レポートから候補を補完する**
   - 現在モニタリングしている指標の一覧を棚卸しする
   - 戦略目標との紐づけがある指標は候補に追加する
   - 戦略目標と紐づかない既存指標は、この段階でフラグを立てる（後続の見直し・改廃の対象）

4. **外部のベンチマーク・業界慣行を参照する**
   - 同業他社の開示資料（決算説明資料、統合報告書）で使用されているKPIを確認する
   - IR部門に「投資家から頻繁に質問される指標」を確認し、対外的な説明責任の観点から候補に含めるべき指標がないか検討する
   - 業界固有の標準的KPIがある場合は候補に含める（ただし、自社の戦略との整合性が前提）

> **よくある落とし穴**: 「測りやすいもの」を優先して選ぶと、戦略と無関係な指標が残り、本当に重要な指標が漏れる。データの取得容易性はステップ2で評価する。ステップ1では戦略との関連性だけを基準にする。

> **定性情報の収集ポイント**: FP&Aが数字を扱うプロフェッショナルだからこそ、数字に表れない文脈を現場から引き出す努力が必要である。候補導出の段階で事業部門の声を拾うことは、後続の合意形成を格段に円滑にする「事前投資」でもある。

### 2. KPI候補の評価と絞り込み

**実行条件**: ステップ1でKPI候補が出揃った後に実施する。

候補の中から、実際にモニタリングするKPIを絞り込む。指標の乱立は注意力の分散を招くため、数を制御することが重要である。

1. **選定基準で候補を評価する**
   - 以下の5つの基準で各候補を評価する

   | 基準 | 評価の観点 |
   |------|-----------|
   | 戦略整合性 | その指標が改善すれば、戦略目標の達成に直接貢献するか |
   | 行動誘発性 | その指標を見た責任者が、具体的なアクションを起こせるか。傍観するだけの指標になっていないか |
   | 測定可能性 | 計算に必要なデータが、許容できるコスト・頻度で取得できるか |
   | 操作耐性 | 意図的な操作（数字の作り込み）や定義の恣意的解釈が困難か |
   | 理解容易性 | 経営層・現場の双方が、定義と意味を直感的に理解できるか |

2. **事業部門との共同評価セッションを実施する**
   - 候補指標の一覧と評価基準を事前に送付し、各事業部門長に自部門に関係するKPI候補への評価を依頼する
   - FP&Aと各事業部門長（またはKPIオーナー候補）の間で1〜2時間の評価セッションを行う。このセッションの目的は「FP&Aが評価を聞く」のではなく「一緒に評価を行う」ことである
   - セッションで確認すべき論点:
     - 「この指標が悪化したとき、具体的にどんなアクションを取りますか？」（行動誘発性の実務的検証）
     - 「この指標の数字を良く見せようと思えば、本質的な改善なしに操作できますか？」（操作耐性の現場検証）
     - 「チームメンバーにこの指標を説明するとき、どう説明しますか？」（理解容易性の現場検証）
   - 評価が分かれた指標については、その場で結論を急がず、「仮採用」として次のステップに進め、運用の中で判断する選択肢も残す

3. **KPIの数を制御する**
   - 全社レベル: 5〜8個。10個を超えると焦点が散漫になる（※ 運用フェーズでは [kpi-periodic-review.md](../2.3.3-KPIの見直しと改廃/kpi-periodic-review.md) の基準（全社7-12個）を上限の目安とする。本SOPの5-8個は新規選定時の推奨数）
   - 事業部門レベル: 部門あたり5〜7個。全社KPIとの重複を含む
   - 「あれば便利」程度の指標はKPIではなく参考指標として分離する。KPIとして管理する指標は、経営会議で定期的にレビューし、未達時にアクションが発動されるもののみ

4. **候補間の重複・相関を確認する**
   - 高い相関を持つ指標が複数ある場合（例: 売上高と受注残）、一方をKPI、他方を補助指標とする
   - 相反する可能性のある指標の組み合わせを意図的に残す（例: 売上成長率と営業利益率）。片方だけの最適化を防ぐため

> **判断の分岐点**: 「測定可能性」の評価で、現時点ではデータが取得できないが戦略上不可欠な指標がある場合、2つの選択肢がある。(a) データ基盤の整備を先行させてKPIに含める、(b) 代替指標（プロキシ）で当面代用し、データ整備後に切り替える。投資対効果とタイムラインで判断する。この判断はIT部門への早期相談が鍵であり、FP&Aが単独で実現可能性を見積もらない。

> **異論のマネジメント**: 事業部門間でKPIの候補について意見が対立することがある。例えば、セールス部門は「受注件数」を推し、デリバリー部門は「案件利益率」を優先するケース。この場合、FP&Aは仲裁者として「両方の視点が必要だからこそ、両指標をセットで管理する」という提案を行うか、上位KPIで統合する方法を示す。合意に至らない場合は、論点を整理した上でCFOまたは経営会議に判断を仰ぐ。議論の過程と各者の見解は記録に残す。

> **業種別の注意点**:
> - **製造業**: 稼働率、歩留まり率、在庫回転率など、オペレーション系KPIが重要。ただし稼働率を単独KPIにすると過剰生産のインセンティブになるため、在庫指標とセットで管理する
> - **SaaS/テクノロジー**: ARR、NRR、Churn Rate、CAC Payback Period等のユニットエコノミクス系KPIが中心。MRR/ARRの定義（契約ベースか請求ベースか）を厳密に決めないと集計値がブレる
> - **小売・流通**: 既存店売上高成長率、客単価、来店頻度、坪効率が基本。EC併設の場合はオムニチャネル指標の定義（店舗受取のEC注文をどちらに計上するか等）が論点になる

### 3. KPI定義書の作成

**実行条件**: ステップ2でKPIセットが確定した後に実施する。

選定された各KPIについて、解釈のブレを排除するための定義書を作成する。定義書は「このKPIについて質問が出たとき、この文書を見れば全て答えられる」状態を目指す。

1. **KPI定義書に含める項目**

   | 項目 | 記載内容 |
   |------|---------|
   | KPI名称 | 正式名称と略称（英語名称を併記する場合はここに記載） |
   | 対応する戦略目標 | このKPIがどの戦略目標の達成度を測定するか |
   | 計算式 | 分子・分母の定義を含む厳密な計算式。「売上高」が税込か税抜か、返品控除前か後か等の曖昧さを排除する |
   | 単位 | ％、千円、件数、日数 等 |
   | データソース | 計算に使用するデータの出所（システム名、テーブル名、帳票名）。手作業で加工が必要な場合はその手順も記載 |
   | 更新頻度 | 日次／週次／月次／四半期。更新タイミング（例: 月次締め後3営業日以内） |
   | 集計期間 | 単月、3ヶ月移動平均、年度累計、直近12ヶ月（LTM）等 |
   | KPIオーナー | 数値に対する説明責任を持つ者（役職名で記載） |
   | 報告先 | このKPIを定期レビューする会議体・報告ライン |
   | 制約・留意事項 | 季節性、一時要因による変動、比較可能性に影響する事象 等 |

2. **計算式の定義で特に注意すべき点**
   - 除外項目を明示する: 「営業利益率」であれば、一時的な構造改革費用や減損損失を含むか除くかを決める
   - 期間按分の方法を明示する: 月中に発生したイベント（M&A、事業売却等）の扱い
   - 通貨の扱い: 複数通貨が関わる場合、換算レート（期中平均レート、期末レート、予算レート）を指定する

3. **データソースの実現可能性を確認する（部門横断連携）**
   - データ提供元部門と合意する項目: データの取得タイミング、フォーマット、品質水準（欠損率の許容範囲等）
   - 経理部門との連携: 管理会計と制度会計の数値の整合性を確認する。特にKPIの計算で使用する「売上高」「営業利益」の定義が、制度会計の計上基準と一致しているか、意図的に異なる場合はその理由と調整方法を明記する
   - IT部門との連携: データ抽出の自動化可否、システム改修が必要な場合のスケジュールと優先順位を早期に確認する。KPI運用開始後に「データが取れない」と判明する事態を防ぐ
   - 手作業による加工が介在する場合、エラーリスクと代替手段を記録する
   - データソースが変更される可能性がある場合（システム移行等）、切替時の継続性確保方法を定めておく

4. **定義書のドラフトをKPIオーナー候補と読み合わせる**
   - 定義書のドラフトが完成したら、KPIオーナー候補と1対1で読み合わせの時間を設ける（30分程度）
   - 読み合わせの目的は「この定義で計算した数字が、あなたの業務実態を正しく反映するか」を確認することである
   - 現場の業務言語と定義書の記述にギャップがないか確認する。例えば、FP&Aが「解約率」と定義する指標を、カスタマーサクセス部門は「チャーンレート」と呼び、計算の分母が異なる場合がある
   - 読み合わせで出た修正意見は即座に反映し、修正版を再送して最終確認を得る

> **よくある落とし穴**: 計算式を「売上総利益÷売上高」のように書くだけで定義した気になるケース。「売上高」の定義に値引き・リベート控除後か前か、グループ間内部売上を含むか、為替換算レートは何を使うか、といった詳細が曖昧なまま運用されると、後から数値の不一致が頻発する。定義書は「もう一人の自分が再現計算できるか」を検証基準にする。

### 4. KPI定義の承認と周知

**実行条件**: ステップ3でKPI定義書のドラフトが完成した後に実施する。

1. **経営会議への上程前にpre-alignmentを実施する**
   - 経営会議でのサプライズを防ぐため、CFOおよび主要な事業部門長に対して、会議の前に個別にKPIセットの概要を説明する
   - pre-alignmentで確認すべき内容:
     - KPIセットの全体像（選定されたKPIの一覧と戦略目標との対応関係）
     - 前回からの変更点（新規追加・廃止候補がある場合）
     - 事業部門との合意状況（合意済みか、未合意の論点があるか）
   - pre-alignmentで出た懸念や修正意見は、経営会議上程前に反映する。会議の場での想定外の反論を最小化することが目的である

2. **KPIオーナーとの合意を取得する**
   - 各KPIオーナー候補に定義書を提示し、以下の確認を得る
     - 計算式と定義に異論がないか
     - 数値に対する説明責任を引き受けるか
     - データ取得・更新の実務が回るか
   - 合意が得られない場合の対応:
     - 定義の技術的な問題: 定義の修正で対応する
     - オーナーシップの問題（「この数字は自分がコントロールできない」）: KPIの構造（他部門への依存度）を見直すか、共同オーナーシップの枠組みを検討する
     - 根本的な反対（「このKPI自体が不要」）: 反対意見の根拠を記録し、CFOを含む場で議論する。FP&Aが一方的に押し切らない
   - 定義とオーナーの両方が確定するまでKPIは正式運用に移さない

3. **経営会議で承認を得る**
   - KPIセット全体を一覧にし、戦略目標との対応関係を示した上で承認を取得する
   - 承認時に確認すべき事項: KPIの網羅性（重要な戦略目標がカバーされているか）、数の妥当性（多すぎないか）、既存KPIからの変更点
   - 経営会議での説明では、財務用語をそのまま使わず、事業部門にとって意味のある言葉に翻訳する。例: 「NRRが105%」ではなく「既存顧客からの収益が前年比5%成長している状態」

4. **KPI定義書を関係者に周知する**
   - 定義書は一元管理し、関係者が常に最新版を参照できる状態にする（社内ポータル、共有ドライブ等）
   - 周知は単なるメール送付ではなく、KPIオーナーが自チームに対して「なぜこのKPIが選ばれたか」「自分たちの仕事とどう関係するか」を説明する場を設けることを推奨する
   - 定義変更時のルール: 変更の影響範囲を評価し、過去データとの比較可能性に影響がある場合は、変更前後の併記期間を設ける

> **判断の分岐点**: KPIの定義を変更する場合、過去の時系列データを新定義で遡及再計算するか、変更時点から新定義を適用するかの判断が必要になる。遡及再計算はデータの一貫性を確保できるが、工数が大きい。変更の性質（軽微な調整か、根本的な再定義か）と、時系列分析の重要性で判断する。

> **フィードバックループの設計**: KPI定義の承認・周知は「完了」ではなく「運用開始」である。定義書の周知後1ヶ月を目処に、KPIオーナーとFP&Aの間で「定義どおりに運用できているか」「データ取得で問題が出ていないか」を確認するフォローアップの場を設ける。初期段階の問題を早期に解消することで、KPIの定着が格段に早くなる。

---

## 組織学習と知見の蓄積

- **選定プロセスの振り返り**: KPI選定の完了後（承認・周知の後2週間以内）、FP&Aチーム内で振り返りを実施する。「候補導出から承認までに何が想定外だったか」「事業部門とのやり取りで得た気づき」「次回改善すべきプロセス上の課題」を記録する
- **ヒアリング知見の蓄積**: 事業部門へのヒアリングで得た定性情報（各部門が実際に重視している指標、非公式に管理している数字、KPIに対する率直な意見）は、FP&Aチームの共有ドキュメントに記録する。次回のKPI見直し時や後任への引き継ぎ時に、貴重な文脈情報となる
- **定義の変遷記録**: KPI定義書には変更履歴を必ず含め、「いつ」「何を」「なぜ」変更したかを記録する。定義の変遷を追えることは、KPIの信頼性の基盤である
