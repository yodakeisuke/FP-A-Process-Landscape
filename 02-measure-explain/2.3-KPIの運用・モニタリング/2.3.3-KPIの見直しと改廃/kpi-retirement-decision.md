# KPIの改廃判断

## 目的

- **誰のために**: CFO、FP&A責任者、事業部門長、経営企画責任者
- **何を解決するか**: 戦略変更や組織再編が起きても、KPIセットは惰性で据え置かれることが多い。古い戦略に紐づいた指標が残り、新しい戦略の進捗を測る指標が不在のまま経営レビューが行われると、誤ったシグナルに基づく意思決定や、変革の進捗が可視化されない状態に陥る。また、KPIの変更は過去との比較可能性を損なうため、無計画な改廃はトレンド分析の断絶を招く
- **届ける価値**: 戦略変更・組織再編を契機としたKPIの追加・統合・廃止を、影響管理を含めて体系的に判断するプロセスを提供し、KPIセットと経営の現実の整合性を維持する

## スコープ

- **対象**: KPIの追加（新規導入）、統合（複数指標の一本化）、廃止（測定・報告の停止）に関する意思決定プロセス
- **前提**: 定期レビューの結果として廃止候補・統合候補・追加候補が識別されていること。または戦略変更・組織再編が改廃のトリガーとなっていること
- **後続**: 改廃決定後のKPIの定義と目標設定プロセス（新規・再定義の場合）、ダッシュボード・レポートの改修、関係者への周知
- **対象部門**: FP&A部門（改廃プロセスの設計・推進）、事業部門（影響評価・移行の実行）、経営企画（戦略整合性の担保）、経理部門（管理会計指標への影響確認）

## 責任者

| 役割 | 担当 |
|------|------|
| 改廃案の策定・影響分析 | FP&Aマネージャー |
| 改廃候補の詳細調査・データ整備 | FP&Aアナリスト |
| 事業への影響評価・移行計画の実行 | 事業部門のKPIオーナー |
| 改廃の最終承認 | CFO |
| 外部報告・開示への影響確認 | 経理部門 / IR部門 |

## 手順

**用語の定義**:
- **改廃トリガー**: KPIの追加・統合・廃止の検討を開始する契機。定期レビューの結果、戦略変更、組織再編、M&A、事業モデルの転換等
- **比較可能性**: KPIの変更前後で、同一基準によるトレンド分析が可能な状態。比較可能性が断絶すると、業績の連続的な評価ができなくなる
- **並行運用期間**: 旧KPIと新KPIを同時に測定・報告する移行期間。比較可能性の確保と利用者の習熟のために設ける

**プロセスの構造**

| フェーズ | ステップ | 実行条件 |
|---------|---------|---------|
| トリガー評価 | 1. 改廃トリガーの識別と影響範囲の特定 | 戦略変更・組織再編の発生時、または定期レビューで改廃候補が検出された時 |
| 改廃設計 | 2. 追加・統合・廃止の判断基準の適用 | ステップ1で改廃検討が必要と判定された場合 |
| 影響管理 | 3. 比較可能性の確保と移行計画の策定 | ステップ2で改廃が決定された場合 |
| 実行 | 4. 改廃の実行と並行運用 | ステップ3の移行計画に基づき実施 |
| 定着確認 | 5. 改廃後の有効性確認 | 並行運用期間の終了後 |

### 1. 改廃トリガーの識別と影響範囲の特定

**実行条件**: 戦略変更・組織再編の発生時、または定期レビューで改廃候補が検出された時。

改廃の起点を明確にし、影響が及ぶ範囲を事前に特定する。トリガーの種類によって改廃の緊急度とアプローチが異なる。

1. **トリガーの種類を分類する**

   | トリガー | 典型的な改廃内容 | 緊急度 |
   |---------|----------------|--------|
   | 戦略の重点テーマ変更 | 新テーマに対応するKPI追加、旧テーマのKPI廃止・格下げ | 中。次の計画サイクルに合わせて実施 |
   | 組織再編（部門の統合・分割） | 旧部門KPIの統合・再定義、新部門KPIの新設 | 高。再編と同時に着手しないと測定の空白期間が生じる |
   | M&A（買収・売却） | 被買収事業のKPI統合、売却事業のKPI除外 | 高。統合初日からの測定体制が必要 |
   | 事業モデルの転換 | 旧モデルの指標体系から新モデルへの全面的な見直し | 中-高。転換の進捗に合わせて段階的に実施 |
   | 定期レビューでの形骸化検出 | 形骸化指標の廃止・統合 | 低。計画的に実施可能 |
   | 外部環境の激変 | 緊急モニタリング指標の追加 | 最高。即座に仮設定し、後から精緻化 |

2. **影響範囲を特定する**
   - 改廃候補のKPIが参照されている全ての場所を洗い出す: 経営レポート、ダッシュボード、事業部門パフォーマンスパッケージ、予算編成の前提、インセンティブ制度（業績連動報酬）、外部開示資料、取締役会報告
   - 特にインセンティブ制度との連動がある場合は、報酬委員会・人事部門との調整が必須となる。KPIの変更が評価制度に影響する場合、期中の変更は原則として避ける
   - カスケード構造への影響: 全社KPIの改廃は部門KPIの連鎖的な変更を引き起こす。影響が波及する階層の深さを確認する

3. **利害関係者を特定する**
   - 改廃によって直接影響を受ける関係者（KPIオーナー、レポート作成者、レポート受領者）を一覧化する
   - 各関係者の立場（改廃に賛成か反対か、中立か）を事前に把握する。特に廃止候補のKPIオーナーは抵抗を示す場合がある

> **よくある落とし穴**: 組織再編時にKPIの改廃を後回しにすると、再編後の新組織が旧組織のKPIで評価される期間が生じる。この期間に「自分たちの実力が正しく反映されない」という不信感が組織に蓄積する。再編の計画段階からKPIの移行計画を並行して策定すべきである。

---

### 2. 追加・統合・廃止の判断基準の適用

**実行条件**: ステップ1で改廃検討が必要と判定された場合。

個々の改廃候補について、追加・統合・廃止のいずれが適切かを判断する。判断は感覚ではなく、基準に基づいて行う。

1. **廃止の判断基準**
   - 以下の条件を全て満たす場合、廃止を推奨する:
     - 定期レビューで意思決定結合度が「低」と判定されている
     - 保険的指標としての価値が認められない（過去に異常時に使われた実績がない）
     - 外部報告義務や規制要件による維持義務がない
     - インセンティブ制度との連動がない（または連動解除が合意済み）
   - 廃止を保留すべき場合:
     - 外部報告（決算説明資料、統合報告書等）で使用しており、急な除外が対外的な疑念を招く場合。この場合は「経営管理上の廃止」と「対外報告での継続掲載」を分離する
     - 規制当局への報告義務がある場合

2. **統合の判断基準**
   - 以下の条件に該当する場合、統合を検討する:
     - 2つ以上のKPIが実質的に同じ事象を異なる角度から測定しており、一方で十分に代替可能
     - 組織再編により、旧部門ごとに別々に存在していた同種の指標を一本化する必要がある
   - 統合時の留意点:
     - どちらの定義を採用するか（または新たな定義を作るか）を明確にする
     - 統合前の個別指標のトレンドデータを、統合後の定義で遡及計算できるかを確認する。遡及不可能な場合は、並行運用期間を設けて新旧の関係を記録する

3. **追加の判断基準**
   - 以下の条件を満たす場合、追加を推奨する:
     - 定期レビューで戦略テーマとのカバレッジの盲点が識別されている
     - 新規の戦略テーマ・事業モデルに対して、進捗を測定する指標が存在しない
     - データソースが確保可能で、合理的な工数で測定を開始できる
   - 追加時の留意点:
     - 新KPIの追加は、既存KPIの廃止または格下げとセットで行うことを原則とする。追加だけを繰り返すとKPI数が膨張する
     - 新KPIは導入後2四半期を「仮運用期間」とし、定義の安定性と意思決定への有用性を確認した上で正式採用する

4. **改廃案を一覧にまとめる**
   - 改廃候補ごとに: 現状の指標名・定義、改廃の種類（追加/統合/廃止）、判断根拠、影響を受ける関係者・システム、推奨する実施時期
   - 優先順位をつける: 戦略整合性への影響が大きいものを優先し、利便性の向上にとどまるものは後回しにする

> **判断の分岐点**: 「廃止」と「格下げ」の使い分けが重要である。格下げとは、経営レビューの定期報告対象からは外すが、データの測定と蓄積は継続する状態を指す。完全廃止すると復活時にデータの断絶が生じるため、測定コストが低い指標は格下げを選択する方が安全な場合がある。

> **業種別の注意点**:
> - **製造業**: 安全・環境系のKPI（災害度数率、排出量等）は規制要件との関連が深い。廃止判断前に法務・コンプライアンス部門と必ず確認する
> - **SaaS/テクノロジー**: 投資家が注目する業界標準指標（NRR、Rule of 40等）は、たとえ社内の意思決定結合度が低くても対外的には廃止しにくい。社内管理用と対外報告用を分離して考える
> - **金融業**: 自己資本比率やリスクアセット関連の指標は規制資本要件に直結する。改廃の判断にリスク管理部門の関与が必須

### 3. 比較可能性の確保と移行計画の策定

**実行条件**: ステップ2で改廃が決定された場合。

KPIの変更は、過去データとの連続性を断ち切るリスクを伴う。このリスクを最小化する移行計画を策定する。

1. **比較可能性への影響を評価する**
   - 改廃の種類ごとの影響:

   | 改廃の種類 | 比較可能性への影響 | 対応策 |
   |-----------|----------------|--------|
   | 廃止 | 当該指標のトレンド分析が不可能になる | 最終データを確定値として保存。後継指標がある場合はブリッジテーブルを作成 |
   | 統合 | 統合前の個別トレンドが追えなくなる | 統合後の定義で過去データを遡及計算。不可能な場合は並行運用で接続期間を確保 |
   | 追加 | 新指標にはヒストリカルデータがない | 可能な範囲で過去データを遡及作成。少なくとも直近4四半期分があれば季節性の把握が可能 |
   | 定義変更 | 変更前後で同名の指標が異なるものを指す | 最も危険。変更前後のブリッジを必ず作成し、定義変更の時点と内容を明記する |

2. **並行運用期間を設計する**
   - 原則として、重要度の高いKPI（経営会議で定期レビューする指標）の改廃には最低1四半期の並行運用期間を設ける
   - 並行運用期間中は、旧KPIと新KPIの両方をレポートに掲載し、差異の理由を注記する
   - 並行運用期間の終了条件: 新KPIのデータ品質が安定し、利用者が新指標に基づく議論に移行し、旧KPIへの参照がなくなったこと

3. **移行計画を策定する**
   - 以下の項目を含む移行計画書を作成する:
     - 改廃対象のKPI一覧と改廃の種類
     - 実施スケジュール（並行運用の開始日・終了予定日）
     - データ整備の作業内容（遡及計算、ブリッジテーブルの作成、ダッシュボードの改修）
     - 関係者への周知計画（誰に、いつ、何を伝えるか）
     - インセンティブ制度への影響がある場合の対応（評価期間との整合、人事部門との調整）
   - 移行計画はCFOの承認を得た上で実行に移す

> **よくある落とし穴**: 定義変更を「マイナーチェンジ」として並行運用なしで実施するケースがある。しかし、計算式の分母の変更、対象範囲の拡大・縮小、データソースの切り替えは、数値に大きな影響を与えうる。名前が同じまま中身が変わる「サイレント改廃」は最も危険であり、変更の大小にかかわらず、定義変更は必ず記録と周知を行う。

### 4. 改廃の実行と並行運用

**実行条件**: ステップ3の移行計画に基づき実施する。

1. **改廃の事前周知を行う**
   - 改廃の内容、理由、スケジュール、影響を関係者に通知する
   - 経営レポートの変更がある場合は、変更が反映される初回のレポートに改廃の説明を付記する
   - 「なぜ変えるのか」を明確に説明する。理由の説明がないKPI変更は、データの信頼性全体への不信感を招く

2. **データ基盤・レポートを改修する**
   - ダッシュボード・レポートテンプレートに新KPIを追加し、廃止KPIを並行運用期間中は注記付きで残す
   - 新KPIの目標値・閾値を設定する（KPIの定義と目標設定プロセスに従う）
   - 並行運用期間中は、旧KPIと新KPIの両方のデータ収集・検証を行う。工数が一時的に増加することを関係者に事前に伝える

3. **並行運用期間中のモニタリング**
   - 新KPIのデータ品質を毎月確認する: 欠損、異常値、定義どおりに算出されているか
   - 利用者の反応を収集する: 新KPIは理解しやすいか、意思決定に使えているか、旧KPIとの違いに混乱がないか
   - 並行運用期間の延長が必要な場合は、その判断を記録する

> **判断の分岐点**: 並行運用期間中に新KPIの有用性に疑問が出た場合、「予定通り旧KPIを廃止する」か「新KPIの定義を見直す」か「旧KPIに戻す」かの判断が必要になる。この判断はFP&Aマネージャー単独ではなく、KPIオーナーとCFOを含めて行う。並行運用期間はこの種の判断のための安全な猶予期間でもある。

---

### 5. 改廃後の有効性確認

**実行条件**: 並行運用期間の終了後に実施する。

1. **旧KPIの正式廃止を完了する**
   - 並行運用期間の終了条件が満たされたことを確認する
   - ダッシュボード・レポートから旧KPIを除外する
   - 旧KPIの最終データとメタ情報（定義、運用期間、廃止理由）をアーカイブする。将来の参照のために少なくとも3年間は保持する

2. **新KPIの有効性を確認する**
   - 導入後2四半期時点で以下を確認する:
     - 意思決定結合度: 新KPIが実際にアクションのトリガーとして機能しているか
     - データ品質: 安定的に正確な数値が取得できているか
     - 理解度: 関係者が新KPIの意味と使い方を正しく理解しているか
   - 有効性が確認できない場合は、定義の再調整または次回の定期レビューでの再評価対象とする

3. **改廃プロセス自体の振り返りを行う**
   - 移行計画どおりに進んだか、想定外の問題は何だったかを記録する
   - 特に以下の点を次回の改廃に活かす: 並行運用期間の長さは適切だったか、関係者への周知のタイミングは適切だったか、データ整備の工数見積もりは正確だったか
   - 改廃の結果を定期レビューの基準データとして引き渡す

> **よくある落とし穴**: 改廃後に「前のKPIの方がよかった」という声が上がることがある。これが合理的な指摘（新KPIの設計に問題がある）なのか、単なる変化への抵抗なのかを区別するために、有効性確認は客観的な基準（意思決定結合度、データ品質）で行い、感想ではなく事実に基づいて判断する。
