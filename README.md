# FP&A Standard Operating Procedures

FP&A 部門の標準業務手順書です。

## FP&A におけるコミュニケーション・コラボレーションの位置づけ

FP&A の業務は、数値の集計・分析だけでは完結しない。経営の意思決定を支援するためには、事業の現場で何が起きているかを能動的に把握し、分析結果を適切な相手に適切なタイミングで届け、提言がアクションにつながるまでフォローする一連のコミュニケーションが不可欠である。

本 SOP 体系では、以下の7つの軸をすべての業務プロセスに組み込んでいる。

| 軸 | 概要 | SOP への反映 |
|----|------|-------------|
| **定性情報の能動的収集** | 数値だけでは見えない事業の文脈を、ヒアリングや現場観察を通じて把握する | 各 SOP の「ヒアリング・すり合わせポイント」に質問例・情報源の優先順位を記載 |
| **ステークホルダーとの信頼構築** | 数値の報告者ではなく、ビジネスパートナーとしての関係を築く | 各 SOP の「ステークホルダー連携」セクションに信頼構築のポイントを明示 |
| **異論・対立のマネジメント** | 見解の相違を建設的に扱い、より良い意思決定につなげる | エスカレーション基準と対立の扱い方をテンプレートに標準装備 |
| **フィードバックループ** | 提言→アクション→検証の循環を回し、FP&A の提言精度を高める | 提言追跡の仕組みとフィードバック収集の問いかけ例を各 SOP に組み込み |
| **部門横断連携** | 隣接機能（経理・経営企画・IR・HR・IT 等）との協働を円滑にする | 部門横断連携マップで情報の依存関係と連携の契機を可視化 |
| **コミュニケーションのタイミングと手段** | 事前すり合わせを徹底し、サプライズゼロを実現する | 各ステップに事前確認・合意形成のタイミングを明記 |
| **組織学習と知見の蓄積** | 振り返りを通じてプロセスを継続的に改善し、ナレッジを蓄積する | サイクル終了時の振り返りと改善アクション管理を標準化 |

## セクション別コミュニケーションフロー

### Section 01: 戦略と整合した計画策定

計画策定は FP&A のコミュニケーション密度が最も高いプロセスである。事業部門との対話を通じて前提条件を構築し、経営層との合意形成を経て最終化する。

```
経営層（方針提示）──→ FP&A（前提条件の設計）──→ 事業部門（ボトムアップ入力）
        ▲                    │                          │
        │                    ▼                          │
        └─── 合意形成 ◄── すり合わせ（複数回の往復） ◄──┘
```

- **定性情報の収集**: 事業部門への個別ヒアリングで成長ドライバと制約条件を把握する。市場環境や競合動向など、数値に表れない前提を能動的に収集する
- **ステークホルダーとの信頼構築**: 予算編成は利害が対立しやすい。事業部門の課題を理解し、一方的な数値の押し付けではなくオプション提示型の対話を行う
- **異論・対立のマネジメント**: 予算目標の乖離が大きい場合、事実ベースでギャップを可視化し、段階的なすり合わせで合意に導く
- **サプライズゼロ**: 経営会議での予算承認前に、CFO・事業部門長と個別に事前すり合わせを完了させる

### Section 02: 業績の測定と説明

月次締めサイクルでは、経理部門からのデータ取得から経営レポートの配信まで、複数部門と連携して進行する。分析結果の解釈には事業部門からの定性情報が不可欠である。

```
経理（実績データ）──→ FP&A（分析・レポート作成）──→ 経営層（レビュー・意思決定）
                            │    ▲                        │
                            ▼    │                        ▼
                      事業部門（差異の背景確認）     アクションアイテム
                            │                            │
                            └──── フォローアップ ◄────────┘
```

- **定性情報の収集**: 数値の差異だけでなく「なぜそうなったか」を事業部門に確認する。差異分析の精度はヒアリングの質に依存する
- **フィードバックループ**: レポートの受け手から「役に立った情報」「足りなかった情報」を収集し、次月のレポート構成に反映する
- **コミュニケーションのタイミング**: 重大な差異は月次レポートの正式配信前に速報として共有する。フラッシュレポートとダッシュボードを活用し、情報のタイムラグを最小化する
- **部門横断連携**: 経理部門の締めスケジュールに依存するため、事前にタイムラインを共有し、データ受領のタイミングを確定させる

### Section 03: 打ち手の評価と提言

投資評価やコスト最適化では、分析結果を意思決定者に対して説得力のある形で提示し、実行後の効果検証までフォローする。

```
事業部門（案件起案）──→ FP&A（評価・分析）──→ 経営層（意思決定）
        │                      │                     │
        ▼                      ▼                     ▼
   追加情報提供          提言・オプション提示      実行指示
        │                      │                     │
        └──────── 効果検証（実行後モニタリング） ◄───┘
```

- **ステークホルダーとの信頼構築**: 案件の起案者（事業部門）に対して、単なる「数値チェック」ではなく「より良い意思決定のための分析パートナー」として関わる
- **異論・対立のマネジメント**: 投資判断で見解が分かれる場合、感度分析やシナリオ比較を通じて論点を構造化し、判断者が選択できる形で提示する
- **組織学習**: 過去の投資案件の実績と当初見込みの乖離を分析し、評価手法の精度向上に活かす。ゲートレビューの結果を蓄積し、類似案件の判断に参照する

### セクション間のデータフロー

```
Section 01（計画策定）
  予算・KPI目標・シナリオ前提
        │
        ▼
Section 02（業績の測定と説明）
  実績データ ─→ 予実差異分析 ─→ ドライバ特定 ─→ 経営レポート
  KPIモニタリング（並行稼働）
        │
        ▼
Section 03（打ち手の評価と提言）
  差異分析結果・ドライバ情報を活用した投資判断・コスト最適化・資金管理
        │
        ▼
Section 01 へフィードバック（ローリング予測の更新、次年度計画への反映）
```

- Section 01 で策定した予算・KPI目標が Section 02 の予実管理の基準となる
- Section 02 の差異分析・ドライバ特定の結果が Section 03 の意思決定支援のインプットとなる
- Section 03 の施策評価結果は Section 01 のローリング予測・次年度計画にフィードバックされる
- 各セクション間の引き継ぎにおいて、数値データだけでなく定性的な文脈情報（前提条件の変化、ステークホルダーの懸念事項、未解決の論点）も併せて伝達する

### プロセスフローの補足

- 2.1→2.2→2.4 は月次締めサイクルの主要フロー（直列）
- 2.3（KPIモニタリング）は月次締めとは独立に稼働する並行プロセス。ダッシュボードの更新やアラート対応は日次/週次で実行され、月次締めの完了を待たない
- 2.4 の一部（フラッシュレポート）も月次締め完了前に発行される速報であり、2.2 の完了を前提としない
- フィードバック収集・KPI改廃・用語統一・可視化標準化は月次サイクルとは独立した改善活動であり、四半期〜年次で実施する
